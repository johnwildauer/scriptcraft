# Feature Blueprint: Beat Board

## Approved target boundaries

### WO-007 spatial integration and authority

The live semantic Beat board is authoritative for card and text edits. Session candidates publish board, managed identity/graph coherence, selection and history atomically; retained source is not rewritten during editing. The writer alone reconciles managed XML at save time and retains unrelated material. Creation allocates stable card/paragraph IDs and durable board/ListItem/Paragraph identities. Item order is stacking order, independent from the creation ledger. Commands 65–68 create, activate, commit geometry, and set None/Card/Text selection; commands 69–70 edit and navigate active Beat text.

The desktop uses reverse-order hit testing, selected-edge/corner resize precedence, text regions and disposable fractional movement/resize previews drawn at the visual top. A drop commits one clamped 20-pixel half-up snapped rectangle with optional activation; Escape, focus loss and pointer loss cancel. Release outside commits the last available clamped pointer position. Selection, save rebase, undo/redo and document/view changes invalidate incompatible previews. WO-008 provides the headless text transaction boundary; desktop caret, keyboard, clipboard and IME adapters remain WO-009. No runtime acceptance is implied.

Model owns the semantic board, fixed-point dimensions, ordered cards, plain titles, body paragraphs, runs, direct recognized paragraph settings, and stable and durable identities. The board defaults to 24,000 × 10,000 pixels with no assigned foreign identity or cards. Cards default to 240 × 100, are bounded to 120–1000 × 60–1000, and use 20-pixel user commits inside the finite board. Semantic board dimensions are positive and bounded to one million logical pixels per axis. Geometry uses 1,000 raw units per logical pixel. Session owns transactional selection and history; viewport zoom and scroll, interaction previews, resolved fonts, and layouts are disposable rather than Project content.

FDX projects only exact supported direct-root and same-namespace board/list structures. The first valid Beat DisplayBoard wins; later Beat duplicates stay inert on Open and are removed only during the next transactional Save or Save As. Their ListItems, unrelated board types, and opaque data remain preserved. This explicit exception supersedes the general no-silent-board-deletion rule only for those duplicate Beat boards. Winning Item order determines back-to-front stacking; ListItems retain source/creation order. Source ownership and identity reconciliation must not promote lookalikes beneath opaque ancestry.

Each managed card has a durable ListItem identity and one or more paragraphs; an empty body has one empty paragraph and no runs. Session-local card and paragraph IDs are unique across all Project owners. Paragraph foreign IDs are optional until established at the source boundary; ambiguous durable mappings cannot be resolved by vector position. Paragraph runs reproduce canonical text and remain subject to the existing bounded text and attribute rules. Card title and Body content are independent of screenplay Body and Title Page; Beat content is not part of screenplay layout, PDF, text export, or print.

FDX import uses the first direct root-namespace DisplayBoards and ListItems containers. The winner is the first direct same-namespace DisplayBoard with one unqualified Type equal to Beat; direct Item identities resolve direct ListItems, and only exact Beat ListItems are projected. The first direct same-namespace Content and its direct Paragraph and Text children define body semantics. Later Content, unsupported ancestry and non-Beat data remain opaque. Paragraph identity registration is limited to this winning referenced path; retained Beat nodes are not screenplay-managed source owners. One collision-checked allocator reserves existing Body, Title and dual IDs before assigning separate card and paragraph stable IDs.

Import normalizes unusable geometry to bounded defaults while retaining raw source, and projects independent milli-percent zoom and milli-pixel origin into FDX-owned disposable state. Finite zoom clamps to 5–300%; missing or malformed values default to 100%, and origin defaults to zero. Codec-time origin is bounded by board dimensions; viewport composition applies the upper clamp. Startup and successful document activation install the document's view state without editing the Project, history or source; failed activation leaves the prior state unchanged.

Detached output serializes semantic Beat content and transactional viewport state, removes later Beat duplicates only on transactional save, and compares managed and unrelated graph partitions, reread semantics and normalized source before publication. A card-identity ledger records ListItems source/creation order separately from Item stacking. Creation transactions allocate collision-checked durable board, card and paragraph IDs and preserve established IDs. Imported id-less paragraphs may use a card-local coordinate solely for initial ID binding. Text and runs have no immutable source-occurrence ledger: changed managed text is projected directly while unrelated retained siblings and board partitions remain opaque. See [FDX Preservation and Storage](../components/fdx-preservation-and-storage.md). This is source integration, not save/reopen evidence.

The desktop presents Beat as a separate root view, with a finite navigable board and no screenplay ruler. Card text layout is not screenplay pagination. Titles are single-line plain Arial 12 bold; bodies support multiple paragraphs and existing inline formatting. Session transactions operate on detached candidates and preserve source, selection, history and dirty state on failure or no-op. Save reconciles semantic and disposable state separately and verifies identity/source safety before publication.

## Text transaction integration (WO-008)

`EditingSession` owns `BeatSelection::{None, Card, Text}`, title/body field positions, collapsed-body typing style and inline insertion patch, selected-text extraction, Select All, edit, and navigation transactions. Positions are UTF-8 byte offsets; Title is restricted to paragraph zero and Body indexes the current ordered paragraph vector. Selection changes advance only the mutation token, never history/revision/dirty state. Text edits atomically publish semantic card values and paragraph identity registrations with one snapshot/revision; undo/redo restores Beat selection and typing state. Insert/Paste, DeleteBackward/DeleteForward, Enter, horizontal navigation, and logical line-edge navigation converge on these APIs. Save rebase maps cards and paragraphs by durable identity, with only the bounded unique exact-content fallback for id-less paragraphs, then clamps offsets to valid boundaries. Desktop visual-line/vertical navigation computes layout targets and commits them through selection; Session has no layout dependency. FDX remains save-time projection.

The original WO-007 scope statement that card deletion was outside the initiative records that stage's historical boundary; it is superseded as an active contract by the selected-card deletion source integration below. Story Map and non-Beat editing and board export remain outside scope. This document describes architecture/source integration, not runtime or acceptance evidence.

## Selected-card deletion source integration (WO-001–WO-003)

The source reader preserves `SubordinateTo` as an opaque element, not as a separate card, Paragraph identity, or anchor-owning attachment. The detached output removes the deleted ListItem node as a whole, so its `SubordinateTo` and Content subtrees disappear together. In the imported shared-board shape, the same ListItem identity can also be referenced by a Story Map `DisplayBoard/Item`; that edge—not `SubordinateTo` ownership—was the immediate deletion blocker. Deletion removes only direct Item references to the deleted ListItem from other direct DisplayBoards, retaining each board, lanes, and all other Items. Unrelated ListItems and source remain unchanged.

`EditingSession` deletes exactly the selected semantic card from both stacking and creation-order ledgers on a detached Project, removes only its managed graph registrations after strict ownership/reference checks, and publishes through the existing Beat snapshot path with selection None. One successful deletion is one undoable semantic edit; Undo restores the complete card and previous Card selection, and Redo reapplies deletion and None. The last card may be removed without deleting or replacing the board. Failures do not partially publish.

Command 74 is `BeatBoardCardDelete` / `beat-board.card.delete`, carries one stable card ID, and is routed by the headless executor and shared desktop dispatcher. Unmodified Backspace/Delete on a valid Card selection emits shared EditDelete exactly once; focused Text remains text deletion, while collapsed Text and None cannot delete a card. Existing focus, IME, menu, modal, replacement, native-output and element-dialog ownership remains authoritative. The final catalog contains 74 unique commands at envelope version 2; no existing ID or command behavior is changed.

FDX candidate finalization permits only whole-card absence while retaining exact surviving-card identity and paragraph-binding checks. Deleted imported cards require correspondence with the original source owner; generated cards deleted before first save have no retained source anchor. Session cleanup removes matching managed ListItem entities, every matching board Item edge to the deleted ListItem, and Paragraph identity registrations when present; their exact multiplicity/presence is not a deletion prerequisite. Anchor/ownership safety remains strict. A surviving-source `RequiredInternal` link to a deleted identity is rejected except for recognized direct DisplayBoard Item references to that ListItem; those exact edges and source Item nodes are removed on the detached candidate/output. RequiredInternal references to deleted Paragraphs and non-board sources remain blockers. References sourced by deleted ListItem/Paragraph identities are removed with their source. Targeting `CrossDomainMayOrphan` references may remain orphaned as expressly allowed by the model contract. Other boards, Story Map lanes/Items, unrelated source/ListItems/graph edges remain preserved. Existing graph partition, complete-candidate validation, semantic/identity/source reread and publication checks remain strict. The empty winning board remains valid. Save rebase follows existing survivors; deletion selection is None, and Undo followed by Save uses the established durable-ID mapping. This is source integration only, not build, save/reopen, native, or product-acceptance evidence.

The original Beat Board plan and its historical no-deletion decision are unchanged.

## Root chrome integration (WO-004)

The app-private Script/Beat root selector starts on Script and is not persisted; Title Page remains a separate child with zoom precedence while active or swapped. Command 64 selects Beat; existing Script mode commands select Script. The shared View catalog and Dashboard toolbar action use the same current dispatcher and availability; custom toolbar arrays are not migrated. Beat composition does not use the Script frame or ruler. Beat status omits page and Body guidance but retains the existing per-window Focus Mode action, Timer, Appearance, diagnostics policy and target-aware zoom; Focus Mode shares the existing fullscreen observation, state, and command path. Script/Title behavior remains unchanged. Script/Title remain 75–300%, Beat 5–300%, with unchanged preset rows and independent milli-percent Beat state. View changes release Script-only transient input and anchors; document activation replaces the Beat state without requiring a root switch. WO-004 did not introduce card rendering; WO-006 subsequently added read-only cards.

## Finite viewport integration (WO-005)

The desktop geometry authority projects `screen = viewport_origin + (board - scroll_origin) * z`, inverse `board = scroll_origin + (screen - viewport_origin) / z`, where `z = zoom_milli_percent / 100000`. Each scroll axis is clamped to `0..max(0, board_dimension - viewport_dimension / z)` using milli-pixel origins. The board is top-left anchored; the workspace and page palette provide the outside and board backdrops. The 40-pixel grid starts at 20, and visible floor/ceil ordinals bound iteration to the clipped board. Only painted line centers are pixel-snapped. The geometry module also provides culling and 20-pixel snap primitives for later orders.

The viewport publishes clipped geometry and optional pointer projection as transient app state. Raw wheel events are processed once, in event order after wheel-zoom adaptation, with both axes and Shift-to-horizontal preserved. Center-anchored control zoom and pointer-anchored pinch/wheel zoom apply their bounded origin immediately; subsequent manual pan therefore cannot be undone by a stale anchor. Root changes and successful document activation discard the published rectangle. Save captures the live clamped FDX view state, not geometry or a Project mutation. No scrollbar or cards are introduced by this order.

## Read-only card layout and paint (WO-006)

[`beat_board.rs`](../../../crates/scriptcraft-layout/src/beat_board.rs) builds immutable card-local title and body layouts using shared measured wrapping and line construction. The title is Arial 12 bold; each body paragraph begins a new left-aligned, non-paginated flow with Arial 12 regular as its base and supported inline runs overriding it. Empty paragraphs retain a line and canonical paragraph-local UTF-8 mapping. Screenplay definitions, indents, spacing, dual dialogue, pagination and output composition do not govern this flow. Default card-local padding is 12 board pixels, title allocation 20, and title/body gap 8; content regions remain bounded for small cards.

The full title and source mapping are retained separately from the ordinary display-only ellipsis projection, whose ellipsis has no source range or caret target. Body layout retains all lines and total height; ordinary paint includes only whole line boxes up to the first overflow. Subdued “Beat Title” and “Body” are presentation-only placeholders for an empty title or wholly empty body. None of these projections changes canonical content. Whole-pixel card sizes map exactly to unscaled logical points; existing fractional imported width and height round to the nearest hundredth only in text layout, without snapping or changing the durable rectangle.

Desktop font preparation extends the shared environment to Beat defaults, run families, canonical title/body scalars, uppercase expansions, placeholders and ellipsis. Shared presentation span styling is reused by Script and Beat. The desktop paints visible cards in Item order with page-paper fill and page-border styling, clipping card and text regions to the board/viewport. WO-007 supplies real selection to the selected-stroke primitive. A disposable per-card cache compares the card with position excluded, metrics, complete resolved environment, and prepared face bytes/index; size, content or environment changes can rebuild an entry, while position and zoom do not. This includes height as well as width, not just wrapping width.

This is source integration, not rendered font/layout or product acceptance. WO-007 supplies spatial interactions and WO-008 supplies headless text transactions; desktop text interaction remains WO-009. Beat content is excluded from screenplay page layout, PDF, plain text and native print. Validation remains user-owned.

## Desktop text editing and IME (WO-009)

The desktop Beat adapter layers pointer mapping, transient text focus, selection/caret paint, keyboard routing, clipboard actions and IME preedit/commit over the WO-006 measured card layout and WO-008 `EditingSession` APIs. It uses the full Title line, body paragraph/line source maps, clipped selection/caret paint, title horizontal follow and transient focused-body vertical scroll. Pointer selection submits validated command-68 selection changes without history; semantic text changes submit typed command-69 transactions, and visual navigation resolves layout positions before command-68 selection. The active Text selection retains its card stroke; focused-card text selection is not redirected to spatial move/resize. First-click card activation behavior from WO-007 remains intact.

Keyboard Text/Paste, Backspace/Delete, Enter, horizontal/visual-line/vertical movement and Shift extension route in event order without screenplay Behavior or dynamic shortcuts. Existing Edit Copy/Cut/Paste/Delete/Select All actions are enabled only for focused Beat text and use session canonical plain text; Cut writes clipboard before deletion. IME preedit is transient paint state, commit routes exactly once to Insert/Paste, and stale preedit is discarded on blur/root/card/document change. Title newline paste normalization and Body multiline semantics remain WO-008-owned. No independent editor semantics, retained XML typing mirror, or separate undo stack is added; inline formatting is specified below under WO-010.

Title/body offsets, preferred x, drag preview, focus, blink and preedit remain transient. Body wheel scroll takes precedence over board pan only while the focused body can scroll; edge deltas fall through to the board. Escape returns to Card selection and blur resets offsets. The current egui version has no custom native IME candidate rectangle command; preedit is painted at the computed canonical caret but platform candidate-window anchoring is a known adapter limitation. This is source integration only; user-owned validation is not claimed.

## Inline formatting and shared controls (WO-010)

The headless session adds style toggle, supported-style clear, and bounded run-formatting operations for a valid Beat Body Text selection only. Bold, Italics, Underline, All Caps, and Strikethrough share the canonical run helpers; cross-paragraph selections use one all-on/all-off decision. Plain Text clears only supported style flags and retains unknown Style tokens and Font/Size/Color/Background. Font, Size, Color, and Highlight reuse the existing `InlineRunFormattingPatch` and exact shared value/palette contract. Collapsed caret changes remain session-only typing state consumed by later insertion. Noncollapsed formatting updates only the exact selected slices of each affected Paragraph in one detached Project candidate and history entry, preserving unselected boundary runs and canonical text. No-op, empty patch, invalid range, or failure publishes no partial edit. Undo/redo restores runs and Beat typing/selection snapshots; FDX projects semantic runs on save.

The shared Format menu and configured main-toolbar Styles group project current Beat checks/values only for the focused valid Body selection. Title, Card-only, None, stale/invalid and locked contexts disable inline formatting. Alignment, paragraph formatting, element changes and other screenplay-only controls remain unavailable. Existing Body/Title Page paths are unchanged; retained shared menu actions are adapted at dispatch time to exactly one of commands 71–73 only when the Beat root is current, with current focus/selection/lock availability rechecked. Highlight Background remains durable/editable run data but receives no new Beat card-paint or output support. This records source integration, not native-menu or visual acceptance.

## Current pointer, caret, and appearance integration (WO-001/WO-002)

The later pointer/caret repair supersedes the earlier WO-007 stage description that left text targeting for later work. One active-card predicate covers Card and Text selection for hit classification and hover projection. Selected edges/corners keep resize precedence; selected title/body content is text behavior with an I-beam and routes to the existing text adapter; selected margins move with the hand cursor. Any interior region of an unselected card uses move behavior and can be dragged immediately. A simple unselected release activates/selects/raises without placing a caret. Selected text drags remain with text selection; movement uses the closed-hand cursor; existing resize, cancellation, stacking, and geometry-commit paths remain in place.

The text adapter uses the real canonical card layout for empty-field position zero. When the matching Title or Body selection is collapsed and transient text focus is active, the caret may paint in an empty field; placeholder strings remain presentation-only and do not become source ranges or semantic content. Appearance ownership is split: `ApplicationPalette::from_visuals()` supplies app-private Beat grid and unselected-border roles through `ScriptWorkspacePalette::beat`; the shared `PagePalette::border` remains for Script/Title Page. Day grid/border are RGB 189, 189, 189 / RGB 189, 189, 189; Night are RGB 80, 80, 80 / RGB 105, 105, 105; Midnight are RGB 50, 50, 50 / RGB 80, 80, 80. The unselected card frame is 1 logical point. Selected frames remain 3 logical points and RGB 112, 190, 255. The finite-board geometry, grid spacing/placement, shared page palette, canonical text/session/FDX ownership, and command catalog are unchanged. This is source integration only, not rendered/native/manual acceptance.

## Supplemental viewport scrollbars (WO-005)

The supplemental WO-005 order supersedes the original finite-viewport no-visible-scrollbar decision without changing the board geometry authority. `views/beat_board/scrollbars.rs` derives independent visible fractions and maximum origins from current `ViewportGeometry`, uses 10-point overlay bars flush to the viewport's right/bottom edges with a reserved intersection, and maps proportional thumbs (24-point minimum, bounded by track) to the full clamped origin range. No track fill is painted; handles use the existing resting/hovered/dragged RGB palette at alpha 64 fill and a 1-point matching-RGB alpha 128 border. Painting remains clipped and overlays grid/cards/text. Drag capture and its grab offset live in the existing cancellable `BeatInteraction`; dragging writes the disposable view-state value through the established origin clamp, with no command or semantic/session edit. Scrollbar hit-testing has first refusal before card, text, empty-board, and double-click actions. Escape, pointer/focus loss, root/view/document changes, and token invalidation use the existing transient cancellation lifecycle. Track presses outside thumbs are consumed no-ops. Wheel/pinch routing and focused-body-first vertical scrolling are untouched, as are transforms, zoom anchors, viewport allocation, card-body appearance and the package/command boundaries. Source integration is not rendered/native/manual acceptance.

The visibility controller is transient within the existing scrollbar interaction: bars begin hidden after Beat-root entry/document activation; an actual pointer move inside the clipped viewport or an effective change to the disposable zoom/origin reveals and refreshes them for 1.0 second. The deadline requests its own repaint to hide without another input event. Central composition compares effective view state, covering wheel/trackpad pan, pinch, thumb drag, status/menu/slider zoom, and other existing view-state paths. Pointer presses/clicks, card creation/selection/editing, text selection/caret placement, typing, IME, clipboard, formatting, semantic edits, and focused-body scrolling alone do not reveal/refresh. Card movement can qualify through actual pointer movement. Capture pins visibility during thumb drag; a pointer over a visible scrollbar hit region keeps it visible, while hidden bars have no input target. Root/document reset discards visibility, deadline, and comparison baseline. None of this state is persisted or routed through Project, FDX, settings, history, dirty state, or commands; no fade is used. Existing appearance, geometry, hit precedence, cancellation and card/text contracts are unchanged.
