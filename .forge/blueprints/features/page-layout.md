# Feature-Area Blueprint: Page Layout

> This feature composes deterministic document-point layout with desktop viewport presentation while keeping editor and Print geometry coherent.

## Scope and requirements

- **Requirements:** [Page layout](../../requirements/features/page-layout.md); [Desktop workspace](../../requirements/features/desktop-workspace.md) owns `REQ-WRITING-LOOP-006` for `AC-WRITING-006.5`–`AC-WRITING-006.11`.
- **Technical context:** [Technical context](../technical-context.md)
- **Requirements traced:** `REQ-WRITING-LOOP-002`, `REQ-WRITING-LOOP-006`; `AC-WRITING-002.1`–`AC-WRITING-002.15`, `AC-WRITING-006.5`–`AC-WRITING-006.11`.
- **Area summary:** One complete source-mapped layout is the authority for pagination, hit testing, navigation, visible-page status, and print composition. Viewport scale and desktop appearance are projections, not layout inputs.

## Shared composition

- [Layout and pagination](../components/layout-and-pagination.md) and the [`scriptcraft-layout` crate root](../../../crates/scriptcraft-layout/src/lib.rs) own canonical document-point geometry, compositions, metric wrapping, pagination, and derived queries. [Document Model](../components/document-model.md) owns canonical content, ordered definitions, formatting, and effective Project-owned DocumentPageLayout plus derived layout-input values in [`formatting.rs`](../../../crates/scriptcraft-model/src/formatting.rs) and [`layout_inputs.rs`](../../../crates/scriptcraft-model/src/layout_inputs.rs); [Editing session](../components/editing-session.md) supplies validated live content and a read-only Project-derived layout snapshot and owns native storage, while FDX owns the codec/source boundary through [FDX preservation and storage](../components/fdx-preservation-and-storage.md); source-derived settings remain represented through model/session composition.
- [Desktop adapters](../components/desktop-adapters.md) paints and interacts with pages; [Command contract](../components/command-contract.md) carries semantic selection and view actions. PDF/plain-text consumers use [`scriptcraft-export`](../../../crates/scriptcraft-export/src/lib.rs) and its Print-layout composition; export remains a bounded, noncanonical output consumer rather than an owner of viewport geometry.

## Capability realization

### Fixed page geometry and source-mapped interaction

- **Requirements:** `REQ-WRITING-LOOP-002`; `AC-WRITING-002.1`–`AC-WRITING-002.5`, `AC-WRITING-002.8`, `AC-WRITING-002.12`–`AC-WRITING-002.13`.
- **Composition and flow:** The layout component resolves each current document definition, supported source settings, explicit resolved-font metrics, and stable-ID direct paragraph/run overrides into complete deterministic geometry. It maps each rendered line to canonical UTF-8 ranges and scalar boundaries. Script View uses those maps for caret placement, hit tests, wrapped-line navigation, selection, and conditional reveal, committing semantic positions through the editing command path. Desktop presentation retains distinct canonical-line and visual-caret rectangles: the visual caret and reveal use the 0.15-leading translated rectangle, while IME remains anchored to the canonical line rectangle; this does not alter interaction ownership or introduce another layout authority. A layout refresh after a successful transaction yields the new complete geometry; a rejected edit leaves the previous session and visible layout intact.
- **Boundary:** Source formatting remains available to the codec even where unsupported or invalid values fall back for layout. Desktop viewport size and scroll position cannot change document positions, page ownership, or pagination.

Project is the authority for effective paper width/height, TopMargin, BottomMargin, and DocumentLeading; HeaderMargin/FooterMargin are retained optional values outside body geometry. Absent direct-root PageLayout installs the complete standard default (612×792 points, 72-point top/bottom margins, Normal leading, 36-point header/footer). Malformed fields use documented field-local fallback, duplicate PageLayout gives ambiguous Unsupported leading and standard geometry/unused margins, duplicate PageSize defaults both dimensions, and unusable combined geometry resets the four geometry fields while retaining independently resolved leading/header/footer. Unsupported DocumentLeading is not absence. Existing retained nodes and original bytes remain unchanged; preservation-free output emits effective values and source-backed output synthesizes only when absent on a detached candidate. Apply Template is settings-only and excludes target/current PageLayout mutation; no ad hoc session setter or command is introduced.

### Presentation, status, and derived layout work

- **Requirements:** `AC-WRITING-002.6`–`AC-WRITING-002.11`, `AC-WRITING-002.14`; `AC-WRITING-006.5`–`AC-WRITING-006.11`.
- **Composition and flow:** Desktop typography resolves supported host faces into the transient font environment used by canonical per-scalar wrapping, pagination, paint, and interaction; host rasterization does not introduce a second geometry authority. The viewport may cull painting while retaining complete geometry for scroll extent and interaction. Visible-page status is derived from page rectangles and the viewport clip, not caret position. Zoom and appearance commands update transient view projection only. Wrap and prepared-layout caches accelerate derived work only when their complete definition, direct-value, resolved-face/metric, and color identity matches; complete page placement still establishes current geometry.
- **Boundary:** Page-edge breathing room belongs to scrollable content. PDF and plain-text consumers request Print composition from the same layout-owned geometry and never inherit viewport zoom, palette, or active editor mode.

- **Central editor scrollbar presentation:** Solid theme-owned scrollbar colors, full opacity of the visible track and app-painted handle in every pointer state, directional direct-handle hover feedback, and stock track-click/handle-drag interaction are desktop-only paint projections in the shared Body and Title Page central composition. The background track remains a fixed 10 logical points at rest and during direct hover. The app paints the visible handle centered at 8 logical points inside that track, with rounded ends (maximum 4-point radius, constrained by actual handle geometry) and 1-point side buffers at full visibility; the hidden built-in stock handle shape is suppressed. Visibility remains need-based, and floating allocation stays zero. Custom painting reuses public scroll geometry and stock interaction state rather than introducing another scrolling authority, widget, or hit target. The editor text-selection interaction rectangle yields only the 10-point right/bottom strips whose corresponding content currently overflows; this does not alter canonical layout, page allocation, content dimensions, actual clipping, source mapping, zoom, or viewport allocation. Future views in that central region inherit the same wrapper and ownership policy; unrelated egui areas are unaffected. These presentation and input-ownership concerns do not move into model/layout.

- **Dynamic typography and geometry:** Effective style comes from the exact current definition plus matching direct overrides. Layout receives a transient resolved-font environment with independent regular/bold/italic/bold-italic face identities and measured scalar/vertical metrics; host discovery remains desktop-only. Courier leading is 1.0×effective style size and Proportional leading 1.2×size, selected by exact resolved face. DocumentLeading contributes +0/+1/−1/−2 points; after wrapping, each visual line uses the maximum of its element base style and effective styles actually present. SpaceBefore is exact nonnegative whole-unit B/S multiplied by effective base leading. TopMargin anchors the first line-box top/imaginary preceding baseline; line-box bottoms are baselines and ordinary fit compares against paper height minus BottomMargin. Natural ascent/descent/line-gap are extent metadata only: glyph ink does not drive fit and line boxes do not clip glyphs vertically. Desktop selection and interaction retain canonical geometry; only the full-height visual caret receives the named 0.15-leading presentation translation, and conditional reveal follows that visual rectangle. The desktop adapter carries the canonical line rectangle separately through viewport projection so IME retains its original baseline. Per-scalar advances and canonical display boundaries are shared by wrapping, pagination, desktop interaction, PDF, and native Print. Absent color uses the active theme on desktop and black in output; supported explicit colors remain literal, while unsupported explicit colors are reported with bounded fallback. Complete cache identity includes effective PageLayout/DocumentLeading, resolver category, exact font/environment, ordered definitions/direct values, SpaceBefore, per-line metrics and full equality after fingerprint lookup. The type-less Title Page Content neutral style is explicit; non-Content title structures stay opaque. PaginateAs supplies keep-with-next policy only and never structural identity. PDF and Windows limitations are bounded and reported, without parity or physical-delivery claims.

### Script View mode projection

- **Requirements:** `REQ-WRITING-LOOP-002`; `AC-WRITING-002.1`, `AC-WRITING-002.4`, `AC-WRITING-002.9`–`AC-WRITING-002.10`, `AC-WRITING-002.12`, `AC-WRITING-002.14`–`AC-WRITING-002.15`; `AC-WRITING-006.5`–`AC-WRITING-006.7`.
- **Composition and flow:** One complete source-mapped layout remains authoritative in Page, Normal, and Speed. Desktop derives presented-page rectangles and one unscaled document-Y offset per page from the selected Body mode and the existing page content bounds. Page and Normal present full paper-height rows; Speed presents only each printable content-bounds height, offset by that page's content top, with no explicit or implicit spacing between adjacent rows. The shared conversion maps screen Y to `rect.top + (document_y - offset) * scale` and reverses that mapping for pointer input; fixed/projected text, selection, decorations, caret, IME, dual-dialogue boundaries, clips, culling, and reveal use the same page presentation. Actual presented rectangles and offsets feed visible-page selection and viewport-center anchors; zoom and mode-transition prepaint geometry use the same allocation policy. Horizontal page geometry, fixed pagination, source maps, and Print composition remain owned by `scriptcraft-layout` and unchanged.
- **Presentation and boundary:** Page retains the workspace backdrop and per-page paper chrome. Normal uses the page-paper backdrop without per-page chrome and adds a text-colored rule at each imaginary full-paper bottom edge that precedes another page; full-page height and existing inter-page spacing remain. Speed uses the page-paper backdrop without fill, border, or rule; it removes only the configured paper margins, retains unused space inside printable bounds, and removes both explicit and implicit inter-page spacing without repagination or reflow. The selected mode is transient Body window presentation, is not persisted to FDX, and does not affect session/revision/dirty/history state, zoom, source mapping, or exports. The separate Title Page viewport resolves Page independently of Body mode.

## Decisions

- Keep complete source-mapped document-point geometry authoritative; presentation scaling never reflows shared pagination.
- Treat indexes and cached wraps as discardable derivations rather than independent sources of page truth.
