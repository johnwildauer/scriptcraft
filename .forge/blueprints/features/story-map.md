# Feature Blueprint: Story Map

## Ownership and semantic representation

The model owns one private Story Map aggregate on `Project`: optional durable board UUID, bounded target pages, and ordered lane values. Each existing `BeatCard` owns its optional exact placement, keeping the ListItem as the sole semantic Beat owner shared by both roots. Lane UUID, Label, numeric Level, and exact Type remain distinct values; source order is preserved and Level has no ordering or placement meaning. Target and placement arithmetic is bounded and checked in integer eighth-page units. Project equality and complete candidate validation include target, board identity, lanes, and card placements. Validated whole-aggregate replacement clones and validates before installation. The existing stable-ID allocator continues to reserve card/paragraph session IDs only; durable native board/lane UUIDs are not StableIds and do not create a second namespace. Story Map changes do not replace layout identity or become Body pagination input.

FDX owns source parsing, retained source, and disposable Story Map view state. The exact Open winner is the first direct root-namespace `DisplayBoards` container and its first direct same-namespace `DisplayBoard` with exactly one unqualified `Type="StoryMap"`. Target is projected only from a unique direct root-namespace `TargetScriptLength`; lanes come from the first direct same-namespace `Lanes` container and its direct same-namespace `Lane` children in source order. The target is bounded to 1–10,000 pages; missing or unusable input falls back in the projection to 120 pages while retaining the source spelling/nodes. Missing or unusable lane collections receive collision-checked Outline 1 (Level 7) then Outline 2 (Level 5) defaults at the import/generation boundary.

Placement import examines only direct same-namespace `SubordinateTo` children of semantic Beat ListItems. A supported child has exact unqualified PageGoal Type, unqualified Order zero, an unqualified Level that uniquely resolves to a lane's exact Type, and finite decimal unqualified Number/Length values exactly representable in eighths and contained by target. Duplicate lane Type strings do not resolve by position or Level; affected placements remain unprojected. Board/lane UUID and Type values must be bounded, nonempty where required, and XML-compatible; lane UUIDs are unique. Unsupported attributes, children, ancestry, foreign namespaces, unresolved references, later Story Map boards, and malformed values stay retained and unprojected.

Height, actual timeline viewport Width, horizontal ScrollOrigin, and ZoomLevel are disposable FDX/document/save-context state, not Project data. Visibility, hover, selection, pointer capture, drag previews, popup state, and scene/cache projections are likewise outside the semantic aggregate. The default visibility preference is an optional global setting with missing-value default false.

## Command and root-composition ownership

The command catalog owns the append-only Outline Editor visibility command and the typed Story Map placement operation. Visibility is a desktop presentation command with no semantic/headless execution path. Placement carries only the stable Beat-card identity, durable destination-lane UUID, and exact start/length eighths; central availability and execution resolve current targets, and the session planner computes the complete placement result. The command envelope remains version 2, and no follower or displacement list crosses the command boundary.

The desktop application owns one root-level Outline Editor composition boundary above the active root viewport. It consumes Project data, the document's disposable Story Map view state, shared theme values, and app-facing interaction interfaces; future root viewports can compose beneath it without depending on Script- or Beat-Board-specific internals.

## Detached output and transactional boundaries

Output operates on a detached candidate. It reconciles only the winning Story Map board, target, ordered lanes, and the recognized managed PageGoal child for each semantic Beat card. Number and Length serialize as exact decimal eighths, Level is the destination lane's exact Type, Order is zero, and Type is PageGoal. A managed child is inserted before Content when required and removed only when its same semantic card no longer has placement. Unrelated ListItem values and unsupported `SubordinateTo` forms remain untouched. Source-backed and preservation-free output describe the same semantic result. Absent supported shells are generated only when semantics require them, with collision-checked native UUIDs.

The first supported board wins; later Story Map duplicates remain inert and preserved, including through Save. Story Map does not inherit Beat duplicate normalization. Existing whole-card deletion removes its placement with the ListItem and removes only matching direct board Item references; no independent placement deletion path exists. View-only attribute changes do not authorize native graph changes. Semantic, identity, graph, normalized-source, destination-conflict, output-reread, and atomic-publication safeguards remain in force. Failed output, verification, activation, or save publishes neither a partial destination nor changed live semantics/view/session state.

Successful Save/Save As captures the current clamped height, actual timeline viewport Width, horizontal ScrollOrigin, and ZoomLevel; direct source-backed serialization retains existing disposable values. Rebase carries placement with its durable card identity. Session snapshots inherit Story Map semantics through Project; there is no Story Map-specific history, dirty flag, revision, mutation token, or StableId allocation.

## Timeline geometry and presentation inputs

Let T be target pages, D the greater of T and the ceiling of the canonical final Body line bottom, W the timeline viewport width after the 90-point label column, Z zoom percent, and S horizontal origin. Unscaled domain width is `B = 2000D/T`. Fit minimum zoom is `Zfit = 100W/B`; effective minimum is `min(Zfit, 12T)`, maximum zoom is `12T`, page pitch is `(2000/T)Z/100`, scaled domain width is `BZ/100`, and maximum origin is `max(0, BZ/100 − W)`. Screen x is timeline-left plus page position times pitch minus S; pointer position is `(pointer x − timeline-left + S)/pitch`. Target-only behavior yields an unscaled width of 2,000, fit minimum W/20, maximum page pitch 240, and width 240T at maximum zoom. Overflow keeps 240 points per page at maximum zoom and extends maximum width to 240D.

The strip is composed below toolbar and above either root viewport. Height is at least 90 points; the label column is 90 points, Page Ruler 24 points, and scrollbar row equals the status-panel height. Ordered dynamic lane rows plus Script share remaining height evenly, with Script immediately below the ruler. The ruler uses 6-point whole-page and 3-point eighth ticks, each one device pixel wide, and initial density thresholds 64/32/16 points per page. The scrollbar uses proportional visible-fraction geometry and a 24-point minimum thumb; visibility auto-hides after one second unless refreshed by qualifying pointer movement, effective zoom/origin change, capture, or pointer contact. Zoom centers on the viewport page; wheel/trackpad changes horizontal origin only. All navigation clamps immediately and is disposable.

The displayed scene/caret projection is a lightweight immutable derivation of canonical Body `ScreenplayLayout`, not a second paginator. Exact scene-boundary metadata identifies headings. Start uses each heading's first canonical line box; end uses the next heading or the final Body line bottom. Caret position uses canonical focus/line geometry. Body edits, selection/caret changes, undo/redo, and document replacement invalidate the projection; actual keyboard/text/paste/IME/pointer activity resets a 250 ms quiet deadline. Due work requests canonical layout once and atomically replaces the snapshot. Zoom, scroll, height, and Beat-only actions do not rebuild it. Failed refresh retains the last valid same-document snapshot; document identity prevents reuse across activation.

Scene blocks share the timeline transform and Script-row clipping. Painted headings remove trailing whole words until they fit without ellipsis or partial words; full canonical headings remain available. A foreground read-only preview is centered below the selected block and clamped to root content, with maximum body size 480 × 200 points. It shows the full heading, wrapping only when one line cannot fit, and only the immediate following Body paragraph. Outside primary press, Escape, activation, or missing source closes it; another scene transfers it. It has no editing, selection, caret, clipboard, IME, or native viewport path.

## Placement operations and shared drag claiming

Session receives an explicit primary card, destination lane UUID, start eighths, and length eighths. It clones Project, resolves identities, computes the complete follower/displacement result, validates the candidate, and publishes through the ordinary Beat snapshot path exactly once. A placement operation cannot accept a precomputed displaced-card list or maintain a parallel placement map.

On move, followers are lower-lane cards whose original starts lie in the primary's original half-open interval; they shift by the primary delta. All lower lanes participate top-down, and a card moves at most once per planner pass. Collision resolution processes primary and carried followers as priorities, preserves each requested priority position, cascades ordinary same-lane cards rightward in current-start then durable-card-ID order, and applies the same start-overlap following rule to displaced upper-lane cards. A lower-lane move never pulls upward. Resize does not initially collect followers; tail growth uses same-lane displacement, shrink changes only primary. If any full cascade cannot fit within target, reject all changes. Exact no-op/rejection leaves Project, selection, history, redo, revision, mutation token, and dirty state unchanged.

Desktop interaction stores only transient candidate, source, pointer, token, preview, and claim data. A three-point threshold distinguishes click from drag; the final five points form the tail-resize target. Requested starts/lengths snap to nearest eighth with nonnegative half-up ties. Initial placement from Beat Board uses one page (eight eighths), clamped to target. The shared Beat drag coordinator permits one owner: a valid Story Map release claims the candidate and emits one placement operation; the Beat Board adapter then cancels its local gesture without committing geometry. Invalid external drops cancel without fallback to the last clamped Beat rectangle. Story Map-originated moves use the same exactly-once/cancellation coordination. Selection, focus, text editing, IME, and card text do not migrate to Story Map.

## Failure and preservation boundaries

Open never rewrites source, resolves unsupported data, normalizes Story Map duplicates, dirties Project, or creates history. Import fallbacks affect only in-memory projection. Detached output retains malformed, unresolved, non-PageGoal, foreign-namespace, unrelated, and later-board material. No failed identity, validation, activation, rebase, save, or publication candidate partially changes destination or prior live state. View-state changes are not semantic graph changes. User-owned review determines rendered/native behavior, persistence/interoperability, and acceptance.
