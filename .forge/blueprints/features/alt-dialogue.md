# Feature-Area Blueprint: Alt Dialogue

> This blueprint describes the current ownership and technical contracts for semantic alternate Dialogue variants. It makes no compilation, runtime, rendered/native behavior, interoperability, or acceptance claim.

## Scope and requirements

- **Requirements:** [Alt Dialogue](../../requirements/features/alt-dialogue.md).
- **Related requirements:** [Screenplay Editing](../../requirements/features/screenplay-editing.md), [Dual Dialogue](../../requirements/features/dual-dialogue.md), and [Native Document Lifecycle](../../requirements/features/native-document-lifecycle.md).
- **Technical context:** [Repository map](../technical-context.md).
- **Area summary:** Alternate variants are owner-local semantic text/run values. Current remains ordinary screenplay content; inactive variants are not nested screenplay paragraphs and do not enter selection, layout, pagination, or exports.

## Semantic ownership and editing

- The model composes [`DialogueAlternatives`](../../../crates/scriptcraft-model/src/dialogue_alts.rs:101) into each [`ScreenplayElement`](../../../crates/scriptcraft-model/src/element.rs:57). [`DialogueAltId`](../../../crates/scriptcraft-model/src/dialogue_alts.rs:21), [`DialogueAlternative`](../../../crates/scriptcraft-model/src/dialogue_alts.rs:75), and [`DialogueAltDirection`](../../../crates/scriptcraft-model/src/dialogue_alts.rs:94) define numeric identity, inactive text/runs, and Previous/Next direction. The owner’s Current is the active numeric identity; inactive values retain inline order. Existing repeated Current values across different owners remain valid.
- Pure model operations supply Add, numeric Previous/Next wrapping, ordinal projection, and Delete’s greatest-lower/otherwise-least-greater promotion. Model validation covers owner and project bounds and unique IDs within one owner; shared run normalization includes inactive values. Sparse and complete run projections preserve actual overrides and unknown attributes while keeping Dialogue defaults out of active Content formatting.
- The session’s [`dialogue_alts.rs`](../../../crates/scriptcraft-session/src/editing/dialogue_alts.rs) exposes the selected Body target and rechecks collapsed-caret, exact Dialogue capability, inline-source support, and variant count inside complete-candidate transactions. Allocation recomputes the whole-document semantic and retained-source maximum with checked arithmetic; the first no-source Add allocates the demoted identity and then the new Current, and no counter is persisted. Successful operations publish owner text/runs/state, caret, history, redo, and ordinary dirty/revision/derived changes together. Add leaves the caret at zero; navigation and Delete leave it at the active text end.
- On an Alt-state-changing candidate, session normalization rebuilds the managed owner's complete Text projection from normalized semantic runs: it reuses safe compatible templates at most once, uses safe fallback templates where representable, synthesizes same-lineage plain Text when needed, and permits deterministic recovery after all prior Text elements were removed. Opaque/nested Text, unsafe topology, mixed content, unmanaged source attributes that cannot be represented, invalid attributes, and missing/ambiguous managed anchors remain bounded failures. The model-owned inline helper runs only for a changed Alt state on a managed owner and stages its owner-child update/removal after strict preflight; semantic and source candidates publish together only after complete validation.
- Add, Previous, Next, and Delete share the session candidate path in [`editing/dialogue_alts.rs`](../../../crates/scriptcraft-session/src/editing/dialogue_alts.rs). Before semantic mutation it constructs a replacement for exactly the selected owner's old current text, using flattened UTF-16 coordinates and excluding separators/inactive variants. After installing the Alt edit it applies ordinary Body replacement maintenance once, then installs final Alt-specific note relocations before retained-source normalization and complete candidate validation. The model's candidate-local ScriptNote API stages identity-keyed range changes and validates post-edit coordinates before assignment; it does not expose unchecked note mutation or alter generic replacement affinity.
- Each action considers all exact Dialogue-capability owners with semantic or retained inline Alt presence, plus the action target for first Add/final Delete. Existing Body mapping determines endpoint paragraph membership, including paragraph start/text end; empty paragraphs have their sole/front caret. Either qualifying endpoint collapses both endpoints to the selected paragraph's flattened start. With two distinct qualifying endpoint paragraphs, the earlier/start-side paragraph wins. A range crossing an Alt paragraph without a triggering endpoint receives ordinary replacement maintenance only. Distinct notes remain distinct when collapsed to equal points; identity, content, order, timestamps and other fields are retained, and undo/redo restores the exact note snapshots. Generic ScriptNote replacement affinity is unchanged.
- For baseline-authorized inline updates/removal, preflight accepts exactly one unqualified `Current` semantic attribute plus namespace bindings, whitespace parent text, and same-namespace `AltId` children with no semantic attributes and decimal text/CDATA content. Extra or qualified semantic attributes, malformed IDs, and other content fail closed before inline mutation. This does not proactively mark every unsupported imported shape unavailable: some unsupported source can still appear eligible until an Alt command fails atomically.
- Existing split behavior is left-biased; a newly created right owner has no inherited Alt state. Join and whole-owner removal discard semantic state with the removed owner. Type changes retain owner-local semantic state; editing remains gated on current exact Dialogue capability. The session’s verified save rebase carries dormant state to a mapped owner, but a later Open of a non-Dialogue owner treats its retained Alt source as opaque under the supported-import boundary.

## FDX ownership and preservation

- The focused FDX importer in [`dialogue_alts.rs`](../../../crates/scriptcraft-fdx/src/dialogue_alts.rs) projects supported direct Body and dual-member Dialogue owners before final Project validation. It resolves the first direct root-namespace AltCollection by numeric Alt ID and exact durable paragraph ID. Unsupported, malformed, unresolved, or ambiguous shapes remain source-backed opaque data. AltCollection paragraph copies remain outside foreign identity registration.
- [`dialogue_alts_output.rs`](../../../crates/scriptcraft-fdx/src/dialogue_alts_output.rs) owns detached source-backed and preservation-free output. Source-backed output maps semantic owners to IDs found in the actual detached Content tree, including dual members and generated owners. It reconciles supported inline Alts and the first root collection while retaining unrelated entries and whole-owner orphans. Only explicit changes to managed Alt values on surviving owners remove corresponding managed entries. Generated or rewritten Alt Paragraphs use the fixed attributes and the actual owner ID; Text uses complete Dialogue defaults plus sparse semantic overrides, with empty inactive text producing no managed Text child.
- FDX semantic comparison and checked output budgets include Current, inactive IDs, text, runs, and attributes. Existing semantic reread, normalized-source, identity, destination-conflict, and atomic-publication gates remain in force. Preservation-free generation uses the already allocated Content paragraph-ID mapping rather than a second identity allocation. No universal Final Draft compatibility promise follows from this source projection.

## Commands and desktop presentation

- The additive semantic command set is ID 87 `editor.dialogue-alt.add`, ID 88 `editor.dialogue-alt.delete`, and ID 89 `editor.dialogue-alt.navigate` with the existing horizontal direction payload. Existing IDs 1–86 and envelope version 2 remain unchanged; the final catalog has 89 unique IDs. The command package executor and desktop availability/dispatch route semantic operations with current Body/selection eligibility; the overlay uses pointer-origin commands and the inactive count uses existing focus/selection commands.
- [`alt_dialogue_overlay.rs`](../../../apps/scriptcraft/src/views/script/alt_dialogue_overlay.rs) projects one frame-local geometry vector from canonical first-line layout for visible pages and an already projected caret page. It uses 0.70 rest opacity, centralized hover RGB (112, 170, 220), 14/15-point icons, 18-point indent gaps, 8/9-point count text, an 18-point count box, and 10-point ordinal text, scaled by zoom. Active controls show right-side Add then optional Delete and left-side Previous/ordinal/Next; inactive owners with multiple variants show only the total count. Paint is clipped to page/editor bounds. Pointer hit testing precedes ScriptNotes and ordinary pointer behavior; unsupported secondary/drag activations are inert. Only Body Editor-purpose presentation receives the overlay.
- The Alt pointer adapter dispatches one action for each completed primary activation accepted by its single primary-click gate, including ordinary-, double-, and triple-classified responses. Secondary/drag input remains inert, the Alt branch does not fall through to ordinary selection, and dispatch rechecks current availability. No press/release identity stabilization landed because the user-owned geometry observations remain blank. Development-only diagnostics reuse bounded value-free histories/counters for Alt outcomes, pointer classifications/submissions, accepted-edit-to-app-paint, and font signature/cache preparation; they are not runtime or performance evidence. WO-005 made no production or layout/cache optimization because its matched-baseline evidence gate was unmet.
- The overlay references `ICON_ADD_CIRCLE`, `ICON_DO_NOT_DISTURB_ON`, `ICON_ARROW_LEFT`, and `ICON_ARROW_RIGHT` from the pinned Material icon API. The WO-005 completion record says the dependency source was unavailable at the expected local path and the requested source-level confirmation of these spellings remains unresolved; this blueprint does not claim that concern is resolved.

## Unchanged boundaries

The six-library-plus-desktop-app internal graph, dependency declarations, production resources, and zero-permanent-test/zero-test-only-fixture policy are unchanged. No settings schema, font, resource, or package edge is introduced. Inactive variants remain excluded from pagination, PDF, native print, plain text, and Fountain output. Documentation and source description are not user review evidence.
