# Feature-Area Blueprint: Exports and Print

> This feature composes immutable project snapshots, fixed Print geometry, output encoders, and native host adapters for explicitly requested review output.

## Scope and requirements

- **Requirements:** [Exports and print](../../requirements/features/exports-and-print.md); [Dual dialogue](../../requirements/features/dual-dialogue.md) owns `REQ-WRITING-LOOP-013` for `AC-WRITING-013.7`.
- **Technical context:** [Technical context](../technical-context.md)
- **Requirements traced:** `REQ-WRITING-LOOP-004`, `REQ-WRITING-LOOP-013`; `AC-WRITING-004.1`–`AC-WRITING-004.6`, `AC-WRITING-013.7`.
- **Area summary:** PDF, plain text, and supported native printing derive from Print-purpose content and never substitute for or mutate the native FDX source.

## Shared composition

- [Layout and pagination](../components/layout-and-pagination.md) owns Print composition and canonical document-point geometry driven by the current definitions and resolved typography; [Editing session](../components/editing-session.md) supplies a stable project snapshot and owns native storage; [FDX preservation and storage](../components/fdx-preservation-and-storage.md) retains the codec/source boundary, with canonical and retained source values owned by [Document Model](../components/document-model.md).
- [Command contract](../components/command-contract.md) carries PDF/Print activations and options; [Desktop adapters](../components/desktop-adapters.md) owns native destination/print panels and external operations.
- The reusable bounded encoders belong to [`scriptcraft-export/src/lib.rs`](../../../crates/scriptcraft-export/src/lib.rs), with plain-text output and loss reporting in [`text.rs`](../../../crates/scriptcraft-export/src/text.rs) and PDF construction in [`pdf.rs`](../../../crates/scriptcraft-export/src/pdf.rs). The export package depends on model/layout and consumes immutable model plus Print-layout data; it owns no session mutation, destination picker, native print panel, filesystem publication policy, or platform adapter. This is package ownership within the feature composition, not a separate export component or navigation entry.
- `scriptcraft-layout` and `scriptcraft-export` have a zero-permanent-test and zero-test-only-fixture-directory policy. Their production layout/environment/cache/geometry and text/PDF contracts below remain authoritative; test removal is not validation or acceptance evidence. Canonical Print composition, output fallback/reporting limits, and desktop/native print evidence boundaries are unchanged and remain user-owned for evidence decisions. Follow the [prevention guidelines](../../../.plan/2026-11-20-template-typography-pruning/future-agent-guidelines.md).

## Capability realization

### PDF and plain-text review copies

- **Requirements:** `REQ-WRITING-LOOP-004`; `AC-WRITING-004.1`–`AC-WRITING-004.7`, `AC-WRITING-013.7`.
- **Composition and flow:** On macOS, the app-owned coordinator presents Open/save panels asynchronously against the actual root owner window. Fountain export and both PDF routes use this shared save-panel path; ordinary PDF retains one integrated fresh default-on Include Title Page accessory, while options-resolved PDF carries its original typed options. Save As PDF enters the typed host-effect path. The native panel returns an accepted destination (and, for ordinary PDF, the checkbox choice); only then does the adapter request a Print composition from an immutable project snapshot. PDF receives one coherent resolved-font environment plus immutable exact face/byte payload. Packaged Courier Prime font programs are embedded complete and unmodified under OFL; eligible host/synthetic faces follow bounded licensing, format, metric, repertoire, and byte-budget policy. The shared complete-face encoder normalizes PDF FontDescriptor ascent, descent, cap height, and FontBBox coordinates from each face's actual units per em to 1000ths of an em; these PDF-unit metadata values do not rewrite the embedded font-program bytes. CID/GID/ToUnicode cover non-BMP mappings; missing embedded glyphs use GID 0 and are reported. Base-14 and `?` substitution are host-only fallbacks; packaged payload failures are errors. PDF bounds are 8 MiB per face, 24 MiB aggregate original font bytes, 4,096 scalars per face, 268 resources, 64 MiB output, and 16 report categories. Plain text emits display text from Print lines, remains environment-only, and reports its lossy nature. Absent color is black, supported explicit colors remain literal, and unsupported explicit colors are reported. Dual-dialogue Print composition is independent of transient editor group selection, and alternate payloads never enter output.
- **Boundary:** Panel cancellation precedes PDF layout/construction/write and Fountain serialization/write. Output writes only to an accepted destination and cannot update session dirty/baseline/history, selection, zoom, or open views. Output uses canonical Print geometry without a second wrap/repagination policy. The export package does not claim universal Unicode/font support, exact visual parity, or physical print delivery. Platform limitations are explicit rather than replaced by a competing options workflow. macOS panels are document-modal sheets with asynchronous completion, not synchronous application-modal nested loops.

### Native Print operation

- **Requirements:** `AC-WRITING-004.6`, `AC-WRITING-013.7`.
- **Composition and flow:** The parameterless Print command is accepted only by the supported host. On macOS the coordinator presents the native Print panel asynchronously as an owner-window sheet, retaining panel resources until its completion is routed on a later ordinary update. Cancellation terminates before PDF construction or native operation creation. Acceptance binds panel settings to the pre-panel immutable request-time snapshot; only the later accepted continuation requests canonical Print composition/builds PDF bytes and submits exactly one PDFKit-backed operation through its asynchronous window-modal completion API. The coordinator retains accepted settings, snapshot, request, byte data, PDF document, operation, and completion delegate until terminal callback cleanup. The native callback reports only operation identity and primitive success into the bounded completion slot and requests repaint. macOS PDF-backed Print retains the same Arc-backed environment-plus-payload snapshot used by PDF export; before its panel, the macOS adapter initializes paper size from the snapshot's effective dimensions, zero additional application margins, 100% native scaling, and horizontal/vertical centering off, while PDFKit adds no fit scaling. Non-centered placement is a pre-panel default, not a guarantee about accepted imageable bounds or absence of every host-specific translation. These are defaults only, and accepted paper, orientation, and scaling choices pass through unchanged. Windows receives environment-only inputs and draws immutable vector packages from the canonical baseline (line-box top plus retained offset) and scalar x; a measured no-wrap DirectWrite baseline only cancels the native row offset, and preview/final share the package/drawing path without line-box y clipping. Natural extents are compared with the actual leading-sized line box and remain observations; descent-aware fit belongs to WO-002.1. The adapter reports bounded family, face/shaping/coverage, missing-glyph, natural-extent and color observations, not canonical geometry uncertainty. The adapter reports cancellation/failure/success only at the level the host API supports.
- **Boundary:** Print never routes through viewport painting, a temporary user-visible export, or a second settings panel. Editor-only invisibles marks are not consumed by Print, PDF, or plain-text composition and do not change canonical Print geometry or output fallback behavior. A reported operation success does not claim exact typography, spooling completion, or physical delivery; unsupported platforms return their explicit unavailable result.

### Canonical decoration output

PDF underline and strikethrough are checked filled rectangles derived from each positioned span's canonical scaled geometry, baseline, and x extents; flags must agree with geometry presence. Before complete-face embedding, both raw decoration metric pairs are compared with the exact parsed payload face, including its collection index/variation-aware values. A mismatch is a bounded payload error, not a fallback metric. macOS PDF-backed Print uses the same corrected PDF bytes and immutable environment/payload snapshot; no second decoration implementation is introduced. Windows immutable vector runs retain the same optional canonical geometry as positioned spans, and preview/final Direct2D drawing uses metric-derived rectangles through the shared package/drawing path. DirectWrite's measured baseline remains limited to native glyph row-offset cancellation.

## Decisions

- Share canonical, document-driven Print layout across PDF, text, and native printing; do not use transient viewport geometry or output-side reflow.
- Keep native panels and operation lifetimes in desktop adapters while keeping document and session state read-only for export.
