# Component Blueprint: Editing Session

> This component owns in-memory screenplay semantics and reversible editing for the lifetime of one open document session.

## Capability

The editing session operates on the canonical [`Project`](../../../crates/scriptcraft-model/src/project.rs) defined by the [Document Model](document-model.md), combining it with transient editing state and transactional operations. The model owns the ordered document element definitions, open exact element-type keys, canonical text, Title Page paragraphs, and formatting values; the session owns edits over those values, active selections for both surfaces, revision/dirty state, history, and safe publication of validated candidates. During Phase 1, editing operations reached role-backed paragraph storage only through open-key and explicitly transitional Role facades. Those transitional adapters are not document authority and are removed after all consumers migrate; after Phase 6.7 the only closed Role mapping retained is the private version-1 command-envelope adapter. Project clones in candidates, clean baselines, and undo/redo snapshots carry the ordered definitions through normal Project value semantics; the session owns no parallel registry or definition history. It is UI-independent and does not persist its transient state as document content.

## Composition

```component
name: EditingSession
container: ScriptCraft Desktop
responsibilities:
  - Own transactional Body and Title Page edits over model values, and active surface selections.
  - Validate and publish edits atomically with undo/redo and accurate revision/dirty state.
  - Coordinate source-preserving project mutations through model preservation operations.
```

- [`editing/mod.rs`](../../../crates/scriptcraft-session/src/editing/mod.rs) is the session editing API and defines `EditError`; [`editing/state.rs`](../../../crates/scriptcraft-session/src/editing/state.rs), [`editing/candidate.rs`](../../../crates/scriptcraft-session/src/editing/candidate.rs), and [`editing/history.rs`](../../../crates/scriptcraft-session/src/editing/history.rs) own session state, candidate publication, and snapshots/history. [`editing/selection.rs`](../../../crates/scriptcraft-session/src/editing/selection.rs) owns session selection validation and remapping.
- [`project.rs`](../../../crates/scriptcraft-model/src/project.rs), [`element.rs`](../../../crates/scriptcraft-model/src/element.rs), and [`title_page.rs`](../../../crates/scriptcraft-model/src/title_page.rs) own the Project, Body owner/element, and Title Page values. [`formatting.rs`](../../../crates/scriptcraft-model/src/formatting.rs) and [`formatted_text/`](../../../crates/scriptcraft-model/src/formatted_text/) own shared formatting and formatted-text values/operations; [`position.rs`](../../../crates/scriptcraft-model/src/position.rs) owns Position and Selection value primitives. [`dual_dialogue.rs`](../../../crates/scriptcraft-model/src/dual_dialogue.rs) owns dual-dialogue model values and project-level operations; session selection-aware toggling is in [`editing/dual_dialogue.rs`](../../../crates/scriptcraft-session/src/editing/dual_dialogue.rs).
- [`editing/state.rs`](../../../crates/scriptcraft-session/src/editing/state.rs), [`editing/history.rs`](../../../crates/scriptcraft-session/src/editing/history.rs), and [`editing/candidate.rs`](../../../crates/scriptcraft-session/src/editing/candidate.rs) retain live selections, revision/dirty state, the mutation token, history, and candidate publication in session. Pure editing modules depend on model values, not FDX; FDX-aware construction and native save/rebase belong to session storage, including [`storage/native_session.rs`](../../../crates/scriptcraft-session/src/storage/native_session.rs) and [`storage/save.rs`](../../../crates/scriptcraft-session/src/storage/save.rs).
- Typed callers enter through [`Command Contract`](command-contract.md). Source-backed mutations are accepted only with the guarantees of [`FDX preservation and storage`](fdx-preservation-and-storage.md); layout is derived by [`Layout and pagination`](layout-and-pagination.md).

## Contracts

- **Provably irrelevant derived invalidation:** A completed edit may bypass the full before/after derived-classification pass only after the existing scoped validator proves a nonstructural single-element candidate against a complete valid baseline, including unchanged non-target elements and global records. The target must retain the same stable identity and exact element-type key, the ordered definition registry must be unchanged, and neither that key's before nor after registry projection may have Scene Heading or Character capability. Such edits cannot change Character projections, scene-heading text, or scene topology, so they contribute no new derived invalidation and leave existing pending work untouched. Classification resolves each side against its own current registry and derives heading order, heading identity sets, Character inputs, and cue ownership only from exact scene-boundary and character-cue capabilities; unresolved managed keys, reordered shared headings, or ambiguous identity correspondence use complete invalidation. Character/heading capability transitions, text edits, structural or multi-owner operations, registry remaps, formatting outside the scoped proof, and every other unvalidated candidate retain complete classification or the existing scoped-scene classification as appropriate. Pending merge, scene-local safe-stop deferral, failed-refresh suspension, correction publication, and clean/dirty behavior remain unchanged.

- **Canonical model and surfaces:** Body is an ordered sequence of elements with exact, case-sensitive open element-type keys, exact canonical UTF-8 text, ordered runs, and managed identities. The Project carries the ordered, complete element-definition registry. Title Page is a separate ordered paragraph model; its typed paragraphs use the same key space and type-less paragraphs remain valid. Body and Title Page own independent selections and transient typing styles but share one Project, revision, dirty baseline, and chronological undo/redo history. Definition order and complete values participate in Project equality, dirty comparison, snapshots, undo/redo, and validation. `AllCaps`, font/style presentation, selection, caret, and editing policy never normalize canonical text; casing, whitespace, tabs, indentation, and imported text remain exact.
- **Shared Body owners and copy-on-write:** [`Project`](../../../crates/scriptcraft-model/src/project.rs) stores Body as `Vec<Arc<BodyOwner>>`. Each [`BodyOwner`](../../../crates/scriptcraft-model/src/element.rs) exposes its existing [`ScreenplayElement`](../../../crates/scriptcraft-model/src/element.rs) read-only and carries an ephemeral revision. Project, detached-candidate, clean-baseline, and history clones clone only the vector/`Arc` shells and share unchanged owner allocations. [`BodyOwner::update()`](../../../crates/scriptcraft-model/src/element.rs) clones and replaces only an owner whose canonical element semantics actually change; a semantic no-op retains pointer and revision. Changed direct Body paragraph formatting also replaces/revises only its matching owner because those overrides live in the Project maps. Structural reorder moves shared owners without revision changes. Split, insertion, recreation, and newly source-mapped owners receive fresh owner allocations/revisions; join and deletion discard consumed owners without transferring their source state. Title Page retains its separate value-owned representation and Title-only edits share every Body owner.
- **Owner revisions and pointer-first equality:** A fresh owner revision accompanies every canonical text/run/ID/type/provenance or direct-formatting change; clones, moves, persistence reuse, and undo/redo restoration retain the surviving owner's revision. Revisions are local runtime identity metadata, not fingerprints and not proof of equality, and are excluded from Project/owner semantic equality, FDX/native serialization, and native semantic comparisons. Project equality includes the complete ordered definition registry as well as Title Page, dual dialogue, both direct-override maps, and preservation/source state. Project and scoped candidate comparisons first accept identical `Arc` allocations, then compare complete canonical owner values for distinct allocations. Dirty state therefore detects manual restoration to the clean value even when that restoration uses new allocations and revisions; neither pointer nor revision alone can force clean or equal.
- **Owner history and persistence reuse:** Undo/redo snapshots retain shared owners, so restoration returns the exact prior allocations and revisions while advancing the existing session revision/mutation token. Mark Saved clones only the shared-owner shell into the clean baseline. Successful validated save/re-read rebasing reuses a prior allocation when stable ID and complete canonical owner semantics match; changed or newly identified decoded owners keep fresh allocations. This reuse does not bypass serialization, reread semantic/preservation checks, destination publication, source-graph validation, or any required scoped/full validation.
- **Saved-session rebase:** Save comparison includes complete ordered definitions, exact body and optional TitlePage Content keys, text/runs, title formatting, all direct paragraph overrides, and source/derived dual-dialogue state. After reread, body selection maps by stable identity when valid, then unique source identity plus format/section without comparing foreign Type; source-less occurrence matching retains its exact-key/text rule. Title selection preserves its existing stable/foreign identity across optional Type changes. Generated-parenthetical marks survive only when the mapped owner still has the exact Parenthetical key and text `()`. The reread project becomes both the live project and clean baseline; undo/redo history remains available and dirty is recomputed against that new baseline. Identity or semantic comparison failure occurs before filesystem/session publication.
- **Selection, navigation, and pointer:** Positions are UTF-8 byte boundaries validated against their surface. Insert, paste, delete, split, join, exact-key element-type change, formatting, and explicit selection commits preserve element order and reject invalid endpoints transactionally. Layout adapters resolve semantic positions for wrapped-line Up/Down, preferred horizontal goal, Home/End, page-edge clamping, pointer Press/Drag/Release, Unicode word DoubleClick, and whole-surface-paragraph TripleClick; no GUI coordinates enter the session. Selection commits and navigation use the same transactional session path. Vertical goal resets on horizontal movement, edits, pointer selection, Home/End, element-type changes, undo/redo, and boundary no-op.
- **Document Behavior transition policy:** Enter and Tab resolve current ReturnKey/TabKey through the shared Project resolver and exact open keys. `ParagraphKeyTarget::Target` owns the exact resolved key; absent and unresolved targets are consumed no-ops and never fall back to Action, General, current type, or a static transition. Execution and read-only guidance use the same pure decision, including resolved same-key targets. Ordinary Enter splits to ReturnKey (including a same-key target), except interior Dialogue retains Dialogue; Tab uses TabKey, with nonblank Character restricted to a consumed no-op. Exact Scene Heading, Character, and Transition capabilities apply strict UTF-8-safe end boundaries. Parenthetical rules require its exact capability and resolve the relevant ReturnKey/TabKey before repair, cleanup, insertion, or conversion; the before-opening Enter operation retains its current key. No Behavior target or PaginateAs value creates structural capability. Command wire version 2 carries an exact open element-type value; only its envelope adapter accepts the bounded version-1 `role` payload, maps recognized old spellings to exact FDX labels, and leaves project membership to command validation/execution. The session receives the canonical exact key, never a Role compatibility value.
- **Collapsed body Delete/Backspace:** Resolve a collapsed boundary in this order: remove the empty current element first; otherwise remove an empty adjacent element before comparing type keys; otherwise join two nonempty elements only when their exact element-type keys match; otherwise return [`EditError::InvalidSelection`](../../../crates/scriptcraft-session/src/editing/mod.rs); finally, preserve ordinary character deletion and document-edge no-ops. Removing an empty current element prefers the forward neighbor for Delete (caret at its zero) and the previous element for Backspace (caret at its end), with the opposite neighbor as edge fallback. Removing an empty adjacent element keeps the caret on the same surviving semantic element. A one-element empty body and an edge with no removable empty neighbor are successful no-ops. A permitted join keeps the left identity/type and combines canonical text/runs; a type-key mismatch changes neither selection nor content/source, history/redo, revision, dirty state, generated state, or active dual-dialogue semantics. Noncollapsed range deletion remains distinct and is not type-gated. The semantic operation is computed before source projection; imported source never vetoes a legal operation. Publication remains atomic after current semantic and current-projection invariants.
- **Generated Parentheticals:** Automatic Parenthetical insertion and strict-transition boundary policy are transient session settings, not document fields. Structural recognition requires the exact Parenthetical capability, and every repair/advance or generated-pair cleanup resolves the applicable current Behavior destination before touching canonical text. The before-opening Enter operation retains the current exact key. The generic Type-only API does not create or repair parenthetical text; it drops generated-parenthetical membership when the resulting owner lacks Parenthetical capability while leaving its text untouched. Only a high-level Behavior transition may synthesize `()` when the destination has Parenthetical capability and the owner is empty; no assignment adapter remains. The session marks only a pair it actually synthesized; marks participate in undo/redo but are never serialized. Successful content edits invalidate a mark, and failed edits do not. Enter cleanup requires enabled automation, a live mark, current Parenthetical capability, and exact text `()`; user-authored, pasted, edited/reconstructed, partial, and unmarked pairs are not treated as generated. With automation enabled, delimiter-only Tab and approved shape repair/advance use the resolved TabKey/ReturnKey before editing text; unresolved decisions leave text untouched. Delimiter-only forward Delete is limited to the exact `(`, `()`, and `)` shapes on a Parenthetical-capability owner. It removes a later owner to the predecessor end; first/only fallback clears the surviving owner and assigns the unique Dialogue-capability key through the exact-key Type source operation. Attachments remain on the surviving owner, and Delete after the closing delimiter or with a noncollapsed selection follows ordinary deletion. Special operations remain transactional and undoable; rejected/unresolved commands are successful no-ops without history.
- **Opaque owner lifecycle, formatting, and dual dialogue:** Body and Title Page edits are surface-aware and canonical-first: semantic text, ordered runs, exact element type, formatting, and structure are committed on a detached candidate before source projection. The same legal operation has the same canonical result with or without imported preservation state. Surviving owners retain their Paragraph shell, direct attributes, and unrelated non-Text attachments; direct managed formatting is projected from current canonical values. Changed Text occurrences are regenerated from canonical runs; only unrepresentable opaque descendants inside an affected occurrence may be discarded, while unaffected opaque siblings remain. Clear removes managed Text but retains other owner data. Type changes update the current Type projection and keep Alts/UserParagraphData opaque on a surviving owner. Split keeps source data on the left and generates a fresh right owner; join/range replacement retain only the semantic survivor; deletion discards the complete removed-owner subtree and registrations; recreation inherits nothing. Title structure follows current semantic order and does not require a prior recipient/template. Dual wrapping and unwrapping operate on ordered source membership; active sides derive only for an existing source group whose current exact capabilities form two Character cues and zero or more Dialogue/Parenthetical members on each side. Arbitrary/case-variant labels and `PaginateAs` do not infer capability or add members. Type-only edits and registry remaps keep an inactive group sequential and source-owned; explicit disable unwraps it, while structural edits retain or remove affected grouping under the established candidate policy. Derived metadata is owner-local: unsupported surviving data may defer refresh but cannot veto screenplay edits or Save; deletion removes it and recreation inherits nothing. Active-group presentation remains transient and unrelated to these source lifetimes.
- **Transactions, history, dirty state, and revision:** Candidate semantic content, source projection, body/title selections, transient provenance, identity state, undo snapshot, revision, and dirty comparison publish together. A no-op does not create history or revision. Failed edit, validation, identity allocation, source preservation, or capacity checks leave the live session, both selections, history, dirty state, revision, and source snapshot unchanged. Undo/redo restores exact project/source/identity/selection snapshots and preserves a single cross-surface timeline. Dirty state is derived from the current session versus its clean baseline; it is not duplicated in presentation. A successful automatic derived correction that changes the project and completes without deferral advances the clean baseline only when the session was clean immediately before that correction. A previously dirty session retains its prior clean baseline and all user edits. Unchanged, failed, deferred, and merely attempted refreshes do not rebaseline.
- **Fresh template-backed sessions:** Startup and independent File → New instantiate the default Screenplay through the public built-in loader; each built-in or external FDXT instantiation/open produces an independent Project and editing session with a fresh project layout identity and normal initial semantic-clean bookkeeping. That clean session state is not a saved-on-disk claim or an [`FdxBaseline`](../../../crates/scriptcraft-session/src/storage/target.rs). Activation installs a matching native path/baseline pair only for an ordinary saved FDX source; fresh-unsaved activation clears both, while desktop presentation separately uses `Untitled ` plus the selected built-in display name or external FDXT source filename stem (only the final extension removed; default Screenplay remains `Untitled Screenplay`). That presentation identity is not Project/session persistence. Template root WindowState/TextState is disposable imported view state and cannot establish the new Project's semantic layout identity or a save baseline. Ordinary Save requires a matching path/baseline pair; otherwise it routes to Save As to an FDX destination, whose path and baseline are installed only after verified publication. No session operation may write an FDXT source.
- **Zero-permanent-test policy:** Session test modules, integration sources, and test-only fixtures are removed under the active development policy. Their removal does not weaken the template-backed session, Save As, nonoverwrite, save/re-read, or rebase contracts above; no validation evidence is implied. Follow the [prevention guidelines](../../../.plan/2026-11-20-template-typography-pruning/future-agent-guidelines.md).
- **Body candidate ownership and move-to-history publication:** Central Body mutation borrows the unchanged live project as its baseline while constructing and validating the first detached candidate. Ordinary success therefore clones the live project shell only for that candidate, sharing every untouched `Arc<BodyOwner>`; dual-dialogue pruning/classification, scoped validation, no-op comparison, derived classification, and source reconciliation read the same unchanged baseline. Structural retry/unwrap paths may clone that baseline shell again and must remap against the exact pre-edit project. Only after candidate validation and derived classification succeed does publication move the replaced live project into the undo snapshot while installing the candidate, rather than cloning another project for history. No-op, validation/preservation failure, derived-classification failure, and every other early return leave the live project unmoved and history/redo untouched. This ownership contract does not alter Title publication, snapshot project/source state, selections, typing styles, generated provenance, history eviction, redo clearing, dirty/revision/token updates, or chronological undo/redo rollback.
- **Editor-command mutation token:** The session exposes a cheap ephemeral token for executor outcome detection. Every executor-reachable operation advances it when semantic content/history/redo or Body/Title selection/typing-style state actually changes, including transient changes with no document revision and content changes while dirty remains true. Candidate-backed no-ops and successful operations with no effective change leave it unchanged; failed operations still return their original errors. The wrapping token is not document revision, dirty/history provenance, a persistence value, or a substitute for save/layout/derived-refresh revisions. It is excluded from semantic `PartialEq` and undo/redo snapshots, so retaining session value equality does not require the executor to clone or compare document-sized state.
- **Candidate validation and fallback:** Detached edit candidates validate canonical text/runs, IDs, selections, direct formatting, and current semantic groups, plus internal coherence of the current generated source projection. Original anchors, source ancestry, foreign identity/reference reachability, old Text partitioning, and source graph equality are not edit-time authorization. Structural edits reconcile from current semantic state before publication; missing source occurrences are regenerated where the relevant FDX container and bounded source identity/anchor allocation are available. Those container/allocation requirements remain operational limits and can still fail. Validation is not skipped: current-model or projection defects roll back the candidate. Native Save separately validates current intent and compares reread semantics/current projection, including the exact ordered complete definition registry, while retaining unrelated root/board, codec, conflict, and publication safeguards. Source-backed definition changes reconcile through their winning settings projection, and preservation-free output serializes the supplied registry; strict semantic and source reread checks remain the save gate. Import diagnostics and session-local IDs/revisions are not semantic fields.
- **Generic Type and definition-remap candidate:** The body and optional-title Type-only APIs use exact old/new `ElementTypeKey` values, require a target definition before constructing a candidate, and update canonical Type, retained Type, and source provenance atomically. They change no text, runs, stable identity, direct formatting, attachments, or opaque payload; typed-to-type-less and type-less-to-typed title changes are supported only for TitlePage Content paragraphs. Body source has exactly one unqualified Type; a typed Content title has one and a type-less Content title has none. Direct TitlePage/Paragraph nodes, Header/Footer data, wrappers, and every other title structure outside Content remain opaque/preserved-only and are not edited or remapped. Unknown or foreign-namespace attributes are not Type aliases. Generic Type changes use the nonstructural candidate path and never invoke dual-group unwrap/retry: a group retains its ordered source member IDs and wrapper provenance while its active two-column sides are rederived from current types, so an invalid pattern is a valid inactive group and lays out sequentially. Definition replacement supplies the complete ordered registry, separate explicit exact-key body and Content-title mappings, and optionally ordered retained settings nodes. Every managed body key and present Content-title key must remain defined or be explicitly mapped to a defined target; malformed/duplicate mappings and invalid retained replacement fail before publication. Source-backed requests reconcile the winning settings projection unless a complete retained replacement is supplied; the latter replaces only direct-root ElementSettings and is rejected for preservation-free projects. Accepted candidates preserve selections and typing state, publish one history entry/revision, recompute dirty state, and fully invalidate derived work; no-op publishes nothing and any failure leaves project, source/indexes, history/redo, generated bookkeeping, selections, typing state, and derived state unchanged. The temporary Role command adapter converts one known Role to its exact key and retains its existing auto-parenthetical policy without using Role to format source Type. The generic candidate contains no template selection/extraction, unmatched-to-Action policy, or lifecycle behavior; Phase 8 supplies those decisions through ordinary request inputs. Dynamic Behavior and later semantic conversion remain out of scope.
- **Title editability boundary:** Across all these operations, only TitlePage Content paragraphs are editable/remappable titles; direct TitlePage/Paragraph nodes, Header/Footer, wrappers, and every other non-Content title structure remain opaque.
- **Lazy source identity-use lifecycle:** Mutable managed-source access invalidates only the source identity-use index; unchanged text-only topology retains the managed paragraph-location index for scoped validation. The central Body candidate boundary ensures paragraph locations before choosing scoped validation but does not ensure identity use on an accepted scoped single-paragraph text edit. Full-validation and structural paths may refresh identity use eagerly. Every identity-sensitive consumer owns an explicit freshness ensure before removal/reference decisions or fresh-ID allocation, including dual-dialogue operations, structural reconciliation, and derived scene metadata. Identity-use absence is transient runtime state, not document content, validation evidence, or permission to treat an identity as unreferenced. Undo/redo and successful save rebase continue to restore/rebuild both transient indexes without changing snapshots or native semantics.
- **Publication and derived state:** Session APIs are the mutation boundary; readers receive immutable project/layout inputs. Candidate canonical mutation, owner-local source projection, selections, transient provenance, identity state, history, revision, and dirty comparison publish together. Derived scene/cast refresh is owner-local and nonblocking: unsupported surviving-scene data is retained opaque and deferred while independent scenes may refresh; a deferral does not reject a screenplay edit or prevent Save. Persistence prepares a detached candidate and changes the active session/baseline only after successful durable publication. Failed current-model/projection or storage publication leaves semantic/source state, selections, history, revision, and dirty state intact.

- **Validated-session dual-dialogue target reads:** The public arbitrary-project [`resolve_toggle_target()`](../../../crates/scriptcraft-model/src/dual_dialogue.rs) retains complete project validation before surface, selection, role, group, or candidate resolution and preserves its existing errors. [`EditingSession::dual_dialogue_toggle_target()`](../../../crates/scriptcraft-session/src/editing/dual_dialogue.rs) instead uses the crate-private post-validation helper because construction fully validates the baseline and every accepted candidate is scoped- or fully validated before publication. The helper is not an unchecked public arbitrary-project API. Selection/surface eligibility, UTF-8 caret errors, Character/candidate recognition and overlap, grouped Disable behavior, mutation validation, and fresh dual-dialogue dispatch resolution remain unchanged; ordinary dispatch still avoids target queries.

- **Shared model semantic projection (WO-004.2):** The Project's borrowed `ElementSemantics` view exposes the exact definition, complete owned values, raw shortcuts, and exact-label capabilities; `Project.resolve_paragraph_behavior_target()` resolves Return/Tab against the same current registry and distinguishes unknown source, absent target, unresolved target, and resolved exact key. Editing execution and read-only guidance use this common model-owned boundary rather than rebuilding closed-role meaning. Phase 5 consumes the shared definition/capability view; Phase 6 alone parses shortcuts, detects conflicts, and binds desktop input.
- **Phase 4 dynamic editing contract:** Pure Return/Tab decisions and read-only guidance resolve the current definition's owned Behavior by exact open key and use the same decision boundary. Absent and unresolved targets are consumed no-ops, not Action/General/current-type fallbacks; same-key operations that would only assign the existing key are no-ops without publication. Special rules use exact-key capabilities only: strict end boundaries apply to Scene Heading, Character, and Transition; Dialogue interior Enter retains Dialogue; blank Character Tab is restricted; Parenthetical shape/provenance handling applies only to exact Parenthetical. Arbitrary and case-variant labels have no special cases, and `PaginateAs` is not semantic identity.

- **Open-key structure and transient Parenthetical behavior:** Ordinary split creates its right paragraph with the current exact key; join requires exact key equality, including for arbitrary labels. Every session-driven Type assignment routes through the exact-key source mutation and changes no other owner-scoped semantic value. Type-only changes preserve canonical runs, stable/foreign IDs, direct formatting, attachments, and opaque source. Structural reconciliation checks old-owner alternate eligibility through that owner's old-project Dialogue capability; arbitrary and case-distinct keys receive no inferred alternate semantics. Automatic Parenthetical insertion, cleanup, repair, and delimiter-only deletion are high-level capability-driven editing behavior, never generic Type-replacement or definition-remap side effects. Generated-pair provenance is transient session state. Scene, Character, Cast List, and dual recognition use only exact-label capabilities. A dual group owns ordered source membership independently of its active projection; inactive groups remain sequential, editable, and source-preserved, and only explicit disable unwraps one. A generic Type change or remap never unwraps/deletes the group.

- **Verification boundary:** Current-Behavior decisions, exact-key operations, capability rules, transactional no-op/failure behavior, active-versus-inactive source membership, and generated-control/Elements/selector routing remain production contracts; no permanent regression suite is retained. Source presence is not execution evidence. Native menu delivery, physical shortcuts, rendered focus/IME behavior, accessibility, and pointer placement remain user-owned host observations.
- **Phase 6 command/execution boundary:** The current command envelope emits version 2 with an exact open `element_type` value for command 22. Version 1 accepts only its bounded legacy `role` representation at the envelope adapter and converts known old spellings to exact FDX labels; neither decoding nor conversion infers registry membership or executes a command. Envelope project validation and direct executor entry independently recheck exact membership in the current Project registry. Execution routes Body changes through `change_element_type()` and explicit Title Page typed assignments through `change_title_element_type(Some(key))`; the optional-key session operation also supports typed-to-type-less and type-less-to-typed transitions, although command 22's required string value does not encode a type-less target. Same-key assignment is a no-op, and unknown/stale keys or failed candidates publish no project/source, selection, history/redo, dirty, revision, or mutation-token change. The session owns no Role command adapter. Toolbar and dynamic shortcut actions are Body-only projections that build this same typed command and recheck current availability/membership at dispatch; command origin remains diagnostic metadata, not edit policy.
- **Typography-complete layout cache identity (WO-005.6):** Validated-session layout reuse requires the published revision, project/document identity, page/layout request values, complete resolved [`LayoutEnvironment`](../../../crates/scriptcraft-layout/src/inputs.rs), and transient surface composition to match. Generic project reuse treats its semantic signature only as a collision candidate and confirms equality of every layout-affecting semantic value retained by the cache, including ordered definitions, title/body content, direct formatting, and active/inactive dual source records. Wrap identity includes the exact open key and full text/run/style/paragraph/color inputs; prepared-owner identity includes its complete environment and effective local layout values. Definition registry or resolved-environment changes cannot reuse stale lower-level output, including same-ID/new-bytes and same-ID/new-metrics cases. WO-009.2 completed resolved-environment consumption and retired the compatibility builders; this source contract does not establish runtime layout, desktop paint, or output parity.
- **Project-derived PageLayout snapshot:** Effective `DocumentPageLayout` is part of the session's Project and therefore participates in equality, dirty state, history, save/rebase semantics, and project identity. Session layout inputs are derived read-only from the current Project, not supplied by callers or mutated through a session-only setter. Undo/redo, candidate replacement, fresh template activation, and successful native-save rebase expose inputs derived from the matching restored/published Project. A future page-layout mutation must be an additive typed command/patch published through one atomic Project/source/history/revision/token/dirty transaction; no command is added here. Apply Template replaces definitions/settings only and retains current effective and retained PageLayout.
- **Complete vertical layout identity:** Complete, wrap, and prepared cache identities include effective page values and DocumentLeading, exact resolved-face resolver category and complete face/environment equality, ordered definitions and direct values, base leading, exact SpaceBefore units and resolved gap, styles/runs/text/context, purpose/composition/geometry mode, and retained per-visual-line leading/natural extents as applicable. Fingerprints locate candidates only; full equality is required, including exact bytes, face index, and complete face equality for prepared-font ID collisions. Baselines are derived after placement/rebase. Presentation zoom/font baseline, palette, viewport/native scale, PDF payloads, and native/output objects are excluded.
- **Saved rebase and dynamic-editing contract:** After the semantic/save gate succeeds, generated-Parenthetical bookkeeping remains transient and is rebased only when a mark's old and reread owners each resolve to Parenthetical capability in their own current registries, the mapped owner retains exact text `()`, and owner identity is established independently of Type. Mapping prefers valid stable identity, then unique source identity; a source-less fallback is limited to one unique matching text occurrence and never uses zip position or unchanged Type. Capability loss drops only the mark, not text; a newly opened session has no inherited marks.

## WO-006.7 compatibility and construction handoff

The temporary caller-supplied fixed-seed Project constructor and FDX nine-base `new_project()` handoff were removed in WO-007.7 after startup/File New migrated to the shared template loader. The session's Role-based `change_role()` adapter and model Role conversion surface remain removed. Version-1 historical spelling conversion remains private to command-envelope decoding, and decoded keys still require exact membership in the current Project registry before execution. Synthetic Project inputs supply their ordered definitions/content or explicitly load a full built-in document; they do not depend on a hidden empty-body constructor.

## WO-007.7 fresh-document construction handoff

Application-created documents arrive as fresh full-content Projects from the FDX catalog's common reader, followed by the established shared session activation/persistence lifecycle. The session does not create Screenplay title/body placeholders or nine-base-only projects. The landed File → New from Template UI launches an independent child through the common loader; it does not replace or mutate the parent session. Apply Template is separately available as a settings-only edit to the existing session. Neither workflow gives a template a writable path or save baseline, and Save as Template is not part of the session API.

## Phase 8 Apply Template contract boundary

Apply Template is an ordinary edit against the existing `EditingSession`, not Open, New from Template, replacement, activation, Save, Save As, or a target/baseline operation. The current Project remains the session authority. The operation accepts detached normalized target definitions and, only for source-backed current projects, ordered detached winning `ElementSettings` nodes; preservation-free projects use the existing writer without acquiring a fabricated source snapshot.

The template-specific [`plan_element_template_application()`](../../../crates/scriptcraft-session/src/editing/template_plan.rs) is pure: it accepts the current Project and normalized target registry, validates the unique exact `Action` destination, clones the complete target registry in order, and walks current semantic Body owners and typed TitlePage Content paragraphs. Exact case-sensitive target keys are omitted from remapping; every unmatched key gets one explicit key-to-Action mapping per surface, shared by any owners with that exact key. Flat Body traversal includes dual members without consulting group activity. Type-less Content titles are omitted. The planner does not inspect text, runs, formatting, group activity, opaque source, or retained settings, and attaches no retained replacement; that is supplied later only for source-backed current projects. Planning errors are bounded and produce no mutation. The public lower-level [`EditingSession.apply_element_template_settings()`](../../../crates/scriptcraft-session/src/editing/apply_template.rs) accepts only an already detached extraction and the existing session: it adds no loader, path, storage target, filesystem, app, or dialog input. Preservation-backed projects attach the detached ordered winners; preservation-free projects omit them and keep their established writer behavior without fabricating source state. It calls the generic Phase 3 candidate exactly once, which performs registry replacement, Type/provenance projection, optional current direct-root settings replacement, validation, history publication, dirty recomputation, and complete derived invalidation. `ApplyTemplateOutcome::Changed` reports the candidate's single mutation-token advance; `NoOp` reports that the generic candidate published nothing. Bounded planning/candidate errors expose no document labels, text, paths, or retained payload. A changed Apply creates one history entry/revision/token advance and clears redo; clean baseline and native storage target remain unchanged, so dirty Apply stays dirty relative to its pre-existing baseline and undo restores the preceding clean/dirty state. Selections and typing styles remain attached to their existing owners/offsets. Any failure publishes no project, source/index, selection, history/redo, derived, revision, dirty, token, target, baseline, or filesystem change.

Apply does not synchronously correct Cast Lists, SceneProperties, parenthetical/content text, or unwrap dual containers. Capabilities, Behavior, generated bookkeeping, active/inactive dual projection, layout, and current controls are recomputed or invalidated through their established registry/revision/mutation-token foundations. The public [`EditingSession.apply_builtin_template()`](../../../crates/scriptcraft-session/src/editing/apply_template.rs) accepts only [`BuiltinTemplateId`](../../../crates/scriptcraft-fdx/src/builtin_templates.rs), calls the common loader once for a fresh target, extracts detached settings, drops the full target document, then delegates to [`apply_element_template_settings()`](../../../crates/scriptcraft-session/src/editing/apply_template.rs). Its bounded error categories distinguish target load, target extraction, planning, and candidate rejection without exposing document values. Changed/NoOp is passed through unchanged; the wrapper performs no second mutation, candidate, history/revision update, derived refresh, storage action, or baseline/path replacement. Phase 9 owns only selection/presentation and a thin adapter, not remapping or a desktop-side semantic transaction.

WO-008.6 integrates the actual [`apply_element_template_settings()`](../../../crates/scriptcraft-session/src/editing/apply_template.rs) path with these existing seams: every changed complete-registry candidate schedules complete derived invalidation even when all current paragraph keys are exact target matches; semantic capabilities and Behavior resolve from the replacement registry; and the candidate does not run deferred corrections. Undo/redo restores the matching definitions/types and re-derives active versus inactive dual state. These production behaviors remain authoritative under the zero-permanent-test policy; no test or validation claim is made.

For a source-backed candidate, the FDX replacement primitive validates the complete ordered detached winner set before touching the staged current tree. Each winner must match its exact definition key and contain no target anchor or managed/attached ownership authority. Expanded names and namespace declarations must resolve under the current root or declarations carried by the detached subtree; target-root-only namespace dependencies are rejected rather than importing target root declarations. Unknown self-contained winning-node attributes, children, comments, and processing instructions remain opaque and intact. The operation removes every current direct-root same-namespace `ElementSettings` node, including inert duplicates and unusable unanchored settings, inserts winners at the deterministic settings position, and assigns fresh anchors unique against all current anchors. It does not transplant target identity/reference/board graphs or change the immutable current source-byte snapshot. The full detached preservation value, including refreshed affected source indexes, is published only after retained-tree and definition-anchor validation succeed; any rejection leaves the supplied current preservation state unchanged.

## Phase 9 Elements UI boundary

Elements inspection and selector visibility, pending catalog ID, mode, focus-return target, and bounded presentation error remain transient desktop state. They do not enter Project, EditingSession, dirty comparison, history, FDX, selection, or layout identity. The inspector reads the current ordered Project registry without caching definitions. An explicit Apply UI activation is checked by the desktop for current selector mode and exact selected-ID/payload equality, then routed once through the shared command executor to [`EditingSession.apply_builtin_template()`](../../../crates/scriptcraft-session/src/editing/apply_template.rs). The session remains the sole semantic authority for target loading, settings extraction, exact-key/Action remapping, candidate count, Changed/NoOp, and failure atomicity. Cancel and all non-Apply presentation paths do not call the service. Changed closes only the selector and invalidates both surface projections; the next Body/Title render prepares the current font/layout environment, active dual presentation is reconciled, and the session mutation token refreshes generated controls. NoOp closes only the selector without a mutation claim. Bounded target-stage and current planning/candidate failures retain the selector selection and display fixed value-free inline feedback without invalidating document/UI projections. No dialog snapshot or template-specific edit path is added to session.

## Decisions

- Keep canonical semantics, surfaces, and transient editing state in one session boundary with explicit lifetimes.
- Treat candidate publication as atomic; narrowly scoped validation is permitted only with the complete-valid-baseline proof and complete-validation fallback above.
