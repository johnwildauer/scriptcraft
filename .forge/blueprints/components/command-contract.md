# Component Blueprint: Command Contract

> This component defines the stable typed activation vocabulary shared by desktop and headless callers. It is independent of any one UI presentation.

## Capability

The command contract gives enabled ScriptCraft actions stable identities and owned, typed parameters. It separates semantic operations that can execute against an editing session from host effects that require an application adapter. Desktop controls, keyboard and pointer handling, and future non-UI callers share this vocabulary without making a user-facing command palette, CLI, MCP service, or network interface part of the component.

## Composition

```component
name: CommandContract
container: ScriptCraft Desktop
responsibilities:
  - Define stable command IDs, typed command payloads, origins, envelope version, and discovery descriptors.
  - Execute session-semantic commands without desktop/window context.
  - Separate host-effect requests from semantic outcomes.
```

- The public vocabulary is rooted at [`scriptcraft-commands/src/lib.rs`](../../../crates/scriptcraft-commands/src/lib.rs). [`values.rs`](../../../crates/scriptcraft-commands/src/values.rs) owns domain values, [`command.rs`](../../../crates/scriptcraft-commands/src/command.rs) owns stable command identity and payloads, [`conversions.rs`](../../../crates/scriptcraft-commands/src/conversions.rs) owns typed conversions and errors, [`wire.rs`](../../../crates/scriptcraft-commands/src/wire.rs) owns the versioned envelope, [`catalog.rs`](../../../crates/scriptcraft-commands/src/catalog.rs) owns descriptors/catalog validation, and [`executor.rs`](../../../crates/scriptcraft-commands/src/executor.rs) is the headless semantic executor. The desktop dispatcher is [`apps/scriptcraft/src/commands/dispatch.rs`](../../../apps/scriptcraft/src/commands/dispatch.rs).
- The command package depends on [`Document Model`](document-model.md), [`Editing Session`](editing-session.md), and directly on the FDX catalog only to convert the closed built-in command value to/from [`BuiltinTemplateId`](../../../crates/scriptcraft-fdx/src/builtin_templates.rs). The headless executor operates on the real session and invokes the session's Apply service; it does not own FDX parsing/extraction, layout, export, the desktop app, native storage, dialogs, or rendering. Desktop and layout/pointer adapters may calculate semantic positions and request host effects, while semantic edits go through the executor and host effects remain adapter-owned.

- **Envelope and origin:** `CommandEnvelope` carries `version`, `origin`, and `command`; current command wire version 2 is independent of FDX. Serde keys are `id` and `params`; unknown IDs/fields and unsupported envelope versions are rejected. `CommandEnvelope::new()` and current command producers emit version 2. At the versioned command-envelope boundary only, version 1 accepts command 22's legacy `role` payload and converts its 17 exact historical snake-case spellings (`scene_heading`, `action`, `character`, `dialogue`, `parenthetical`, `transition`, `note`, `new_act`, `end_of_act`, `cast_list`, `general`, `shot`, `sequence`, `outline_1`, `outline_2`, `outline_3`, `summary`) to their exact FDX labels. Version 2 uses `element_type` only. The element-change payload rejects a missing, duplicated, mixed, or version-inappropriate representation; unknown fields and all versions other than 1 and 2 fail before execution. The adapter never maps an unknown v1 spelling to Action/General and is unrelated to removed legacy document JSON. Origins are `Menu`, `Toolbar`, `NativeMenu`, `Shortcut`, `Keyboard`, `Pointer`, `ImeCommit`, `InternalFollowUp`, `Cli`, `Mcp`, `Test`, and `NativeOs` (serialized as `native_os`); they are routing/diagnostic metadata only and never change semantics. macOS Dock Quit is dispatched with `native_os` origin. Commands, origins, keymaps, and view state are not screenplay persistence.
- **Typed boundaries and compatibility defaults:** Text is owned UTF-8; paths use validated `DocumentPath`; element types are bounded owned exact strings backed by model `ElementTypeKey`, while surface, style, alignment, movement, timer, pointer, and import decisions use explicit domain types; selections/positions are checked UTF-8 byte offsets on the selected surface. Element labels are never trimmed, case-folded, parsed through a closed Role, or assigned a fallback. Legacy surface-less editor payloads default to Body where declared; explicit surface values are authoritative. Payloads exclude GUI/native handles, pointer coordinates, and rectangles. `PdfExportOptions` is a typed, transient, `deny_unknown_fields` value whose `include_title_page` defaults to `true`; `pdf.include-title-page.resolve` keeps its serialized ID/payload and command-wire compatibility, and directly supplied options continue through the shared continuation and legacy destination-picker path without reopening an egui options modal. Ordinary PDF activation obtains destination and a fresh default-on choice together from the native dialog; cancellation performs no output work.
- **Headless execution:** The reusable executor operates on the real `EditingSession` without desktop context. It applies supported edit, selection, exact element-type, navigation-commit, formatting, history, dual-dialogue, and typed built-in Apply semantics; it distinguishes `Changed`, `NoOp`, `Unavailable`, `Rejected`, ordinary edit failure, and bounded Apply-template failure. Apply maps each closed `BuiltinTemplateValue` exhaustively to its exact catalog ID and calls `EditingSession.apply_builtin_template()` once; Changed/NoOp and target-load/extraction versus current-planning/candidate errors are returned without a second edit. The desktop selector guard is not required for direct headless callers. Both envelope project validation and direct executor entry freshly require exact membership of command 22's target in the current ordered project registry; rejection details do not disclose the supplied key or document content. Body commands use the generic exact-key operation, and explicit Body or Title Page commands route through their corresponding session operation. A Title Page command assigns a typed key; the generic optional-key session API also retains typed-to-type-less behavior, which command 22's non-optional wire value does not encode. Same-key assignment is a no-op; unknown/stale targets, invalid selections/surfaces, and failed candidates publish no semantic, source, selection, history/redo, dirty, revision, or mutation-token change. Host-only or presentation-only commands are not emulated as semantic operations: `ui.status.set`, `application.quit`, and `view.script-view.set` are rejected by the headless executor. File pickers/storage, PDF/Print panels, clipboard, focus/window/viewport effects, Script View mode, timer clocks and notifications remain adapter-owned. `application.quit` is a root-host-effect request; the desktop routes it to guarded root Close rather than treating it as a semantic document operation. `view.script-view.set` is executed by the desktop dispatcher against transient per-window Body presentation state and does not mutate the editing session. Layout/pointer adapters may calculate semantic positions but commit them through the same executor.
- **Authoritative executor outcome boundary:** For a supported operation, the executor compares only the session-owned ephemeral mutation token immediately before and after execution. The owning session advances that token for every executor-reachable semantic publication, including content, history/redo, element-type, alignment, dual-dialogue, and range-style changes, and for Body/Title selection or typing-style changes that do not advance document revision. A successful operation with an unchanged token is `NoOp`; a changed token is `Changed`; an edit error remains `Failed` with its original error. Existing early `Rejected` and `Unavailable` returns do not execute an operation. The executor does not clone or value-compare the session, live or clean project, or history/redo snapshots, and does not infer outcomes from revision or dirty state. Session candidate validation, dirty comparison, derived invalidation, rollback, and document revision behavior remain owned by the session and are unchanged by this observation boundary.
- **Desktop dispatch and effects:** One desktop dispatcher rechecks current availability and exact current-project element membership at activation/dispatch, then routes semantic commands through the headless executor. Toolbar and generated keyboard activation construct the same open-key command; origin remains diagnostic metadata and never changes semantic policy. Menu/native/owned-accelerator events retain FIFO ordering; focused text, IME, paragraph keys, deletion, navigation, element-type changes, and pointer commits remain synchronous in source event order. `EffectDispatched` asserts routing only, not successful dialog/file/print/window/notification behavior. A picker obtains input and then dispatches a distinct direct-path command; cancellation dispatches none. Cut deletes only after clipboard write succeeds; Paste inserts only after a successful nonempty clipboard read. Direct-path Open/Save As remain callable without GUI context and preserve staged import and transactional storage rules. The typed [`EditError::IncompatibleParagraphJoin`](../../../crates/scriptcraft-session/src/editing/mod.rs) remains a failed semantic outcome; only the desktop adapter routes that specific failure to best-effort native rejection feedback, while successful no-ops and unrelated errors remain silent. Sound does not replace the bounded diagnostic or alter command success.
- **Style-clear semantics:** `editor.style.clear` clears only Bold, Italics, Underline, AllCaps, and Strikethrough on the selected surface; it preserves canonical text, alignment, non-style attributes, and unknown Style tokens. A noncollapsed selection is one undoable edit; at a collapsed caret it clears transient typing styles without document mutation.
- **Command availability:** Descriptors recheck availability at execution. Unknown IDs, invalid/out-of-range parameters, stale selection/history, unavailable commands, and modal-blocked commands fail or no-op according to typed outcomes without semantic mutation. Disabled placeholders have no ID, descriptor, command-map entry, dispatch, or activation behavior.

- **Behavior decision ownership:** Enter/Tab semantic decisions and their read-only guidance belong to the current editing session/model projection, not command descriptors or a desktop adapter. The shared pure policy resolves exact open Behavior targets against the current registry and returns the same owned target key to execution and guidance. Absent/unresolved targets are safe consumed no-ops; exact capability rules govern strict boundaries, interior Dialogue split, blank-Character Tab, and Parenthetical special handling. The status adapter renders the key label directly and performs no Role lookup. Phase 6 owns open command payloads, generated controls, and platform shortcut parsing/conflicts; headless policy and source assertions do not establish physical shortcut, focus, IME, or rendered-control behavior.

- **Model projection handoff (WO-004.2):** The Project exposes one borrowed semantic view of the exact current definition and its exact-label capabilities, plus one Return/Tab target resolver over that same registry. Unknown source keys, absent targets, unresolved owned targets, and resolved keys remain distinct; no fallback or `PaginateAs`-derived identity is introduced. Command descriptors and desktop adapters consume session guidance built on this shared projection. Raw per-definition Shortcut/WinShortcut values remain available from the complete definition; Phase 6 owns parsing, conflicts, open command payloads, and bindings.

- **Phase 6 dynamic controls and focused input:** The ordered current Project registry is the sole authority for toolbar choices, exact labels, raw shortcut values, and Behavior guidance. Toolbar and overflow use the same per-render projection containing every definition in registry order and dispatch exact keys; focused Body selection is projected fresh, with no Action fallback. Enter/Tab guidance renders the exact targets from the shared session decision. The pure shortcut parser reads only `Shortcut` on macOS and `WinShortcut` on Windows, trims surrounding ASCII whitespace, treats blank values as none, enforces the definition-string byte bound, and accepts plus-separated ASCII case-insensitive Ctrl/Alt/Option/Shift modifiers followed by exactly one supported A–Z, 0–9, named editor key, semicolon, or colon. Bare chords imply the platform primary (Command on macOS, Control on Windows); macOS Ctrl adds literal Control, Windows Ctrl is the primary, Alt/Option share one slot, and Windows Shift adds Shift. Semicolon/colon are logical text chords; colon canonicalizes to Shift+semicolon before exact matching. Source spellings are never rewritten. Injected exact menu reservations and fixed-editor wildcard key classes disable all affected entries, and every member of an unreserved duplicate group is disabled rather than winning by registry order. Structured privacy-safe issues expose only a zero-based definition ordinal, stable kind, and optional coarse normalized key category; no more than 32 issues are retained and suppressed issues are counted separately. Dynamic activation is Body-only and remains behind menu ownership, fixed editor behavior, focus, replacement/modal/native-output, and IME gates; named keys require the logical and physical keys to agree. Current controls are disposable projections keyed by document identity, session mutation token, platform, and accelerator owner; they do not enter Project, history, FDX, or layout identity.

## Phase 8/9 Apply service and command boundary

Phase 8 introduces no command ID, command payload, wire-version change, descriptor, selector, or dialog. [`EditingSession.apply_builtin_template()`](../../../crates/scriptcraft-session/src/editing/apply_template.rs) is the public headless semantic service: it accepts only a typed [`BuiltinTemplateId`](../../../crates/scriptcraft-fdx/src/builtin_templates.rs), invokes [`instantiate_builtin_template()`](../../../crates/scriptcraft-fdx/src/builtin_templates.rs) once for a fresh common-reader target, reduces it through [`extract_element_template_settings()`](../../../crates/scriptcraft-fdx/src/apply_template.rs), drops the full target document, and delegates to the existing settings-only session operation. Target-load, target-extraction, planning, and candidate-rejection errors remain distinct bounded categories and expose no labels, text, paths, or retained payload. Changed/NoOp are the existing candidate outcome; this service adds no mutation, history, revision, refresh, save, or replacement step of its own. Matching, Action fallback, dirty/history behavior, and errors are not command- or desktop-owned. No command executor or application handler may create a second candidate or replace/activate the current document for Apply.

Phase 9 adds a thin desktop adapter: it checks current availability plus live Apply-mode and selected-ID/payload equality, then routes explicit Apply once through the shared executor/service. Changed closes only the selector, invalidates Body and Title presentation projections, reconciles the active dual presentation, clears prepared font presentation, requests repaint, and lets normal layout lookup prepare the new font/layout environment; mutation-token identity refreshes current controls. NoOp closes only the selector and performs no refresh or mutation claim. Bounded failure keeps the selector and selection open with one fixed value-free inline category and performs no document/UI projection invalidation. Cancel constructs no target, plan, candidate, or mutation. Selector state, pending selection, native/in-window presentation, and menu enablement remain transient desktop concerns; they do not own semantic definitions, remap policy, source nodes, session candidates, or save targets.

### Phase 9 Elements and template command boundary

The five core typed commands use entries 53–57 above: `FormatElementsOpen`, `FormatElementsClose`, `FormatTemplateSelectorOpen`, `FormatTemplateSelectorCancel`, and `FormatTemplateApply`. The first four are bounded host effects and remain unsupported by the headless semantic executor. Apply carries only `BuiltinTemplateValue`, a closed Serde catalog identity with the exact forms `screenplay`, `stageplay`, and `dramatists-guild-musical`; it is not an element key, display label, path, or arbitrary resource identifier. IDs 58–59 add `FileNewFromTemplateOpen` and `FileNewFromTemplate`: the former is a host effect, while the latter launches an independent child using the typed catalog value and is never an editor-executor Apply operation. Element-type command values remain exact open strings. These additive identities do not change command-envelope version 2, FDX, or document persistence; peers that do not recognize an additive command reject its unknown ID normally.

Both in-window and native menu activation resolve Format → Elements through the same catalog descriptor, fresh availability projection, typed command and dispatcher; the in-window primary+E accelerator enqueues that same command through its owned FIFO route. Menu construction and activation mapping perform no loading or session mutation. The desktop Apply adapter requires an open selector in Apply-to-current mode and an exact match between the pending catalog ID and command payload at dispatch; stale, mismatched, empty, or wrong-mode commands are rejected before invoking the service. One accepted command reaches the existing headless executor, which exhaustively converts the typed catalog value, calls `EditingSession.apply_builtin_template()` once, and returns Changed/NoOp or a bounded typed failure without manufacturing a second candidate. A direct headless caller uses the same executor/service without desktop selector state. The New-from-Template selector and activation use the same catalog metadata and transient selector presentation but a separate NewDocument mode and independent-child host effect; they do not execute Apply or replace the current session. There is no separate UI executor, catalog/parser/remapper, or command-to-replacement route.

For the shared-menu implementation, the stable catalog item identity remains `format.elements`, while its typed activation is `format.elements.open` (`FormatElementsOpen`). macOS retains the catalog item's native ID and drains its activation into the common FIFO with `NativeMenu` origin; the in-window menu and owned Windows primary+E accelerator resolve the same catalog command and enqueue through that FIFO. Elements/selector host commands and New-from-Template host effects stay app-adapter-owned; all seven additive IDs remain outside document persistence and leave command wire version 2 unchanged. The sole version-1 closed-role adapter remains confined to command 22's private envelope compatibility boundary and does not restore a model Role or legacy JSON document path.

## WO-006.6 focused input and refresh integration

The desktop current-control snapshot is shared by toolbar choices, modifier guidance, and named/logical-text activation. It refreshes on the exact document-identity, session-mutation, platform, and menu-accelerator-owner key before controls or focused input consume it; successful document activation also invalidates it explicitly. Dynamic named chords require matching logical/physical keys and exact modifiers. Only one-scalar semicolon/colon Text events are considered before insertion, and successful dispatch consumes that event without a second text edit. Fixed editor and in-window menu-popup ownership precede dynamic dispatch, while existing IME, surface-focus, replacement/modal, native-output, and native-menu protections remain authoritative. Current Enter/Tab status continues to use the same ordered Behavior decision as execution. Resolver diagnostics are bounded, count-only, and privacy-safe.

## Version-1 element-command compatibility boundary

- Command ID 22 retains stable ID/order and its Body surface default while its canonical value is an owned exact open `element_type` string in wire version 2, bounded by the model key limit. ## Decisions

- Keep the vocabulary UI-independent and typed, with a headless executor for reusable semantic actions and one desktop dispatcher for all app activation.
- Keep all 52 stable IDs, command identities, payload defaults, and descriptor order unchanged while command-envelope versioning advances independently to version 2; preserve the version-1 adapter only for command 22.
