# Component Blueprint: FDX Preservation and Storage

> This component describes the bounded FDX codec, model-owned source preservation, and session-owned native storage composition as separate responsibilities.

## Capability

The FDX codec maps bounded FDX input into the canonical model and interprets/emits the retained source representation. The open model Project owns retained source trees, managed-source mappings, identities, and preservation state; session owns native file access and transactional save composition. Session storage serializes a detached Version 6 candidate, verifies supported semantic and preservation projections, checks the destination against its captured baseline, and publishes only a fully prepared candidate. Native FDX is the durable on-disk semantic source; byte-identical XML and universal Final Draft compatibility are not implied.

## Composition

```component
name: FdxPreservationAndStorage
container: ScriptCraft Desktop
responsibilities:
  - Decode and encode bounded FDX versions and project structures, including codec-owned settings, lineage, root view state, and writer verification.
  - Interpret and emit model-owned retained source trees, managed-source mappings, identities, and preservation state.
  - Compose native-session file access, detached save verification, conflict handling, publication, and successful session rebase in session storage.
```

## Contracts

- **Generalized opaque-source policy:** The ordered source tree remains authoritative. Exact expanded names and ancestry distinguish managed projections, recognized attachments, supported identity contexts, structural containers, generic opaque source, and invalid/unsafe input. Safe unknown nodes and attributes default to generic opaque retention; opaque ancestry prevents descendants named Paragraph, Text, DualDialogue, or Image from acquiring typed meaning. This refines the older named-attachment-only statements in the following contracts: unrelated safe opaque children are not a blanket Open failure. In particular, the later `UserParagraphData` paragraph's “safe-stops” wording describes refusal to assign its recognized attachment semantics, not import rejection when the occurrence can be safely retained generically; unsupported `Alts` placements similarly do not acquire alternate semantics when retained as generic source. Unsupported-but-unambiguous shapes remain opaque and do not fabricate semantics; malformed, hostile, resource-exceeding, invalid root/version/Content, genuinely ambiguous managed identity, and known required-reference failures remain bounded errors.
- **Identity and nonprojection:** Typed definitions/references are collected only from managed and explicitly supported known contexts. The `XRef` identity exception is exact: an `XRef` is typed as `Other(XRef)` only when it is a direct child of a same-namespace `DocumentRef` that is itself a direct child of the same-namespace `FinalDraft` root. A foreign-namespace `XRef`, an `XRef` under any other parent or deeper ancestry, and every `XRef` below generic opaque ancestry remain generic opaque source and are not registered. Generated scene arcs use their exact supported ancestry; only a direct same-namespace Paragraph at the supported CharacterArcBeat edge is registered. Foreign namespaces, opaque ancestry, and lookalike placements remain opaque. ID-like values under generic opaque ancestry remain verbatim source and do not become typed identities, board entities, references, or deletion dependencies. Raw source IDs remain reserved for managed-ID collision avoidance. The own unique unqualified ID attribute of a recognized managed or exact alternate-copy paragraph is definition-only for lexical-use scanning. Global source-use accounting may reserve IDs or support derived refresh, but never authorizes or vetoes a semantic screenplay edit. Recognized same-namespace Text character data alone supplies canonical runs; opaque payload does not enter semantic text, layout, PDF, plain text, or supported exports.
- **Current projection and storage gates:** Canonical edits publish first as detached semantic candidates; the retained tree is editable owner-local output state, not an editing permission graph. Current canonical runs deterministically produce the affected Text projection: unchanged matching Text templates may be reused, otherwise standard same-namespace Text nodes are generated. Opaque descendants inside an affected Text occurrence that cannot represent the new canonical runs are discarded only with that occurrence; unaffected opaque siblings, owner attachments, and unrelated source remain. Empty canonical text removes managed Text while retaining unrelated non-Text owner content. Exact open Type and direct-formatting fields are deterministic upserts; unknown attributes remain on the owner. Missing managed source is regenerated from current semantic identity/provenance where possible, not treated as a read-only gate. The Project registry is authoritative for complete definitions. Each recognized definition has at most one winning retained ElementSettings anchor on import and exactly one after source projection; later exact-label duplicates remain retained, unanchored, and inert. Winning nodes project current recognized definition fields in registry order without a second mutable settings authority. Save serializes current semantics plus retained owner-local and unrelated source. Output reread compares the complete ordered element-definition registry, canonical Body/Title Page meaning, current intended identities/projection, and normalized current source; import diagnostics and session-local IDs/revisions are not semantic comparison fields. Definition mismatch uses the existing semantic-reread diagnostic and is not a source-tree mismatch or duplicate-import diagnostic. Whole direct-root ElementSettings replacement is a separate bounded operation: it replaces that region while preserving other root children and order. Removing a definition also removes its complete exact-label settings family when an inert duplicate could otherwise become the new winner on reread; case-distinct labels and similarly named foreign-namespace nodes are not that family. Original source bytes remain unchanged. Original paragraph-target references and identities are not immutable permission baselines. Unrelated nonparagraph/root/board data, required board references, strict codec safety, destination conflict detection, and atomic publication remain guarded. Operational source-container/identity allocation failures remain possible and are documented separately from source-shape vetoes.
- **Generic owner lifetimes:** Body/title/member edits retain arbitrary opaque children and unknown attributes, including Bookmark, on the current owner. Split is left-biased and copies no opaque data to a new right owner; join retains only survivor-owned data; authorized explicit whole-owner deletion discards the complete removed subtree and its owner-scoped registrations without merge, tombstone, or graveyard. Raw source references in surviving nodes may remain orphaned and do not veto explicit deletion; stale paragraph-target typed references/anchors and bindings solely owned by the removed paragraph are cleaned without deleting unrelated raw XML. Required board references remain strict. Dual member source follows the exact member node through wrap/unwrap; outer source follows the wrapper and is removed with it on unwrap, not transferred. Undo/redo restores exact prior source snapshots; recreation receives a fresh identity and no former payload. Bookmark remains a raw attribute, not a navigation/editing/semantic feature. These generalized rules supplement rather than replace the separately recognized `UserParagraphData`, `Alts`, and spell-check attachment contracts.

- **Managed and opaque ownership:** The ordered source tree retains imported material and unrelated data. Semantic Body and Title Page owners are identified by stable current project IDs; a missing, foreign, duplicate, or unusual imported source registration does not make a semantically legal owner read-only. Current projection regenerates a supported owner occurrence at its current structural position when needed. Opaque title occurrences remain source-tree data rather than semantic title roles. Header/Footer, DynamicLabel, Tabstops, nested TitlePage TextState, unknown nodes/attributes/namespaces, mixed content, comments, processing instructions, CDATA, and unowned payload retain their source ownership until the affected owner/occurrence is destructively changed. Unsupported bounded source remains opaque; it does not create an edit permission rule. Required Content containers and successful bounded source identity/anchor allocation are still operational prerequisites for source creation and may fail.
- **Typed TitlePage import and Type mutation:** Only Paragraph nodes inside the direct TitlePage Content container are semantic titles; they are managed with or without Type. A present nonempty Type preserves its exact optional open key, including arbitrary and case-distinct labels, against the project's ordered definitions, while type-less Content paragraphs remain valid. Direct TitlePage/Paragraph nodes, Header/Footer data, wrappers, and every other title structure outside Content are opaque and preserved-only regardless of Type; they are not displayed as semantic titles, do not create definitions, and are never remapped. WO-003.2/WO-003.3 add a bounded retained-source operation and detached session candidate for typed-to-typed, typed-to-type-less, and type-less-to-typed updates on managed TitlePage Content owners only. The source operation changes only the unqualified Type attribute and retained type summary, uses deterministic insertion before the paragraph ID when adding Type, and checks the current optional semantic key plus title source provenance/identity first. Duplicate or namespace-qualified Type lookalikes fail atomically. This does not add broader writer reconciliation.
- **UserParagraphData attachment boundary:** A recognized direct same-namespace UserParagraphData subtree remains opaque on a surviving managed body/title paragraph, dual member, or wrapper. Other placements, duplicate/wrong-namespace forms, nested-in-Text data, and unrelated unsupported children remain opaque where safely retainable and do not gain recognized attachment semantics or veto a legal semantic text/role/structure edit. Canonical Text projection may discard only opaque inline descendants at the changed Text occurrence; non-Text owner attachments remain with a surviving owner. Deleted-owner attachments leave with that complete owner. UserParagraphData contributes nothing to semantic text/runs, identities, board relationships, dual markers, layout, or exports; payload IDs are not typed identities/references, while raw IDs remain reserved for collision-safe allocation. Structural normalized-tree writer comparison and bounded Open safety remain strict. Version 2 Continue and root-level UserDocumentData policy are unchanged.
- **Text and formatting preservation:** Managed empty body/title text projects to no semantic runs and no managed Text children; whitespace-only text remains nonempty. Canonical text and ordered runs control every legal projection. Reuse unchanged matching Text templates, otherwise generate standard same-namespace Text nodes; discard opaque inline descendants only inside a changed Text occurrence that cannot represent the canonical runs. Preserve unaffected opaque siblings and direct Paragraph attachments. Direct recognized Paragraph fields are deterministic current-value upserts with duplicate managed fields coalesced; unknown attributes remain. A right owner’s direct formatting disappears with that owner on a same-role join and does not block the join. Split is left-biased and does not copy owner data. Strict output comparison checks the newly intended projection, not an unchangeable original XML graph.
- **Dual Dialogue and alternates:** Supported outer General/DualDialogue/spell-check topology is classified independently from current member semantics. Every safe nested Paragraph with one unique bounded nonempty exact Type becomes an ordered managed member, including arbitrary/case-distinct keys; only the current exact-known two-cue pattern derives active sides. Other safe member patterns remain valid inactive source containers. Unsupported wrapper topology stays opaque and does not fabricate a group. Source-backed reconciliation and preservation-free output retain the wrapper and every ordered member while active or inactive; reread comparison checks ordered positions, wrapper provenance/overrides, member identity/content/overrides, and the derived active split without serializing sides. Current semantic membership, not old wrapper ancestry, anchors, or member templates, determines structural wrapping/unwrapping. Required structure is generated from current canonical members when necessary; surviving member owner nodes follow their exact members, and wrapper-owned source leaves with the wrapper. Inline Alts remains opaque data on its surviving owner and never enters canonical text/runs/selection/layout/export. A legal role change away from Dialogue updates the current canonical role and source Type without an Alts veto; Alts stays opaque on that owner. Split retains owner data only on the left/original element; joins/deletion remove it with the removed owner. Alternate copies remain opaque and are not pruned or exposed as export text.

- **Phase 4 semantic/source boundary:** Active dual sides and candidate membership are derived from exact Character, Dialogue, and Parenthetical capabilities, never from spelling similarity, case folding, Behavior targets, or PaginateAs. A source container's ordered members and wrapper provenance remain authoritative when the current pattern is inactive; generic Type changes and definition remaps preserve it without unwrap or deletion. Only explicit disable unwraps an inactive group. Explicit unwrap first verifies the exact wrapper anchor, ownership, Type, and unique foreign-ID registration, then authorizes removal only for that wrapper owner; it removes wrapper-scoped typed references/anchors/bindings and source data, rehomes exact member nodes, and registers their paragraph IDs for flat output. It does not transfer the wrapper ID, interpret unrelated raw ID matches as dependencies, or change the conservative shared removal classifier used by derived metadata. Required board references remain strict. Scene boundaries, Character cues, and Cast List correction use the same current-registry exact-label capability projection. SceneProperties are read or reconciled only on a current scene-capability heading; removing that capability leaves the attachment opaque and untouched, while a later restoration to the exact base key makes it eligible for ordinary derived refresh. Preservation-free output generates SceneProperties only for scene-capability headings and derives arcs only from Character-capability cues before the next such heading. Arbitrary types' attachments and non-Content title structures remain opaque/source-owned rather than gaining inferred semantics; `PaginateAs` is layout data, never structural identity.
- **Generated Parenthetical and delimiter source lifetime:** Generated `()` provenance is transient stable-owner session state, created only by a high-level Behavior transition that actually synthesized the pair. It is not stored in Project, FDX, retained source, or the clean baseline. Cleanup requires the live mark, exact current Parenthetical capability, exact text `()`, and enabled automation; capability-removing Type changes discard only the mark and preserve authored text. Delimiter repair/advance resolves the exact current Behavior target before source or text mutation. Delimiter-only forward Delete recognizes only exact `(`, `()`, or `)` text on a Parenthetical-capability owner; removing that owner discards its attachment with its subtree, while a first/only fallback preserves the owner and its attachments as empty Dialogue through the exact-key Type projection. Delete after the closing delimiter and noncollapsed range deletion retain ordinary semantics, so surviving-owner attachment/source lifetime remains unchanged.
- **UserParagraphData lifecycle:** Text/style/alignment/Type edits retain the paragraph's attachment unchanged; clearing removes managed Text only. Split keeps the attachment on the original/left owner and never copies it to the new right owner; join or cross-paragraph deletion keeps only the survivor's own attachment, and whole-owner deletion removes it with its subtree. Exact-key type-only changes retain the current owner and its direct formatting, stable/foreign identity, and opaque source unchanged. Old-owner inline-Alts structural eligibility uses the old project's exact Dialogue capability, not a transitional Role conversion; arbitrary labels and case variants do not inherit alternate semantics. Dual member attachments follow their exact member nodes through wrap/unwrap; wrapper-owned data ends with the wrapper. Title paragraphs follow the same left/survivor/deletion rules. Undo/redo restores the prior owner/source snapshots; no attachment is generated for a new owner, transferred, merged, or retained in a graveyard. Opaque payload IDs/names do not become managed identity or dependency evidence; raw-ID collision reservation and strict managed identity validation remain. Raw external paragraph-ID occurrences may orphan during authorized explicit removal, while required board references remain strict; derived-refresh removal queries stay conservative.
- **Identity allocation and rebase:** Existing source IDs, including non-UUID values, remain associated with surviving owners where present. Newly generated managed body/title, wrapper, scene-arc, DocumentRef, and XRef identities use collision-checked bounded allocation; actual entropy exhaustion, collision exhaustion, or anchor/event limits remain operational failures. No historical tombstone registry is used. Ordinary text/type/derived refresh, Save/Save As, and reopen retain current established IDs; split keeps the left ID and allocates a right ID; join/deletion removes only consumed owners; undo/redo restores exact snapshots. Explicit structural removal is keyed by current semantic owner identity and removes that owner’s subtree and registrations; missing/foreign old source anchors or paragraph references do not veto the semantic operation. Surviving raw values may orphan. Derived refresh is owner-local and nonblocking; unsupported surviving metadata is deferred on that owner, while deletion removes it and recreation inherits nothing. Required board references and unrelated root/board data remain strict. Successful save/re-read rebases the same live session; failure publishes no candidate identities or baseline changes. Ephemeral Body-owner revisions are never serialized or used as native equality evidence. After all normal save/reread gates pass, rebase may reuse a pre-save shared allocation only when stable ID and complete canonical owner semantics match; source/preservation comparison and publication behavior are unchanged.
- **Transient index freshness and lazy identity use:** Managed paragraph locations and source identity uses are separate ephemeral indexes over the same authoritative preservation state; neither participates in semantic equality or native serialization. Every mutable managed-source access invalidates source identity-use freshness. Text-only mutation can retain valid paragraph paths, while an explicit paragraph-location rebuild also invalidates identity use because callers may have changed the source tree out of band. An accepted scoped single-paragraph text edit ensures only the paragraph-location index and may publish with identity use absent. Removal-safety queries, raw-source-ID reservation, fresh foreign paragraph/wrapper/scene-arc allocation, dual-dialogue wrapping, body/title structural reconciliation, and derived scene-metadata reconciliation each ensure current identity-use state at the consuming operation rather than relying on an earlier caller rebuild. Explicit dual-wrapper unwrap uses its separately validated owner authorization, not the conservative removal-safety query. An absent index is never removal permission or an empty raw-ID reservation set. Direct public source-tree or identity/reference mutation followed by `rebuild_indexes()` rebuilds both indexes and refreshes source byte accounting. Full/structural editing, save rebase, and undo/redo may restore eager freshness; this does not change their validation, preservation, or history contracts.
- **FDX structure and writer verification:** Bounded readers reject unsafe XML features and malformed/unusable versions; import is read-only, and native output is Version 6 without universal Final Draft compatibility. Preservation-free generated root order places `Content`, effective `PageLayout`, `WindowState`, root `TextState`, the current ordered registry's `ElementSettings`, and optional `TitlePage` in the writer's canonical sequence; source-backed imported order remains retained. Generated root TextState attributes are `Scaling`, `Selection`, `ShowInvisibles` in order. Root TextState is disposable root-only view state: Open selects only one direct root instance, defaults invalid/missing Scaling to 100 then clamps to 75–300%, and maps a complete valid Selection from bounded UTF-16 flat body offsets (one paragraph separator) to canonical UTF-8 positions; malformed/unmappable selection becomes caret 0,0. Open applies zoom/selection once; transactional save replaces the root block with current body zoom/selection and `ShowInvisibles=No`. Nested TitlePage TextState is opaque and never initializes the editor. New-document and source-backed output retain their distinct XML declaration/separator rules; imported top-level/opaque order is never rearranged.
- **Effective PageLayout projection:** The common bounded reader parses only a direct-root same-namespace PageLayout and its PageSize. Project owns the effective paper dimensions, top/bottom margins, typed DocumentLeading and optional exact header/footer margins; session inputs are derived from Project. Absent PageLayout installs the complete standard values (612×792 points, 72-point top/bottom, Normal, and retained 36-point header/footer). Field-local malformed/missing values use their documented defaults; duplicate PageLayout is ambiguous and yields standard geometry/unused margins plus Unsupported leading; duplicate PageSize defaults both dimensions; combined unusable geometry resets the four geometry fields while retaining independently resolved leading/header/footer. Unsupported DocumentLeading remains unsupported, not Normal. Nested/foreign lookalikes stay opaque. Existing PageLayout nodes, unknown attributes/children, malformed spelling and original bytes are unchanged. Preservation-free generation emits effective PageLayout; source-backed writing inserts one only when absent, on a detached candidate after Content and before WindowState, never normalizing an existing source node. Writer/save reread compares effective values and successful session rebase derives the matching read-only layout snapshot. Apply Template excludes PageLayout.
- **Ordinary FDX root-marker output projection:** Source-backed serialization clones retained sections, prepares exactly one direct `FinalDraft` root by normalizing its unique unqualified `Version` to `6` and removing its direct unqualified `Template` attribute, then performs lineage, view-state, settings, paragraph reconciliation, and expected-section capture on that detached projection. The operation does not mutate original bytes or the live pre-save retained tree. It preserves surviving root attributes and their order, namespace-qualified `Template` lookalikes, descendant elements named `Template`, opaque non-Content TitlePage structures, and all unrelated root values; it does not insert `Template=No`. Preservation-free generation already has no root marker. Direct serialization and transactional Save/Save As therefore return ordinary marker-free FDX, with the re-read source comparison expecting the same projected tree.
- **DocumentRef/XRef:** Transactional Save/Save As updates the direct root DocumentRef DateTime to one captured local-wall-clock `YYYYMMDDTHHMMSS` (UTC only if local offset discovery fails), preserves an existing DocumentRef ID/source position and unrelated attributes, and creates a fresh UUID v4 ID if absent. Session-open time is independently captured at session creation and remains ephemeral/fixed across saves. Ordinary Save appends one direct XRef carrying session-open time and a fresh collision-checked ID only if no direct XRef exists; otherwise existing XRefs remain unchanged. Save As appends exactly one XRef regardless of existing history. The source classifier registers that `XRef` as `Other(XRef)` only at the exact same-namespace `FinalDraft → DocumentRef → XRef` ancestry; all other `XRef`-named payload remains opaque. Direct source-backed serialization has no lineage side effects. Lineage, root WindowState, and root TextState changes occur only on the detached transactional candidate after original identity/reference graph comparison and before strict final identity/source-tree checks.
- **WindowState:** Root `WindowState` is disposable native view state, not Project/session semantics. Only one unambiguous direct root element is considered; signed bounded Left/Top and positive bounded Width/Height are required, unknown/missing Mode means Normal, and unusable state never blocks Open or triggers restore. Restore is one best-effort native outer-position/inner-logical-size request after activation with no retry. Transactional Save replaces root duplicates by one canonical Height/Left/Mode/Top/Width block from the latest valid OS-logical snapshot, using shared defaults only when no complete snapshot exists; a missing block is inserted after PageLayout or before ElementSettings (after Content for preservation-free output). Direct source serialization leaves it unchanged. Nested lookalikes and unrelated source remain opaque.
- **Detached candidate and normalized comparison:** Save preparation, owner-local derived refresh, current semantic/projection validation, serialization, codec reread, semantic comparison, current intended identity/projection comparison, unrelated root/board safeguards, destination conflict checks, and normalized current-source comparison precede publication and live-session rebase. Mutable paragraph references may be removed with their owners; surviving raw XML may retain orphan values. Original-byte comparisons remain only for unrelated nonparagraph/root/board state that the operation did not authorize changing, not as screenplay edit or save permission. Normalization omits serializer-invisible empty XML text nodes and merges adjacent nonempty text nodes only; it does not omit empty CDATA, whitespace-only text, empty elements, comments, processing instructions, or opaque empty Text controls. Code 30 reports a deterministic bounded child-index path and structural category only; it does not relax current-intent comparison.
- **Saved-session rebase identity:** The semantic save gate compares the complete ordered definition registry, managed body/TitlePage Content projections, all direct paragraph overrides, and dual source membership plus its derived active state. Rebase maps body selections and dual members by stable identity where valid, then unique foreign identity with source format/section; foreign Type is not identity. Title selection remains mapped by its existing stable/foreign identity even when its optional Type changes. Generated-parenthetical bookkeeping is session-only and is retained only for a mapped exact Parenthetical owner whose canonical text remains `()`. Successful publication installs the same reread project as the live project and clean baseline, preserving history for post-save undo/redo; comparison or identity failures precede publication.
- **Capability-aware generated-mark rebase (WO-004.9):** The old and reread owners are independently resolved through their respective current definition registries; a generated mark survives only when both owners have exact Parenthetical capability and the mapped reread text is exactly `()`. Stable identity is preferred, then unique source identity; source-less identity fallback requires one unique matching text occurrence and never uses positional zip or an unchanged Type key. The mark remains session-only and is not copied into the Project, retained tree, FDX, or clean baseline.
- **Storage and replacement:** Reads are bounded, no-follow, and refuse unsafe/non-regular/symlink paths. Save As to an absent path is create-only; an existing path can be replaced only with explicit consent. Consented replacement captures a bounded no-follow byte baseline and basic permissions, rechecks the baseline immediately before same-directory atomic replacement, and falls back to atomic create-only installation if the destination became absent. A racing creator is never overwritten. Temporary bytes are flushed/synced before atomic publication. Destination conflicts retain the external version. Unsafe/unreadable/oversized/changed destinations and preparation, codec, re-read, conflict, or publication failures leave the prior valid destination and live session/path/baseline/selection/dirty state unchanged. Failure reporting says the document is unchanged and does not claim a successful save.
- **Privacy and diagnostics:** Save errors expose bounded value-free categories, never screenplay/source text, XML text/attributes/namespaces, IDs/UUIDs, image data, serialized XML, or filesystem paths. `UnsupportedConstruct` writer codes preserve their integer prefix at character zero through codec, transaction, and desktop error details; other categories receive no writer code. Code 30 preserves its prefix and adds one bounded deterministic structural path/category only. Diagnostic routing is independent of the desktop `--dev` visibility gate.

## Phase 8 settings-only Apply boundary

The built-in target is loaded through the Phase 7 common reader and reduced to its complete normalized ordered definition registry plus exactly one retained direct-root `ElementSettings` winner per definition in matching order. The FDX-owned `ElementTemplateSettings` value keeps those two ordered projections private and exposes read-only accessors, so callers cannot desynchronize them. Extraction clones the source-backed target Project, runs Phase 3 settings reconciliation on that detached clone, then resolves winners from the normalized registry's existing definition anchors; it does not recursively read FDX or traverse target content. First-use and required-base definitions therefore have fully materialized retained settings, while later inert duplicates are excluded. Extraction validates the registry, exact keys/order, winning anchors, unique exact `Action`, and preservation bounds before returning a complete value or a bounded error. Retained unknown attributes, namespace bindings, opaque winning-node children, comments, and processing instructions remain attached to detached winners; target-local anchors, ownership/reference authority, and source-location bookkeeping do not transfer. Target body/title content, PageLayout, headers/footers, continuation, root view/window state, source bytes, target identity graph, path, baseline, and all other settings are absent from the result.

For a source-backed current project, Apply replaces the entire direct-root same-namespace `ElementSettings` region—including inert duplicates and unanchored/inert source settings—with the detached ordered winners, assigns fresh current-document anchors, and preserves all non-definition root children/order and the current original-byte snapshot. Foreign-namespace lookalikes, descendant settings, and other current source remain outside that region. Before mutation, each replacement must agree exactly with the ordered target registry, contain no target anchor or managed/attached ownership authority, and have expanded names and namespace bindings resolvable in the current root context. Self-contained unknown namespace payload is retained verbatim; a target-root-only prefix dependency or retained source-identity binding that would require importing target namespace/identity graphs is rejected. Publication rebuilds the affected retained-source indexes only after the staged tree and fresh-anchor set validate. The current Project registry stays authoritative; source-less current projects omit retained nodes and use the established preservation-free writer. A failed replacement is atomic and cannot leave mixed settings, target identities, partial index changes, or altered source bytes. Exact keys and Type projections follow the session's Apply policy; no target content or unrelated target source is imported.

The single session candidate is the publication boundary. Apply neither changes storage target/baseline nor invokes filesystem, staged-open, activation, writer-save, or rebase operations. Undo/redo snapshots carry the complete semantic and retained authorities together, and normal save/reopen later verifies the current document's definitions, Types, source projections, and preserved non-definition data. Phase 8's headless Apply semantics and Phase 7–9 selector/native-menu/visual behavior remain distinct evidence boundaries chosen by the user; source contracts and test absence are not execution evidence. See the [technical context](../technical-context.md#user-owned-phase-8-evidence-boundary).

## Phase 9 presentation and FDX ownership boundary

The Elements inspector is a live desktop presentation of the Project's ordered definitions, not an FDX settings editor. The desktop does not own an FDX parser, retained settings copy, template catalog, target source graph, or second replacement/transaction path. Current-document direct-root `ElementSettings` replacement and preserved-source atomicity remain FDX/session responsibilities.

## Decisions

- Preserve the source tree alongside narrowly managed semantic projections; unsupported data remains opaque rather than being guessed at or discarded.
- Keep detached candidate preparation, strict re-read/comparison, conflict detection, atomic publication, and session rebase as separate gates.
