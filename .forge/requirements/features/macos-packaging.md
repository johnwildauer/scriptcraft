# Requirements Area: macOS App Packaging

## Area purpose

Provide a repeatable, source-owned path for constructing a relocatable macOS app bundle and compressed disk image for user-run review. This is a bounded packaging/distribution choice for the current artifact iteration, not a declaration of the complete set of product-supported or unsupported platforms.

## Packaging and distribution requirements

- **REQ-MACOS-PACKAGING-001: Reproducible app bundle assembly.** The packaging driver shall derive the marketing version from `apps/scriptcraft/Cargo.toml`, build only the `scriptcraft` package for the current `aarch64-apple-darwin` artifact, and assemble `ScriptCraft.app` with display name `ScriptCraft`, executable `scriptcraft`, bundle identifier `com.scriptcraft.app`, initial integer build version `1`, and a valid property list. The bundle declares two separate extension-fallback document types: FDX with Editor role, Alternate handler rank, and `fdx`; and FDXT with Viewer role, Alternate handler rank, and `fdxt`. Viewer describes non-writable template-source handling; an instantiated template document remains editable. It declares no imported or exported UTI: no FDX/FDXT UTI is invented or claimed as ScriptCraft-owned. Neither declaration uses `NSDocumentClass`. The declarations make the app eligible for Launch Services delivery; they neither validate file content nor claim the default handler. The bundle shall not claim an untested minimum macOS version or require Cargo at app runtime.
- **REQ-MACOS-PACKAGING-002: Source, bundle, and runtime icons.** The supplied 1024×1024 icon master shall remain byte-identical when relocated to `packaging/macos/AppIcon.png`. The packaging driver shall generate the ordinary and Retina icon sizes from that square master without cropping or changing its aspect ratio and install the generated `.icns` resource in the app bundle, preserving the `CFBundleIconFile=AppIcon` declaration. On macOS, the desktop executable shall explicitly supply eframe's documented empty-icon sentinel so eframe does not call its native application-icon setter; Launch Services shall retain ownership and display the icon from the packaged bundle metadata/resource through startup and project-open handling. The source PNG shall remain embedded and supplied as the runtime icon on non-macOS native targets. macOS window icons are not a separate presentation surface. Runtime setup shall not rely on repository-relative or current-working-directory paths.
- **REQ-MACOS-PACKAGING-003: Runtime resource and font license boundary.** Courier Prime and Material Symbols font binaries shall remain embedded in the executable; packaging shall not duplicate the font binaries in the app. Built-in FDXT template bytes are compile-time resources in the FDX package and are not staged as runtime files or resolved relative to the repository/current working directory. The local bundle shall include the applicable font license/attribution records. Rust dependency license/notice review is deferred to a separate distribution-preparation decision and is not a prerequisite for this local artifact. This deferral does not assert that third-party notice obligations do not apply to later distribution.
- **REQ-MACOS-PACKAGING-004: Ad-hoc signature and unnotarized scope.** After the executable, icon, metadata, and font license/attribution records are assembled, the driver shall ad-hoc sign the complete app without a timestamp and verify the bundle signature and arm64 architecture. It shall not use `--deep` as a substitute for bundle construction, access credentials, invoke Gatekeeper assessment, or imply Developer ID authentication or notarization. No clean-launch or downloaded-recipient guarantee is made.
- **REQ-MACOS-PACKAGING-005: Bounded DMG and artifact outputs.** The driver shall stage only the signed app and an `/Applications` symbolic link, create a compressed read-only DMG, verify its image/layout, inspect executable linkage, and produce a SHA-256 sidecar. All generated artifacts and cleanup shall remain under the fixed `target/macos-package/` root; unrelated build output shall be preserved.
- **REQ-MACOS-PACKAGING-006: Rebuild and user acceptance.** A standalone guide shall document prerequisites, the one rebuild command, optional workspace checks, exact version/architecture output names, bundle inspection, Finder launch, functional scenarios, limitations, recipient guidance, and troubleshooting. Artifact inspection covers exactly two separate declarations (FDX Editor/Alternate with only `fdx`, and FDXT Viewer/Alternate with only `fdxt`), extension-fallback metadata, and absence throughout the property list of `LSItemContentTypes`, imported/exported UTI declarations, and `NSDocumentClass`. Packaged user scenarios cover cold and running Finder/Dock opens for both formats, FDXT open-as-new/nonoverwrite behavior, source-hash preservation, Save As to ordinary FDX, unchanged FDX/FDXT default-handler state, and relocation without a repository working directory or runtime template-resource directory. Source-level regression assertions and package metadata are not evidence of native Finder/Dock delivery, font availability, or relocated-app acceptance. The user owns all checks, packaging execution, review, artifact inspection, application launch, recipient tests, Launch Services behavior assessment, and acceptance; script completion is not Launch Services acceptance.

## Observable acceptance

When the user runs the documented path with its prerequisites, the expected deliverables are a version-derived `ScriptCraft-<version>-arm64.dmg` and matching `.sha256` under `target/macos-package/`; a valid `ScriptCraft.app` bundle with the expected metadata, executable, bundle icon, and font license/attribution records; an ad-hoc signature; and an arm64 executable whose inspected linkage has no unexplained non-system dependency. Artifact inspection includes exactly two independent extension-fallback declarations: FDX Editor/Alternate/`fdx` and FDXT Viewer/Alternate/`fdxt`, with no UTI metadata or `NSDocumentClass` anywhere in the property list. Runtime acceptance includes user-owned cold/running Finder and Dock ingress trials for both extensions; FDXT activation as editable content titled `Untitled ` plus the external source filename stem, removing only its final extension with no writable source target; unchanged FDXT source hash; Save routing to FDX Save As; marker-free ordinary FDX output; and unchanged default-handler state for both types. It also confirms that macOS continues showing the bundle-declared icon in Finder/Dock after application startup and project open; the application does not replace it with eframe's icon. Declaration does not guarantee Finder presentation or install/capture a system-wide default. User acceptance covers the documented optional workspace checks, Finder/functionality scenarios, and recipient behavior within the stated limitations. Rust dependency license/notice review remains a separate gate before broader distribution.

## Boundaries and limitations

- Ad-hoc signing is not Apple Developer ID signing or notarization. Recipients may receive a Gatekeeper warning; guidance is limited to trust-qualified right-click/Open and Privacy & Security/Open Anyway flows.
- `aarch64-apple-darwin` describes this artifact choice only, not a permanent support matrix or platform exclusion.
- The bundle omits `LSMinimumSystemVersion`, `LSItemContentTypes`, imported/exported UTI declarations, `NSDocumentClass`, sandbox entitlements, an installer, updater, background service, credentials, and notarization configuration. Its `fdx`/`fdxt` extension declarations are nonexclusive and do not set or capture either default handler; Windows remains a separate portable, no-registration package.
- Bundling does not guarantee macOS notification authorization or delivery.
- No generated app or DMG is accepted merely because a packaging script completes.
