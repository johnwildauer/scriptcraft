# Requirements Area: Page Layout

> This document specifies desired user-facing behavior for a cohesive area. Describe requirements in established-state voice, even when implementation is future work. Group related capabilities into sections and keep stable IDs so each requirement and acceptance criterion remains independently traceable. Do not add lifecycle status, implementation evidence, progress, or a backlog here.

## Area purpose

Writers can move between continuous screenplay editing and a predictable fixed-page preview. Page geometry, source mapping, interaction, and zoom remain coherent as the document is edited and viewed.

## Capability groups

### Shared screenplay layout

- **REQ-WRITING-LOOP-002: Shared deterministic writing and page views.** The system shall let a screenwriter write continuously and inspect a predictable fixed-page result based on the same screenplay meaning and layout inputs.
  - **AC-WRITING-002.1:** The same screenplay, current ordered element definitions, direct formatting, page inputs, and explicit resolved-font environment shall produce repeatable page structure and source mappings regardless of presentation zoom or palette. Imported FDX layout is not guaranteed to paginate exactly like every other screenplay application.
  - **AC-WRITING-002.2:** Layout shall apply the complete current element definition plus only its matching direct overrides and preserve canonical text without adding spaces or tabs to simulate indentation. Body and print/output wrapping shall use effective paragraph bounds, first-line indent, and resolved per-scalar advances consistently, without a separate arbitrary text-width limit. Type-less TitlePage Content paragraphs use an explicit neutral presentation supplied by the layout environment, not a guessed element definition; title structures outside Content remain opaque and are not laid out as managed paragraphs.
  - **AC-WRITING-002.3:** Long text and oversized elements shall wrap or split safely, with continued layout progress and no infinite loop or unbounded blank-page behavior.
  - **AC-WRITING-002.4:** A valid text position and rendered geometry shall support reliable caret placement and pointer hit testing at valid text boundaries.
  - **AC-WRITING-002.5:** Supported paragraph alignment, first-line indent, left/right positions, spacing, leading, PaginateAs, and explicit page starts shall affect their assigned behavior independently, using the current definition and only its matching stable-ID direct override. Left/right indents validate as a pair; invalid direct values fall back to the definition pair, unusable definition values to page margins. First indent resolves independently through direct value, definition value, then zero. Courier leading is 1.0×effective style size and Proportional leading is 1.2×size, selected by the exact resolved face category. DocumentLeading adds +0/+1/−1/−2 points (Normal/Loose/Tight/Very Tight) to each candidate before taking a line maximum. After wrapping, the element base style and distinct styles actually present on each visual line determine that line's maximum; later base-only lines return to base leading. SpaceBefore is an exact nonnegative whole-unit ratio B/S (selected point value/base element-setting size), multiplied by effective base leading; inline size overrides do not change it. Apply the gap only at nonempty same-page paragraph boundaries, not fresh-page starts. TopMargin anchors the first line-box top. Each baseline is that line-box top plus its resolved natural ascent and DocumentLeading adjustment; the next line-box top advances by full effective leading. Body, keep-with-next, Title Page, dual-block, oversized, and spill fit use each candidate final natural bottom (baseline minus signed natural descent) at BottomMargin. Leading-based advancement and applicable gaps remain separate; fresh-page oversized progress stays bounded. Natural ascent/descent/line-gap remain metric extents in this baseline correction; character ink never determines leading, wrapping, or clipping, and line boxes do not clip glyphs vertically. Unsupported DocumentLeading remains unsupported; invalid direct SpaceBefore uses its field-local fallback and invalid definition derivation is a bounded error. PaginateAs enables keep-with-next only for exact Scene Heading, Character, and Parenthetical; other values do not grant capabilities. StartsNewPage remains paragraph/direct-override data. Imported pagination need not match another application.
  - **AC-WRITING-002.6:** Supported definition and direct-run font family, size, weight, italic, underline, capitalization, hidden-text, and color settings affect their supported presentation. A transient resolved-font environment supplies four independently selected styles per declared family and complete face identities/metrics. The exact resolved face selects the Courier or Proportional leading category; family spelling does not. Courier Prime fallback faces use Courier; successfully resolved proportional host faces use Proportional. Natural font-table descent determines conservative final-line fit; line gap and character ink do not control leading, wrapping, or clipping. Host discovery remains desktop-only. Color and font fallbacks remain bounded and do not rewrite source settings.
  - **AC-WRITING-002.7:** All Caps changes display text only and preserves canonical text and valid source positions, including Unicode uppercase expansions. Hidden-text definitions remain visible/editable and subdued in the editor, but are omitted from print/PDF/plain text. PDF uses complete unmodified packaged Courier Prime faces and may embed eligible host/synthetic faces under bounded policy; embedded scalars use CID/GID and ToUnicode including non-BMP mappings. Missing embedded glyphs use GID 0 at canonical x and are reported. Base-14 and `?` substitution are host/synthetic-only fallbacks and are reported separately; packaged payload/font failures are errors. PDF reports explicit-color fallback and bounded resource/budget outcomes without claiming universal glyph coverage or visual parity.
  - **AC-WRITING-002.8:** Supported direct paragraph formatting overrides only its matching element-definition setting; absent or unusable values use the documented shared fallback. Invalid direct values remain preserved and fall back independently. Direct paragraph geometry does not alter element-definition typography, title-page interpretation, or run formatting. Splitting does not copy direct paragraph formatting to the new paragraph; joining across a paragraph whose direct formatting would be lost is rejected without changing the document.
  - **AC-WRITING-002.9:** Scrolling and viewport changes shall not change fixed page dimensions, source mapping, page count, or which document positions own interactions. Pages outside the visible area may be omitted from painting, but shall not become inaccessible or acquire interaction ownership.
  - **AC-WRITING-002.10:** Desktop glyph baselines for managed Body and TitlePage Content equal each line's canonical baseline: line-box top plus the retained natural ascent and DocumentLeading adjustment. Selection and interaction retain the canonical leading-sized line box; the full-height visual caret is translated downward by 0.15 of that line's leading as a presentation-only offset. IME text is anchored at the canonical line-box top and uses the same canonical baseline offset as ordinary glyphs. Pointer, navigation, and decorations use the same baseline-aware projection, and conditional caret reveal uses the translated visual rectangle. Horizontal clipping includes the effective first-line indent while retaining the paragraph right edge; page clipping remains deliberate, but the line-box y is not a glyph clip. Natural extents may exceed the box; metric-aware culling includes the line box, baseline, and natural extents and remains broad-phase paint work; pagination separately reserves final-line natural descent. Natural descent is not a persistent status warning.
  - **AC-WRITING-002.11:** Repeated layout for unchanged semantic content and effective Project-owned PageLayout plus resolved environment yields the same complete output as a fresh layout. Complete/wrap/prepared identity includes DocumentLeading, resolver category, exact face metadata/metrics/scalar maps, ordered definitions/direct values, base leading, SpaceBefore units/gap, styles/runs/text/context, purpose/composition/geometry mode, and per-line leading/natural extents as applicable. Fingerprints select candidates only; full equality authorizes reuse, including exact prepared-face bytes/index/complete-face equality. Baseline derives after placement/rebase. Zoom, palette, viewport, native scale, PDF payloads/objects, and native output objects are outside canonical identity.
  - **AC-WRITING-002.12:** Caret, page/line hit testing, and vertical movement use canonical display boundaries and actual variable-height line boxes with deterministic document-order tie-breaking. Nearest-line queries operate across differing leading and line-box heights; Title pages remain excluded from Body hit-test/navigation.
  - **AC-WRITING-002.13:** An edit that cannot be shown to preserve the document and its imported source content shall be fully checked or rejected. Failed edits do not change the document, selection, undo/redo history, save state, or visible layout. A retained dual source container whose current ordered member types do not form an active two-sided projection remains valid document content; layout emits no dual block for it and presents its members once each in ordinary sequential body order, without unwrapping the source container.
  - **AC-WRITING-002.14:** Page-edge breathing room belongs to the scrollable page content and moves with it. Script View has independently controlled space before the first page and after the last page; ordinary scrolling does not obscure pages with edge fades. In the central editor region, scrollbars appear only when content overflows. The background track remains 10 logical points thick at rest and during direct hover; the visible app-painted handle remains 8 logical points thick at rest, hover, and drag and is centered within the track, leaving a 1-point cross-axis buffer on each side at full visibility. The handle has rounded ends with a maximum 4-logical-point radius, clamped to half its smaller dimension during visibility animation or constrained sizes. Floating allocation is zero, leaving page width, canonical layout, zoom, and viewport geometry unchanged. This local presentation applies to Page, Normal, Speed, Title Page, and future views in the central region, not globally to egui scrollbars. Presentation spacing does not alter core document layout, and zoom preserves the intended relationship between page origins, page geometry, and scroll extent. The track and visible handle remain fully opaque at rest, when the pointer enters the editor, during direct scrollbar interaction, and while dragging; entering the editor does not reduce alpha. The desktop theme owns distinct editor-scrollbar track, resting-handle, hovered-handle, and dragged-handle colors; direct handle hover is brighter in Night and Midnight and darker in Day, while dragging retains the owned dragged-handle presentation. Stock handle dragging scrolls the corresponding axis, and clicking the track outside the handle repositions the viewport. Custom painting changes no hit target, scrolling rule, clipping rectangle, page allocation, canonical layout, zoom, or source mapping. Editor text-selection hit ownership excludes only currently necessary scrollbar strips; text selection elsewhere, clipping, scroll extent, and page geometry remain unchanged.
  - **AC-WRITING-002.15:** Body Script View offers Page View, Normal View, and Speed View over the same complete, source-mapped core pages. In all modes the fixed paper-width screenplay column remains centered and its horizontal geometry, zoom, pagination, page total, source mapping, and fixed layout do not change. Page View retains the workspace backdrop and per-page paper fill/border. Normal View uses the active page-paper color across the Script View backdrop, omits per-page fill/border, retains full paper-height page rectangles and the existing external page gap, and draws one 1.0-logical-point text-colored rule at each imaginary full-paper bottom edge that precedes another page, spanning the centered paper width; it draws no rule after the final page. Speed View uses the page-paper backdrop without per-page fill, border, or bottom rule; each presented page is cropped to its printable content bounds by removing only its configured top and bottom paper margins, and adjacent printable regions have neither explicit nor implicit inter-page spacing. Speed preserves unused space within each printable region and does not repaginate, reflow, join pages, or remove other printable-region whitespace. Pointer mapping, caret and selection geometry, navigation, decorations, IME text/clipping, dual-dialogue boundaries, culling, caret reveal, visible-page status, and zoom/mode-transition anchoring use the same presented-page coordinate transform so interaction remains aligned with the complete core pages. Mode selection is transient per-window Body presentation, defaults to Page View for each new window, is not persisted to FDX, and does not change screenplay content, revision, dirty state, undo/redo history, zoom, source mapping, or PDF, Print, and plain-text output. The separate Title Page viewport always remains in Page View regardless of Body mode.

Definition-registry replacement, including Apply Template, invalidates every derived layout/control input affected by the new ordered definitions even when some or all paragraph keys are retained. Layout and cache reuse resolve the current complete definitions, Behavior/capabilities, direct overrides, and effective environment; reused output equals fresh layout. Inactive dual groups follow AC-WRITING-013.4 sequential composition and emit each retained member exactly once. Apply itself does not invoke content correction to make layout fit or a dual pattern active.

Underline and strikethrough presentation on Body and managed TitlePage Content shall derive position and thickness from the exact resolved face's OpenType metrics at the effective style size. Each metric position identifies the top of its stroke and thickness extends downward. Repeated layout/cache reuse shall retain the resulting optional span geometry with complete resolved-environment identity; decorations shall not change text advances, wrapping, line-box advancement, baseline, pagination, page fit, or interaction geometry.

The disposable Body mode persistence clarification below supersedes only AC-WRITING-002.15's statement that mode is not persisted to FDX. The exact bounded `SplitState/ScriptPanel/@DisplayMode` import and fallback, successful document activation, and detached Save/Save As projection are specified in AC-WRITING-003.13. Body mode remains outside screenplay/session semantics and does not alter geometry, zoom, dirty/undo state, Title Page Page mode, or output.

### Page visibility, zoom, and appearance

These visible-page and view criteria retain their stable `AC-WRITING-006.*` IDs here; their parent [`REQ-WRITING-LOOP-006`](desktop-workspace.md) is owned by Desktop Workspace.

- **AC-WRITING-006.5:** The visible-page indicator shall use one-based numbering and identify the rendered sheet with the greatest vertical overlap with the editor viewport. Exact overlap ties select the earlier sheet. If no sheet overlaps, the nearest vertical interval is selected, with ties selecting the earlier sheet. The total includes every rendered sheet, including an optional title page.
- **AC-WRITING-006.6:** Visible-page state is independent of caret/source position and remains current after scrolling, resizing, zoom changes, layout reflow, and caret reveal. While geometry for the same document is temporarily unavailable or stale, the last page and total remain displayed; startup and successful document replacement show unavailable until valid geometry exists. Failed Open and same-document Save do not clear the retained value. Page-status updates do not move the editor, reveal the caret, steal focus, persist view state, or change editing input ownership.
- **AC-WRITING-006.7:** The page-zoom control shall provide an accessible continuous whole-percent range from 75% to 300%, inclusive, with integer steps and no visible value text on the slider. An adjacent arrowless percentage control shows the current value and offers exactly 75%, 90%, 100%, 125%, 150%, 175%, 200%, 250%, and 300%. Both controls share one zoom value and retain it across resizes. At 100%, page presentation width corresponds to effective paper width; the page is centered when it and its exterior side margins fit and remains reachable by horizontal scrolling otherwise. Zoom changes only page presentation, not source mapping, focus/input-method ownership, fixed pagination, PDF output, document semantics, revision, dirty state, or undo history. The whole-percent zoom is disposable native view state restored on Open and updated on Save/Save As. Desktop scale conversion is platform appropriate and is not applied to shared document geometry or PDF.
- **AC-WRITING-006.10:** A supported native inward or outward pinch adjusts the same transient page zoom as the slider and presets, within the 75%–300% limits and without changing document, session, pagination, export, or editor-input state. Pinch event delivery depends on platform support. Native UI scale is independent of page zoom and is not applied twice.
- **AC-WRITING-006.11:** Appearance offers exactly System, Day Mode, Night Mode, and Midnight Mode. Its global choice persists separately from each process's applied presentation state, and the saved choice is initialized before the first rendered application content. System follows the desktop framework's resolved theme and resolves only to Day or Night; Day uses a light page, while Night and Midnight use dark pages, with Midnight and its major surfaces measurably darker than Night. Midnight is explicit only. Page text, input-method text, selected text, caret, and selection boundary maintain the specified contrast against their adjacent composited colors. Applying an appearance change through the existing typed command persists a real choice change; exact no-ops do not enqueue a preference write. Appearance changes do not change screenplay data, layout/source mappings, session revision, dirty/undo state, zoom, or exports. Desktop palette and page, toolbar, status, control, overlay, and feedback colors remain presentation concerns, distinct from screenplay data and shared document layout. Persistent preference recovery and lifecycle limits are specified in [User Settings](user-settings.md).

- **AC-WRITING-002.16 — Script View ruler:** The root Body Script View may show one pinned ruler strip below the toolbar and above the Body viewport when the global ruler preference is enabled; Title Page has no ruler, and placeholder Split/Beat Board surfaces imply no split-pane behavior. The borderless allocated strip uses the active mode-aware Script View backdrop and is 20 logical points high. Within it, a 12-point paper-colored bar is vertically centered, leaving four points of marker overflow above and below; the bar uses the active page-paper color in Page, Normal, and Speed and exactly matches the actual first presented page's left edge and width after ScrollArea composition, without independent snapping or recomputation. Ticks and labels use the effective paper width, begin at document X zero, and mark eighth-inch intervals with stronger half-inch and inch marks. All tick kinds and numeric labels are vertically centered on the bar. Tick and label painting is clipped to the intersection of the allocated strip and exact page-width bar, so endpoint paint cannot extend past the displayed page; endpoint centers stay at their canonical positions and are not inset. Whole-inch labels begin at 1, only appear when the full inch lies within the paper width, and never label zero. The unidentified heavier reference mark near 0.5 inch is not implied. Tick positions and the three marker positions use canonical page geometry: the actual first presented page rectangle and that frame's current presentation scale after ScrollArea composition, so Page, Normal, and Speed retain exactly the same horizontal geometry. Marker positions come from the focused Body paragraph's first canonical layout line: its unaligned first-line left and final paragraph left/right bounds, including direct overrides and active dual-column geometry. Markers retain their allocated-strip clipping and existing overflow and are display-only; they do not change layout, editing, hit testing, or document state.

## Constraints

- Project owns the effective DocumentPageLayout; absent direct-root PageLayout uses the complete standard default (612×792 points, 72-point top/bottom margins, Normal leading, retained 36-point header/footer margins). Missing/malformed fields and unusable combined geometry use the documented field-local/combined fallbacks; duplicate PageLayout/PageSize and unsupported DocumentLeading retain their bounded ambiguity/unsupported behavior. Existing source nodes/original bytes remain unchanged. Preservation-free output emits effective PageLayout; source-backed output synthesizes only when absent on a detached candidate. The session snapshot is derived/read-only, Apply Template does not change PageLayout, and no ad hoc mutation API/command is added.
- Core wrapping, pagination, and PDF geometry use OS-independent document points and explicit resolved-font identities/metrics; model/layout/export code does not discover host fonts or call platform font APIs. Viewport zoom and palette affect presentation only.
- Preserving source layout settings does not imply exact pagination fidelity for every FDX document.
