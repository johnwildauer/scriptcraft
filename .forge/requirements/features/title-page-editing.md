# Requirements Area: Title Page Editing

> This document specifies desired user-facing behavior for a cohesive area. Describe requirements in established-state voice, even when implementation is future work. Group related capabilities into sections and keep stable IDs so each requirement and acceptance criterion remains independently traceable. Do not add lifecycle status, implementation evidence, progress, or a backlog here.

## Area purpose

Writers edit title-page content on a dedicated surface while retaining a single screenplay document, shared history, and the same safe native save/reopen behavior as the body.

## Capability groups

### Title content and separate editing surface

These title-page criteria retain their stable `AC-WRITING-007.*` IDs and realize the title-page portion of [`REQ-WRITING-LOOP-007`](native-document-lifecycle.md), owned by Native Document Lifecycle.

- **AC-WRITING-007.3:** An imported title page retains its ordered paragraphs, blank lines, alignment, styles, and separate header/footer. Title-page editing is provided in a separate native window within the existing application and document session; opening it does not start another application process or create another document. Metadata is not inferred from paragraph positions.
- **AC-WRITING-007.5:** A new document retains the selected built-in template's complete ordered editable title-page sequence and literal placeholders, including Script Title, Written by, Name of First Writer, Based on, If Any, Address, and Phone Number; Script Title defaults to Underline and All Caps. Stageplay and Dramatists Guild Musical retain their own complete ordered title-page sequences and placeholders rather than receiving Screenplay boilerplate. Only paragraphs inside TitlePage Content are semantic/editable titles; they retain any exact nonempty type key, including arbitrary and case-distinct labels, and resolve against the same document-owned definition registry as body paragraphs. TitlePage Content paragraphs may remain type-less. Direct TitlePage/Paragraph nodes, Header/Footer data, wrappers, and every other title structure outside Content remain opaque/preserved-only regardless of Type and never synthesize definitions or receive remapping. Title paragraphs are not assigned a type merely to make them editable. Supported title content is editable while headers, footers, dynamic labels, and unrelated source material remain preserved. Each editable occurrence is treated distinctly; repeated imported identifiers remain preserved rather than being treated as unique semantic identities. Unsupported or ambiguous source mappings are rejected or left untouched rather than guessed.
- **AC-WRITING-007.6:** The main Script View shows body content only. The Title Page editor shows title-page content only in a separate ordinary native window using the same application and document session. Reopening the title editor focuses the existing title window rather than creating another one. Closing the title window closes only that view; closing the main window requests closure of the title view. An unavailable native window is not replaced by an embedded editing panel. On the Title Page surface, a focused collapsed selection resolves and paints its caret through the same geometry, focus, width, palette, clipping, and blink path as Body; range selections and unfocused surfaces do not show a caret. Title Page invisibles use the shared editor-only overlay described in AC-WRITING-007.11.
- **AC-WRITING-007.7:** Title-page zoom begins at 100% independently of body zoom. Title selection and zoom are transient, and nested TitlePage TextState does not initialize title zoom or selection. Its direct ShowInvisibles value is the narrow exception: it supplies disposable Title Page visibility only under the bounded FDX rules in AC-WRITING-003.11. For a built-in or external FDXT opened as new, imported root WindowState/TextState are disposable view-state inputs only: any supported best-effort root view restoration does not establish a saved-document baseline or semantic project layout identity, and the new document receives a fresh session and project layout identity. Appearance and sprint timer are shared. The title status surface shows page count, Timer, Appearance, zoom slider, and percentage without Body center guidance or Focus Mode. Hidden Focus Mode has no slot, adjacent empty gap, input target, or accessibility presence; Timer and Appearance remain adjacent with the ordinary item spacing. Native root view state for an ordinary opened FDX document restores body zoom, selection, and bounded Body invisibles visibility only.

Managed TitlePage Content uses the same effective Project-owned DocumentPageLayout and canonical vertical policy as Body and Print. Courier and Proportional leading are size-derived from the exact resolved face; DocumentLeading adjusts each candidate, and the base title style plus styles present on each wrapped visual line determine that line's maximum. The canonical baseline is line-box top plus the retained natural ascent and DocumentLeading adjustment; the full-height visual caret alone is translated downward by 0.15 of the line's leading for presentation, and IME text uses the same canonical baseline offset as ordinary glyphs. Selection and interaction retain the leading-sized line box. Natural descent participates in Title Page fit through each candidate final natural bottom (baseline minus signed descent); line-top advancement remains full effective leading. Glyphs are not clipped vertically to the line box, and oversized fresh-page progress remains bounded without an ink-clipping promise. Effective PageLayout persists through save/reopen; an absent source uses the complete standard default, malformed source uses documented fallbacks, and retained source/original bytes remain unchanged. Non-Content title structures remain opaque and outside layout.

Underline and strikethrough on managed TitlePage Content shall use the exact resolved face's decoration metrics and the same canonical baseline/metric-derived stroke geometry as Body. Top edges and thicknesses follow the resolved font metrics at the effective title style size; decorations do not change title wrapping, pagination, fit, or interaction geometry. Opaque title structures remain excluded.

### Apply Template and typed titles

The Elements/Apply UI observes the existing title boundary only: summaries describe definitions, not individual TitlePage Content values, and no title or non-Content source is edited by the inspector. On successful Changed Apply, an already-open Title Page surface is refreshed through the current session/layout path; it remains the same viewport and session. A type-less TitlePage Content paragraph remains type-less and otherwise unchanged, while an unmatched present typed Content key follows the exact-key remap below.

For Apply Template, a present type key on a managed TitlePage Content paragraph is retained only on an exact case-sensitive target-definition match; otherwise it maps to the target's exact Action key. A type-less Content paragraph remains type-less and otherwise unchanged. Type-looking values on direct TitlePage/Paragraph nodes, Header/Footer data, wrappers, or any other opaque non-Content title structure do not participate. Apply changes no title text, runs, order, identity, formatting, attachments, or unrelated source, and is one ordinary session edit rather than document replacement or save.

The same open, exact-key document registry serves body paragraphs and typed TitlePage Content paragraphs. A target template's title content is never copied during Apply: only the current definitions/settings and present typed keys participate, with exact matches retained and unmatched typed keys mapped to target Action; type-less Content paragraphs and all non-Content title structures remain unchanged.

### Application-modal native Elements and selector viewports

Elements and its selector are separate ordinary native immediate viewports in the same process, session, and application; they are application-modal presentation surfaces, not native OS modal dialogs or document/session windows. When either element viewport owns input, the separate Title Page viewport remains open and continues to render/repaint the current session, but it does not receive pointer editing, scrolling, keyboard navigation, dynamic shortcuts, paste, timer/editor-popup interaction, or IME commits. Underlying Title Page focus activation redirects to the topmost element viewport. This presentation ownership does not alter typed/title selections, TitlePage Content, shared history, or the Title Page viewport lifecycle. Opening Elements from Title Page captures only a transient return surface, relinquishes editor focus, and transfers keyboard ownership to the topmost native element viewport. Canceling the selector returns focus to Elements; closing the final element viewport returns focus to the captured Title Page only if that viewport remains open and supported and no migration, replacement, native-output, or other dialog lock owns input. Otherwise focus returns to Body. Closing the Title Page viewport while an element viewport remains open does not restore editor focus over that viewport; a later final element close falls back to Body.

### Formatting, history, and persistence

- **AC-WRITING-007.8:** Body and title text runs support Bold, Italic (shown as “Italics” in the UI), Underline, All Caps, and Strikeout. All Caps changes display only and maps displayed positions back to canonical source positions, including Unicode expansion. FDX accepts Strikeout, Strikethrough, and StrikeThrough inputs and emits canonical Style tokens in Bold, Italic, Underline, Strikeout, AllCaps order followed by alphabetically ordered unknown tokens; empty Style is omitted and unknown tokens/attributes are retained. Paragraph alignment supports Left, Center, Right, and Justified, with Justified represented by the FDX Full value; direct alignment overrides role defaults. A style is selected for a range when any intersecting run has it; a collapsed caret reflects its effective typing style. Alignment is selected only when all selected paragraphs share the value. Empty paragraphs retain typing style transiently without fabricating text; clearing all text removes managed text content, and entering text creates content with the active styles. Unsupported source/run structures reject the edit without mutation.
- **AC-WRITING-007.9:** Body and title edits share one undo/redo timeline. Native Save and Save As persist title text, run styles, direct alignment, and the ordered current definitions while preserving supported source structure. A new-from-template document retains all example body and supported title-page Content paragraphs as editable content, its selected template's retained document settings, and a fresh session/layout identity; it starts semantically clean with no native path or FDX storage baseline and is presented as `Untitled ` plus the selected built-in catalog display name or, for external FDXT, the source filename stem with only the final extension removed (default Screenplay therefore remains `Untitled Screenplay`). Ordinary Save routes to Save As, which publishes only an ordinary FDX destination; it cannot target or overwrite the built-in or external FDXT source. Only a TitlePage Content title may change to another exact key present in the current definitions, or to no Type; a type-less TitlePage Content paragraph remains type-less unless explicitly assigned a defined key. Such a Type-only change preserves title content, runs, identity, formatting, attachments, opaque source, and selection, and updates its retained Type projection atomically. Direct TitlePage/Paragraph nodes, Header/Footer data, wrappers, and other out-of-Content title structures remain preserved-only and are not remapped. Saving keeps the same active document session and preserves both surface selections. A failed edit, save, conflict, serialization, reread, or publication leaves prior valid live and destination state intact. Existing source structure, identities, run attributes, opaque siblings, and unrelated source remain preserved. Generic opaque children and arbitrary unknown attributes—including Bookmark—remain attached to their exact title paragraph through text/style/alignment/Type edits. Split retains them only on the original/left title paragraph; the new right paragraph receives no opaque data or unknown attributes. Join retains only the survivor's own opaque data and attributes, regardless of differences in opaque values; removed-owner data disappears with that owner. Whole-owner deletion removes its subtree and attributes without a graveyard, and undo/redo restores the exact prior source state. Opaque values are not merged or treated as managed identities; actual managed formatting conflicts and genuine external references remain guarded. Bookmark is not a navigation, editing, or semantic feature. Byte-identical XML and universal Final Draft compatibility are not promised.

The following toolbar criterion retains its stable ID in this area because it specifies title-page controls; the parent [`REQ-WRITING-LOOP-005`](desktop-workspace.md) is owned by Desktop Workspace.

- **AC-WRITING-005.10:** The independent global `toolbar` and `title_page_toolbar` settings select and order built-in items for the main and Title Page toolbars. Their default main sequence is flexible space, New, Open, Save, Save As, flexible space, Title Page, Elements, flexible space, Show/Hide, Export Text, Export PDF, flexible space, and overflow; it does not include Styles or Alignment. The default Title Page sequence is flexible space, Styles, Alignment, flexible space, Close Title Page, and overflow. Missing, explicitly empty, or all-unknown arrays use these defaults; known items retain order and repetitions, and unknown IDs are omitted from the effective sequence. The settings do not redefine item presentation or behavior. Styles offers independently selectable Bold, Italics, Underline, All Caps, and Strikethrough; Alignment offers Left, Center, Right, and Justified. Choices are accessible and keyboard-activatable and apply to the explicitly focused Body or Title Page surface. At narrow widths each formatting group moves to overflow as a whole only when the configured toolbar has its overflow item; without that item, no static overflow indicator is synthesized. Selection indicators reflect the formatting rules in AC-WRITING-007.8; selected, pressed, and hovered states remain visually distinguishable. Formatting separators are decorative, do not respond to input, and do not alter document semantics or persistence.

- **AC-WRITING-007.11:** Body and Title Page invisibles visibility are independent per-document editor view flags. The View > Document action, primary+J shortcut, and main-toolbar Show/Hide dropdown toggle the flag for the currently active editor surface, including when the Title Page window is open; toggling Body leaves Title visibility unchanged and vice versa. The Title Page flag remains with the document while its window is closed. Title marks use the same color, canonical-position, noninteractive overlay as Body and appear only in Title Page editor-purpose layouts; they do not change title content, selection/caret/pointer/IME behavior, history, dirty state, layout, or output.

Shared typed paragraph Leading/Spacing values, FDX representations, and layout resolution also apply coherently to managed TitlePage Content when those values are present. This shared representation does not add Title Page formatting menus, a Title Page inline-typing patch, a Title Page context menu, or the Body explicit-Type paragraph-format reset. Title Page Type-only assignments retain their separate preservation contract in AC-WRITING-007.9, and Apply Template retains its separate bulk policy.

### Inline run normalization

Managed TitlePage Content paragraphs use Body's canonical run normalization: exact concatenated text, empty-run removal, idempotence, and semantic merging across known Style token order and strikethrough aliases. Style output is Bold, Italic, Underline, Strikeout, AllCaps, then alphabetized unknown tokens; empty Style is omitted, and unknown tokens/attributes are preserved. Valid integer or decimal Size source spelling remains available for round-trip; absent Size inherits and invalid/unsupported source Size is not silently rewritten. AllCaps remains display-only. This supersedes AC-WRITING-007.8's former Strikethrough output spelling and preserved unknown-token order. The shared model rule does not create a Title Page formatting menu, typing patch, or Body-only clear-size action.
