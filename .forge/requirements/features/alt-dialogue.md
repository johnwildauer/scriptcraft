# Requirements Area: Alt Dialogue

> This document specifies desired user-facing behavior for alternate Dialogue variants. Requirements use established-state voice and stable identifiers; they do not record implementation status or evidence.

## Area purpose

Writers can keep multiple text-and-run versions of a Dialogue paragraph on its existing screenplay owner, switch the active wording while editing, and retain supported alternate data in the native document without treating inactive variants as screenplay paragraphs.

## Authorship, identity, and transactions

- **REQ-WRITING-LOOP-014: Owner-bound alternate Dialogue authorship.** The system shall let a writer author, navigate, and remove alternate Dialogue variants while preserving the screenplay owner's identity, ordinary editing behavior, and output boundaries.
  - **AC-WRITING-014.1 — Variant identity and Add:** The active variant is the owner’s current canonical text and runs, identified by the numeric Current value. Each inactive variant is referenced by an inline AltId and is associated with the same durable paragraph ID as its owner. Numeric IDs are unique within one owner, but existing Current values may repeat across different owners and are not renumbered merely because they repeat. Add allocates from the whole-document maximum across semantic Current/AltId values and retained raw Current, AltId, and Alt Id values, including unsupported and orphaned source; allocation uses checked maximum-plus-one, begins with IDs 1 and 2 when no values exist, and persists no counter. Add works for an owner with no Alt state or existing Alt state, retains the former active text/runs under the appropriate identity, creates a fresh empty Current, and places the caret at offset zero. Empty variants are valid and remain distinct by numeric identity. Inactive runs use the sparse projection relative to the current Dialogue definition.
  - **AC-WRITING-014.2 — Navigation, deletion, and history:** Previous selects the greatest lower numeric ID and wraps to the greatest; Next selects the least greater numeric ID and wraps to the least. The displayed one-based ordinal and total are calculated from the numerically sorted per-owner variant IDs, not from the ID values or inline order. Previous, Next, and Delete leave a collapsed caret at the newly active text end. Delete promotes the greatest-lower inactive ID, or otherwise the least-greater inactive ID; it is unavailable when only one variant exists. Deleting the last inactive variant removes the owner’s inline Alts state and restores Add eligibility for the still-focused eligible owner before Save, reopen, focus change, or another edit. Each successful Add, Previous, Next, or Delete is one atomic undoable/redoable operation; an unsuccessful or ineligible operation does not partially change the owner. Inactive variants do not enter Body text offsets, screenplay layout, selection, pagination, or output.

## Editor presentation and interaction

- **AC-WRITING-014.3 — Owner eligibility and overlay:** Active controls appear only for a collapsed caret on an exact Dialogue-capability Body owner with supported inline Alt source. Unsupported inline Alts remain noneditable and do not receive controls. On the right, Add precedes Delete; Delete is shown only for multiple variants. On the left, multiple variants show Previous, the active ordinal/total, and Next in that order. Controls center vertically on the canonical first line box; right controls use the paragraph-right bound, and the left group/count uses the unaligned first-line left with an 18-point indent gap. Inactive paragraphs with multiple variants show only the total-count box, including Current. Rest controls use 0.70 opacity over subdued page text and one centralized subdued blue on hover; icons are 14 points at rest and 15 on hover, the count numeral is 8 points at rest and 9 on hover, the count box is 18 points square, and the ordinal is 10 points. Sizes and geometry scale with zoom. The active controls and inactive count box are never shown together.
  - **AC-WRITING-014.4 — Pointer isolation and output scope:** Selecting an inactive count box focuses that Body owner and places a collapsed caret at its text end; the action does not change an Alt variant. Alt hit testing takes precedence over ScriptNote markers and ordinary pointer placement. Each eligible completed primary activation dispatches exactly one existing Alt action regardless of ordinary, double, or triple click classification, with current availability rechecked at dispatch. Secondary activation and drag interactions on Alt geometry are inert; behavior outside the Alt branch, including non-Alt selection, remains unchanged. The overlay is limited to Body Editor-purpose presentation and is clipped to the page and editor; it does not change canonical layout. Only Current enters ordinary screenplay output. Inactive variants are omitted from pagination, PDF, native print, plain text, and Fountain output.

## FDX and owner lifecycle

- **AC-WRITING-014.5 — Supported source projection and safe fallback:** Supported direct Body Dialogue and supported dual-member Dialogue Alts use the inline Current/AltId projection and entries resolved from the first direct root AltCollection by both numeric Alt ID and the owner’s exact durable paragraph ID. A complete, supported projection is semantic; malformed, ambiguous, unsupported, foreign-namespace, unresolved, or orphaned data remains safely opaque and does not become an editable variant. New or changed AltCollection Paragraphs use the fixed alternate-paragraph defaults (Alignment Left, FirstIndent 0.00, Leading Regular, LeftIndent 2.50, OutlineLevel 1, RightIndent -1.11, SpaceBefore 0, Spacing 1, StartsNewPage No) and the owner's durable paragraph ID. Alt Text output starts with complete Dialogue run defaults and overlays actual sparse overrides, including Size, Bold, Font differences, unknown attributes, and run ordering. Alternate paragraph defaults never become screenplay direct formatting. AltCollection paragraph copies are not foreign paragraph identities. Output preserves unsupported source, unrelated entries, and orphaned AltCollection copies; only explicit variant operations on a surviving owner remove that owner’s managed inactive entries.
  - **AC-WRITING-014.6 — Type, structure, and native-document safety:** Supported Alt state remains attached to its owner through ordinary text/run edits and Type changes. It is editable and presented only while the owner has exact Dialogue capability; dormant state produces no overlay on a non-Dialogue owner and becomes eligible again if that capability is restored. Split retains state on the original/left owner and does not copy it to the new right owner. Join and whole-owner removal discard semantic state with the removed owner but do not turn retained AltCollection copies into managed deletions; such copies remain opaque orphans. Native save and rebase preserve the existing destination-protection, detached-candidate, semantic/source/identity reread, and failure-safety requirements. Supported Alt data does not establish universal Final Draft compatibility.

  - **AC-WRITING-014.7 — ScriptNote replacement and relocation:** Every Add, Previous, Next, and Delete replaces the active owner’s current-text interval in flattened Body coordinates for ordinary ScriptNote range maintenance, then applies the Alt-specific final relocation rule. Consider every exact Dialogue-capability paragraph with semantic or retained inline Alt presence, as well as the action target. If either note endpoint maps to an eligible paragraph, collapse both endpoints to that paragraph’s paragraph-start caret; if both endpoints map to distinct eligible paragraphs, select the earlier/start-side paragraph. Paragraph start and text end belong to the paragraph under existing coordinate mapping; an empty paragraph uses its sole/front caret. A range crossing an eligible paragraph without either endpoint mapping into one receives ordinary replacement maintenance only. Inactive variants do not enter Body coordinates. Relocation retains distinct notes, identities, content, order, and timestamps even when ranges collapse to the same point; Undo/Redo restores the note-containing snapshots.
