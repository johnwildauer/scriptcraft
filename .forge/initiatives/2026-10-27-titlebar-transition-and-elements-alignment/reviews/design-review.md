## Findings

### Blockers

- **None.** The intended work is identifiable, all four work orders are related to the approved outcome, the dependency chain is executable, and no explicit project-policy gate makes comparison impossible. Human design approval remains pending and is correctly a later execution gate rather than a reason to mark this design blocked ([`03-design-review.md`](../../../process/03-design-review.md:32-45), [`project-manifest.md`](../../../project-manifest.md:88-95)).

### Warnings

- **TTA-DESIGN-W-001 — Initiative phase and execution-log metadata disagree.** **Severity:** warning. **Evidence:** The plan records `Phase: plan` and a `draft -> plan` transition ([`titlebar-transition-and-elements-alignment-v1.md`](../titlebar-transition-and-elements-alignment-v1.md:5,23)), while the execution log still records `Current phase: draft` and no review or approval event ([`execution-log.md`](../execution-log.md:8-17)). **Recommendation:** Reconcile both records to `review` and record this review result before any execution dispatch. **Required next state:** `review`; do not advance to `execute` from this artifact.

- **TTA-DESIGN-W-002 — Seam and transition-metric acceptance is directionally clear but not numerically complete.** **Severity:** warning. **Evidence:** [`WO-002`](../work-orders/WO-002-unified-titlebar-toolbar-surface-and-transition-geometry.md:22-31,69-74) requires a seam-free surface, bounded heights, metric measurements, and the strongest supported invariant, but does not define a seam-pixel tolerance, rectangle tolerance, metric delta/tolerance, sample schedule, or exact pass/fail invariant. The plan calls for metric tolerances without selecting them ([`titlebar-transition-and-elements-alignment-v1.md`](../titlebar-transition-and-elements-alignment-v1.md:44-45,119-127)). **Recommendation:** Before implementation dispatch, record measurable thresholds and sampling rules in WO-002/WO-004, with a separate result for unsupported OS-owned animation. **Required next state:** `review`; this is non-blocking under the design-review policy.

- **TTA-DESIGN-W-003 — Native maximize/restore behavior is bounded but cannot be proven from headless API semantics.** **Severity:** warning. **Evidence:** Installed `ViewportInfo` exposes optional `maximized`, `inner_rect`, and `outer_rect` ([`input.rs`](../../../../.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/egui-0.29.1/src/data/input.rs:214-229)); `ViewportCommand::Maximized(bool)` is a request ([`viewport.rs`](../../../../.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/egui-0.29.1/src/viewport.rs:1003-1008)); and macOS runtime maximized queries are avoided after initialization in [`update_viewport_info()`](../../../../.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/egui-winit-0.29.1/src/lib.rs:987-993). [`WO-001`](../work-orders/WO-001-viewport-state-direction-and-native-restore-contract.md:18-31,47-61) correctly models unknown state and native-bounded restore. **Recommendation:** Require OS/backend identification and explicit pre/post state and rectangle records when smoke is available; otherwise report stale/unavailable state rather than reversing the inverse helper or claiming exact restoration. **Required next state:** `review`; retain the limitation through validation.

- **TTA-DESIGN-W-004 — Seam-removal strategy is aligned, but ownership and visual proof must remain explicit.** **Severity:** warning. **Evidence:** Current source has separate [`title_strip_frame()`](../../../../apps/scriptcraft/src/main.rs:1663), [`toolbar_frame()`](../../../../apps/scriptcraft/src/main.rs:1659), and adjacent top panels in [`update()`](../../../../apps/scriptcraft/src/main.rs:1697), while [`WO-002`](../work-orders/WO-002-unified-titlebar-toolbar-surface-and-transition-geometry.md:22-24,56-61) permits one shared surface or the smallest frame adjustment and retains separate title response and toolbar allocation. **Recommendation:** Have the geometry ledger identify the authoritative fill/stroke/margin owner, title hit rectangle, toolbar content/clip rectangles, and seam criterion; preserve hit coverage and allocation. **Required next state:** `review`; carry the ledger into WO-004.

- **TTA-DESIGN-W-005 — Durable-document classifications require evidence-driven reconciliation.** **Severity:** warning. **Evidence:** [`WO-001`](../work-orders/WO-001-viewport-state-direction-and-native-restore-contract.md:76-82) uses `verify unchanged`; [`WO-002`](../work-orders/WO-002-unified-titlebar-toolbar-surface-and-transition-geometry.md:76-82) makes blueprint updating conditional; [`WO-003`](../work-orders/WO-003-elements-closed-selected-text-centering.md:72-78) authorizes a desktop-blueprint update; and [`WO-004`](../work-orders/WO-004-cross-surface-native-validation-and-document-reconciliation.md:78-84) defaults both domains to `verify unchanged`. These distinctions are defensible because viewport/width requirements already exist while closed-only centering is a new durable presentation distinction. **Recommendation:** Preserve an explicit final `update`, `verify unchanged`, or `not applicable` result with document evidence per work order; do not create documentation deltas merely to satisfy the classification. **Required next state:** `review`; final classification remains a validation/closeout obligation.

- **TTA-DESIGN-W-006 — WO-004 is a real bounded implementation/reconciliation boundary, not an administrative shortcut.** **Severity:** warning. **Evidence:** [`WO-004`](../work-orders/WO-004-cross-surface-native-validation-and-document-reconciliation.md:18-31,57-69) requires prior-diff comparison, configured checks, bounded native smoke, a source change only for a real scoped defect, a regression with any source change, evidence-backed durable updates, and a separate fresh validator. It expressly excludes administrative-only edits and approval/validation substitution. Its dependency is correctly last ([`WO-004`](../work-orders/WO-004-cross-surface-native-validation-and-document-reconciliation.md:86-90), [`titlebar-transition-and-elements-alignment-v1.md`](../titlebar-transition-and-elements-alignment-v1.md:129-140)). **Recommendation:** Dispatch only after WO-001 through WO-003 are independently validated; any source delta needs a concrete defect, regression, comparable diff, and fresh WO-004 validation. If no defect exists, no source change is correct. **Required next state:** `review`; execution still requires human approval and normal gates.

### Notes

- **TTA-DESIGN-N-001 — Scope and dependency order align.** WO-001 establishes viewport state direction; WO-002 consumes it for chrome geometry and transition measurements; WO-003 consumes the settled toolbar geometry; WO-004 integrates and reconciles evidence. This matches the manifest's sequential default and fresh validation policy ([`project-manifest.md`](../../../project-manifest.md:50-55,97-102)).
- **TTA-DESIGN-N-002 — The current Elements baseline is 128 points.** Current source records [`TOOLBAR_ELEMENTS_WIDTH`](../../../../apps/scriptcraft/src/main.rs:26) as `128.0`, and the plan plus [`WO-003`](../work-orders/WO-003-elements-closed-selected-text-centering.md:18-29) explicitly preserve it. The parent’s historical approximate 92-point target is not silently restored.
- **TTA-DESIGN-N-003 — Current evidence supports investigation, not a preselected inversion or animation promise.** [`title_strip_viewport_command()`](../../../../apps/scriptcraft/src/main.rs:1671-1673) maps known false/true state to maximize/unmaximize and unknown to no command. Width-derived page/font scale is observable through [`presentation_geometry()`](../../../../apps/scriptcraft/src/main.rs:1509-1517) and [`renderer_font()`](../../../../apps/scriptcraft/src/main.rs:1539-1547), so the plan properly separates semantic layout stability from paint-metric stability.
- **TTA-DESIGN-N-004 — Parent evidence is historical.** The closed parent review and validations establish prior boundaries and native-smoke limitations, but current source and fresh API/native evidence remain authoritative for this follow-up.

Owner: WO-002 implementer and validator. Blocking: no for design alignment; required before claiming measurable acceptance.

Owner: WO-001/WO-002 implementer and validator. Blocking: no under current project policy; unavailable evidence must remain a warning.
