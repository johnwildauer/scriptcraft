## Findings

### Blockers

- **V3-DESIGN-B-001 — V3-WO-002 does not yet define a complete source-level boundary for its toolbar metric claim.** **Severity:** blocker. **Evidence:** The work order requires toolbar icon/text and page metrics to remain stable ([`V3-WO-002`](../work-orders/V3-WO-002-stable-titlebar-transition-metrics.md:16-29,69-74)), but its implementation path names only app-owned page/presentation metrics. In current source, [`live_document_surface()`](../../../../apps/scriptcraft/src/main.rs:1411) consumes [`presentation_metrics_with_policy()`](../../../../apps/scriptcraft/src/main.rs:1900), while toolbar icon/text are painted through ordinary egui font/layout paths in [`toolbar_action_button()`](../../../../apps/scriptcraft/src/main.rs:912). The work order simultaneously prohibits global egui scale, which is correct, but does not state how toolbar metrics are stabilized without changing global layout/input/accessibility semantics. **Recommendation:** Revise V3-WO-002 before execution to choose and bound one technically supported app-owned strategy: either narrow the acceptance claim to page/app-owned renderer metrics, or specify a toolbar-local metric/render boundary with exact stable fields, state ownership, and preservation tests. Define whether “stable” means logical egui points, app paint metrics, native physical bounds, or a measurable tolerance; do not imply that page-only metrics stabilize ordinary egui toolbar rasterization. **Required next state:** `plan` until the work order is clarified; no implementation dispatch.

### Warnings

- **V3-DESIGN-W-001 — V3-WO-001 has the required correction and refusal boundary.** **Severity:** warning. **Evidence:** [`V3-WO-001`](../work-orders/V3-WO-001-toolbar-bottom-black-bar-removal.md:16-34,56-74) traces panel/frame/row/padding/central/clip/physical rounding, permits a direct correction only after app ownership is proved, forbids blind paint-over, and requires `blocked` rather than pass when the result is proved external or native evidence is unavailable. The current source ledger and shared frame are logical ownership evidence, not native pixel proof ([`chrome_surface_ledger()`](../../../../apps/scriptcraft/src/main.rs:123), [`chrome_frame()`](../../../../apps/scriptcraft/src/main.rs:2061)). **Recommendation:** Retain this boundary and require the validator to record the exact owner category and corrected source boundary; deterministic continuity alone must not be called black-bar removal. **Required next state:** `review` after recording this clarification; non-blocking.

- **V3-DESIGN-W-002 — The app-owned transition fallback is directionally safe but its release predicate is underspecified.** **Severity:** warning. **Evidence:** [`V3-WO-002`](../work-orders/V3-WO-002-stable-titlebar-transition-metrics.md:26-34,56-61) correctly rejects `has_requested_resize`, desktop/work-area polling, native animation control, global zoom, and exact native history. It proposes request/settling observations, but does not specify the precise bounded stable-frame/metric predicate, repaint behavior, maximum hold, or behavior when optional maximized state is stale/unknown. Installed API evidence supports snapshots and request commands, not a transition timeline ([`ViewportInfo`](../../../initiatives/2026-10-27-titlebar-transition-and-elements-alignment/titlebar-transition-and-elements-alignment-v2.md:172-178) and [`ViewportCommand::Maximized(bool)`](../../../initiatives/2026-10-27-titlebar-transition-and-elements-alignment/titlebar-transition-and-elements-alignment-v2.md:174-176)). **Recommendation:** Define a deterministic finite state machine using only app-owned request/frame observations and viewport/metric snapshots, with an explicit bounded release/recovery path and no claim of native animation control. **Required next state:** `review`; non-blocking, but clarify before implementation.

- **V3-DESIGN-W-003 — Mandatory visual gates are explicit and enforceable, but their evidence owner is not named.** **Severity:** warning. **Evidence:** The v3 plan and both work orders require a rebuilt real-app check, reject unavailable-native pass, and specify the exact black-bar and maximize/restore observations ([`titlebar-transition-and-elements-alignment-v3.md`](../titlebar-transition-and-elements-alignment-v3.md:81-87), [`V3-WO-001`](../work-orders/V3-WO-001-toolbar-bottom-black-bar-removal.md:69-74), [`V3-WO-002`](../work-orders/V3-WO-002-stable-titlebar-transition-metrics.md:69-74)). However, no named user/evidence record format or orchestrator responsibility is stated. **Recommendation:** Require each validation artifact to include the user visual result, date/session, build/rebuild identity, normal/maximized/restored observations, and pass/fail or blocked disposition; make absence of that record non-complete. **Required next state:** `review`; non-blocking.

- **V3-DESIGN-W-004 — Sequential dependency order is correct.** **Severity:** warning. **Evidence:** The plan orders [`V3-WO-001`](../work-orders/V3-WO-001-toolbar-bottom-black-bar-removal.md:76-80) before [`V3-WO-002`](../work-orders/V3-WO-002-stable-titlebar-transition-metrics.md:76-80), preventing changed chrome geometry from confounding metric work. This matches the manifest's sequential default and fresh implementer/validator requirements ([`project-manifest.md`](../../../project-manifest.md:97-102), [`00-overview.md`](../../../process/00-overview.md:98-114)). **Recommendation:** Preserve strict per-WO implementation and validation separation; do not parallelize or let WO-002 consume unvalidated geometry changes. **Required next state:** `review`; non-blocking confirmation.

- **V3-DESIGN-W-005 — Durable-document classifications are defensible but conditional.** **Severity:** warning. **Evidence:** Both work orders classify requirements as `verify unchanged` and blueprint impact as `verify unchanged` by default ([`V3-WO-001`](../work-orders/V3-WO-001-toolbar-bottom-black-bar-removal.md:82-88), [`V3-WO-002`](../work-orders/V3-WO-002-stable-titlebar-transition-metrics.md:82-88)). This is reasonable because the existing requirements and blueprints already bound toolbar geometry, native request semantics, and presentation-above-semantic-layout ([`screenplay-writing-loop.md`](../../../requirements/features/screenplay-writing-loop.md:115), [`scriptcraft-desktop.md`](../../../blueprints/containers/scriptcraft-desktop.md:105)). - **V3-DESIGN-W-006 — Branch and approval gates remain pending.** **Severity:** warning. **Evidence:** The v3 plan makes no current branch/HEAD claim and explicitly leaves branch confirmation and human approval pending ([`titlebar-transition-and-elements-alignment-v3.md`](../titlebar-transition-and-elements-alignment-v3.md:28-31,74-79)).
