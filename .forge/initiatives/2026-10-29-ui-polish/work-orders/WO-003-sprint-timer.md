## Implementation plan and acceptance contract

### Integration, ownership and lifetime

1. Add one actual stopwatch-icon clickable status item with accessible name **Sprint Timer**, stable identity, pointer and keyboard activation and a readable fallback if the chosen icon is unavailable. Use the WO-002 shared seam once; logical order is **Sprint Timer → Focus Mode → Appearance → zoom**, left to right and in overflow. WO-004 supplies Focus Mode later; do not invent a visible placeholder. At narrow widths the timer remains reachable through WO-002's disclosure with the same action, identity and ordering; no duplicate action, clipped hit target, hidden input or footer growth. Support Tab/Shift-Tab, Enter/Space and Escape using normal intentional focus transfer, not editor focus theft.
2. Keep a single transient model owned by the desktop window, not popup rendering or a project. Separate UI open/close state from timer state and update the model in the app lifecycle even if the popup or overflow is not painted; when the window receives no updates, reconcile elapsed time on its next update. Popup dismissal by icon, outside click, Escape, another popup or a move into/out of overflow is handled consistently. Define a logical open/close transition so frame recomposition, parent overflow closure and repeated close callbacks do not reset twice or destroy an active timer. An actual user dismissal applies the close rules below; opening a child from overflow must not inadvertently dismiss/reset it.
3. Present a top-level two-choice selector **Countdown** and **Stopwatch**; the numeric minutes field is configuration, not a third mode. Only one mode and one timer state can exist. Switching is enabled only when idle, and choosing a different mode resets the selected mode to its idle defaults. Disable switching for running or paused timers. A completed countdown is not active: Reset or closing restores countdown defaults, after which mode switching is available; do not silently discard the completion message through a mode change.

### Countdown

4. Idle defaults to the numeric-only minutes field `25`, enabled **Start Sprint** and visible disabled **End Sprint**. Permit empty while editing and filter nondigits on typing and paste. Use a bounded input strategy that detects oversized numeric input rather than silently truncating it into a valid duration. On Start or Enter in the field, accept only representable whole minutes from 1 through 1440 inclusive. Empty, zero, oversized, nonrepresentable and any invalid submitted value leave timer state and entered text unchanged, do not start or notify, and produce bounded inline accessible feedback. Document and test the visible filtering behavior, including signs and decimal separators; validate the resulting field text, never silently clamp an out-of-range value.
5. On valid Start/Enter, capture both the parsed number and the exact accepted input text, including leading zeroes, and establish a checked monotonic deadline using an injected clock. Display remaining time as ceiling whole seconds in `mm:ss`, with unbounded-width minutes as needed. Replace Start with **Pause**. Pause first reconciles the current deadline, then freezes the remaining duration; **Resume** establishes a new checked deadline from the frozen duration. Time is computed from elapsed monotonic time, never decremented once per frame. Invalid/repeated Start, Enter, Pause, Resume or End actions outside their appropriate state are no-ops. A deadline reached before a competing Pause/End is reconciled first, so completion is not lost or doubled.
6. **End Sprint** before completion, whether running or paused, cancels that sprint without notification and returns to countdown idle with the exact captured pre-start input text restored and Start enabled/End disabled. This value remains visible until another start or an actual idle close. Closing while running or paused preserves state and timekeeping; closing idle resets to `25`. Reset and closing completed also reset immediately to countdown idle `25`. App exit/relaunch persistence is not provided.
7. At or past the deadline transition exactly once to completed, show **Great Work! You completed a 1 Minute Sprint** for numeric value 1 or **Great Work! You completed a N Minutes Sprint** for any other captured value, and request at most one best-effort OS notification. At completion, put enabled **Reset** in the former Start/Pause position and keep **End Sprint** visible but disabled. Repaints, popup reopen/close, Reset and stale asynchronous callbacks must not emit another notification for that completion; starting a new sprint creates a distinct generation.

### Stopwatch and scheduling

8. Stopwatch idle displays `00:00:00`, enabled **Start** and visible disabled **End**. Start records a monotonic origin; Pause accumulates elapsed duration, Resume records a fresh origin, and End from running or paused clears to zeros and idle. Display elapsed whole seconds as `hh:mm:ss`, with hours at least two digits and greater than 99 without wrapping. Use checked or saturating duration/format arithmetic and defined bounded behavior at representational limits; never panic or wrap. Repeated inappropriate actions are no-ops. Closing while running or paused preserves the state; closing idle resets defaults.
9. Reconcile time before actions and once per app update regardless of popup visibility. While running, request bounded repaints sufficient for the next displayed second and countdown deadline even with the popup closed; avoid a zero-delay busy loop, and stop timer-owned periodic repaint when idle, paused or completed. Account for egui's next-frame delay and unrelated repaint sources in tests; scheduling is best effort, not an exact real-time guarantee. On next execution after an overdue deadline, complete once. A suspended UI process cannot guarantee an on-time OS notification, and monotonic clock behavior during system sleep is platform-dependent; do not promise sleep-inclusive elapsed time without native evidence. No verified OS scheduling service is assumed.

### Notification boundary and failure handling

10. Use a small injectable, non-reentrant notification sink and a monotonic clock seam for deterministic tests. Commit the completed state and a per-generation attempted marker before invoking or scheduling any external notification, so synchronous failure, asynchronous callbacks and re-entrant updates cannot duplicate requests. Keep callbacks generation-scoped, marshal results safely to the UI, and ignore stale results after reset/new sprint; do not block the UI on permission or delivery. Reconcile time before handling each user action so simultaneous expiry and input have one deterministic outcome.
11. Investigate supported target-specific notification options using locally available sources and offline dependency resolution before selecting an adapter. Preserve the app's unsafe-code and strict lint policies; do not introduce an unsafe bridge or require network access as an implicit prerequisite. Check authorization status and request permission at an appropriate user-initiated point only when needed, handling not-determined, granted, denied, restricted/unavailable and request errors without repeated prompts or re-entrant starts. Use only the captured duration and generic completion text; never include screenplay content, paths or sensitive diagnostics.
12. Submit one local OS notification request on completion when supported and authorized. A successful submission is not proof of display or delivery; account for foreground presentation, OS settings and focus/Do Not Disturb. Denied permission, unsupported platform, missing identity, submission failure or unavailable adapter must not prevent completion or Reset: retain the in-app completion message and give bounded, accessible, non-sensitive feedback explaining notification unavailability without claiming delivery. If a safe supported implementation or offline dependency cannot be established, record the precise blocker and route through design/policy; do not silently ship a fake successful notification or bypass required validation. An optional verified OS scheduling service is not authorized merely by this proposal.
13. Timer interaction and passive time passage must not change project bytes, revision, dirty/undo/redo state, source selection, layout/page mappings, page zoom, fixed PDF/plain-text output or native save state. Ordinary intentional focus transfer to the timer must not dispatch its text or Enter to the editor; returning to the editor follows normal focus behavior.
