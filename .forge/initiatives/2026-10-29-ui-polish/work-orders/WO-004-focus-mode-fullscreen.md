## Implementation plan and acceptance contract

1. Register one real, accessible **Focus Mode** action with stable identity through the delivered WO-002 seam after WO-003. Logical order is **Sprint Timer → Focus Mode → Appearance → zoom**, including suffix overflow. Use an appropriate fullscreen icon with readable text fallback if unavailable; accessible name and state must communicate the next action and reported/pending/unavailable state without relying on icon shape or color. Pointer, Tab/Shift-Tab and Enter/Space activate once; overflow activation has the same behavior, no duplicate enabled representation or clipped hit target. Preserve WO-002's minimum usable width and bounded below-minimum fallback, error/Diagnostics/status access and stable footer.
2. At the app/window boundary obtain this viewport's actual reported optional fullscreen value on each update, including when the item is in overflow. Do not maintain a separate optimistic boolean as the source of truth. When known and not gated, activate with exactly one `ViewportCommand::Fullscreen(!reported)` for that same viewport. Do not send a maximize, decoration, move, resize or monitor command as part of Focus Mode. OS-originated entry/exit, including green button and Escape **where the OS delivers it**, updates the next action and accessible state from subsequent observations without an automatic compensating command. Escape is not assumed to exit fullscreen on all macOS configurations.
3. Model each in-flight request explicitly, with target, generation and bounded reconciliation/repaint scheduling. Commit the pending marker before dispatch so reentrant activations cannot issue duplicates. Disable or otherwise consume repeated presses while pending; do not queue an implicit inverse, count clicks as toggles, or automatically retry. Unknown observations never imply `false`: disable/no-op with accessible, bounded explanation. A return to known state is reconciled without fabricating an acknowledgement. Make transitions idempotent under multiple frames, delayed updates, UI relocation and reentrant callbacks.
4. Define a bounded timeout and recovery policy using an injectable monotonic clock; on an unobserved, ignored, contradicted or otherwise unresolved request, clear/expire the pending operation into a truthful unavailable/uncertain state with bounded accessible feedback, and stop periodic polling. Do not blindly resend or reverse a stale command. Allow a subsequent explicit user action only when a fresh, trustworthy observation and the selected safety gate permit it; reconcile late OS observations without replaying old intent. Distinguish a target *reported* by the backend from proven native transition completion. If a safe completion signal is unavailable, any debounce/settling guard is only a duplicate-suppression heuristic, not proof the OS finished; document its limits, handle OS reversal/late failure, and surface a design/implementation blocker if the required native behavior or safe reentry cannot be established. Do not leave the control pending forever, start a busy repaint loop, or claim success merely because a command was sent.
5. Let the native backend/window manager own prior window settings and fullscreen restoration. Preserve existing native decorations and the approved title-strip behavior, if present, without issuing synthetic maximize or geometry commands. Exercise fullscreen entered from normal and maximized windows, separately observing size, position and monitor before/after, monitor migration and native titlebar controls. Do not assert universal exact restoration or reapply captured geometry, especially after monitor changes. If a title-strip maximize action exists at implementation time, ensure it cannot interfere during an unresolved fullscreen transition and its established known/unknown maximized-state contract remains intact; do not trust stale macOS maximized state as fresh. If it does not exist, preserve the current native titlebar and report the requirement discrepancy, rather than silently claiming a test covered a nonexistent action.
6. Fullscreen is window presentation only. Preserve the WO-001 selected page zoom and pinch/slider/preset synchronization through entry, exit, resize and monitor scale changes; invalidate/rebuild visible-page geometry when necessary without stealing focus or scrolling on status projection. Preserve WO-002 appearance, WO-003 timer progression, toolbar/editor input, IME and hit testing. It must not alter project bytes, semantic roles, fixed pagination/source ranges, revision, dirty/undo/redo, native path or PDF/plain-text output. Distinguish intentional focus transfer from passive state changes.
7. Before claiming target capability, verify on the target app/platform that the framework route behaves like the native green button, including transition/Space/menu-bar behavior and exit; source inspection and rendered mocks cannot establish this. If ignored, unsupported, materially non-equivalent, or unsafe to reconcile, use only the bounded disabled/no-op/explanation fallback and record the exact evidence and blocker for the orchestrator/design/policy decision. Do not silently ship a maximization substitute, add an unsafe bridge, or weaken mandatory acceptance/validation. A safe alternative requires separate authorization.
