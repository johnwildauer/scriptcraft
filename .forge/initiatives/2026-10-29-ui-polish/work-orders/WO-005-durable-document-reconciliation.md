## Existing applicable requirements — verbatim

The following is a **pre-execution snapshot** of the requirements as they stood before this WO's edits. It is retained for traceability, not as the current requirements text. WO-001–004 now have separate passing validations; this execution replaces the conflicting scale clauses and adds only behavior supported by their evidence. The prior 006.1 restriction against unrequested actions remains; the authorized controls are explicitly named without permitting unrelated icons/actions.

> **AC-WRITING-001.2:** Given an element, the system shall preserve its explicit role and canonical UTF-8 text independently of capitalization, spaces, tabs, indentation, or font appearance.
>
> **AC-WRITING-001.3:** Given a valid selection, the system shall support insertion, deletion, split, join, role change, undo, and redo while preserving valid text boundaries and element order.
>
> **AC-WRITING-002.1:** Given the same project and fixed page profile, the system shall derive stable page structure and source mappings independent of window zoom.
>
> **AC-WRITING-002.4:** Given a document position and rendered geometry, the system shall support a safe caret/hit-test round trip at valid text boundaries.
>
> **AC-WRITING-003.1:** Given a valid project, the system shall serialize a versioned native representation containing semantic content, stable IDs, metadata, and page-profile inputs, while excluding transient caret/layout/undo state from required content.
>
> **AC-WRITING-004.1:** Given a project, PDF export shall use fixed print layout rather than transient viewport layout.
>
> **AC-WRITING-004.2:** Given a PDF or plain-text export, the system shall not silently replace the native source of truth or falsely mark the native project clean.
>
> **AC-WRITING-005.1:** Given the desktop app is running, the toolbar shall present the typed default Item order New, Open, Save, Save As, Flexible Space, Elements, Flexible Space, and Export PDF.
>
> **AC-WRITING-005.2:** Given an actionable toolbar Item is activated, the desktop shall route it through existing application/session adapters and preserve command safety, status, persistence, and fixed-layout PDF behavior.
>
> **AC-WRITING-005.3:** Action Items shall use an icon-first, borderless icon control with a small explicit padding region as the hover/click surface. The centered text label beneath it remains outside that response, retains its normal text color, remains available for accessibility use, and does not add a redundant visible-label tooltip.
>
> **AC-WRITING-005.4:** Given the current caret/focus is within a screenplay element, the Elements Item shall display that element's explicit role using the seven supported labels Scene Heading, Action, Character, Dialogue, Parenthetical, Transition, and Note; choosing a label shall apply the role through the existing transactional session operation and preserve the document on rejection.
>
> **AC-WRITING-005.5:** Given a toolbar width, Space shall consume one deterministic 72-point width, rendered normal Items shall consume their complete group width including label text measured at runtime with the active egui style/font, and Flexible Space Items shall divide the remaining width equally after the shared 4-point horizontal row-padding and 4-point inter-item-gap budget, and a narrow toolbar shall retain the leftmost fitting Items while exposing non-spacing Items through a far-right `>>` text menu. Action entries and Elements role choices in that menu shall remain executable without persisting toolbar layout state; a fully fitting composition shall keep its rightmost Item, including its label, inside the actual clipped toolbar content right edge after panel, frame, and viewport insets are applied. Items with an approved typed width override, including the Elements control, shall use that same resolved width for allocation and rendering without changing the shared padding, gap, flexible-space, overflow, or clipped-edge budget.
>
> **AC-WRITING-005.6:** Given the desktop app is running, a dedicated compact title strip shall display centered bold `ScriptCraft` placeholder text above the toolbar. A double-click shall request maximize/unmaximize only when the viewport's maximized state is known; unavailable or ignored state shall use a bounded no-op/native fallback rather than an unsafe or exact-restoration claim that the platform cannot support.
>
> **AC-WRITING-005.7:** Toolbar action controls and the Elements control/label surface shall request the standard arrow cursor, while the existing whole-document editing response shall request the text/I-beam cursor. Decorative labels and painted page rectangles shall not create competing cursor owners.
>
> **AC-WRITING-006.1:** The desktop status presentation shall support distinct noninteractive-text, clickable-text, and clickable-icon Item capabilities. Interactive Items shall have explicit accessible names and support keyboard focus and activation; noninteractive text shall not own focus, activation, pointer response, or cursor behavior. The status bar shall not introduce unrequested actions or icon assignments.
>
> **AC-WRITING-006.2:** The status bar shall report the live editing session's clean/unsaved state and current operation status, without displaying a cumulative frame count or project path. A clean in-memory project without a named path shall not be described as previously saved; it may be labeled `Clean` without asserting that it has been saved.
>
> **AC-WRITING-006.3:** Operation errors shall remain visibly identifiable, and bounded diagnostics shall remain reachable without exposing screenplay text, source text, or serialized project contents. Diagnostics is retained for the current release scope, with its removal deferred until pre-release.
>
> **AC-WRITING-006.4:** At narrow widths, a deterministic bounded fallback shall retain access to visible-page state, clean/unsaved state, operation/error status, diagnostics, and zoom controls. Status text shall clip horizontally as single-line content rather than wrap or grow the footer.
>
> **AC-WRITING-006.5:** Given the actual rendered sheet rectangles and actual editor scroll clip, the visible-page Item shall use one-based numbering and select the sheet with the greatest vertical overlap; exact overlap ties shall select the earlier rendered sheet. If no sheet overlaps, it shall select the nearest vertical interval, with exact-distance ties selecting the earlier sheet. The total shall include every rendered sheet, including an optional title page.
>
> **AC-WRITING-006.6:** Visible-page state shall be independent of caret/source position and remain current after scrolling, resize, presentation-scale changes, layout reflow, and conditional caret reveal. If layout or geometry is invalid, missing, or stale, the status bar shall show an explicit unavailable state until fresh geometry is published. Page-status updates shall not scroll the editor, reveal the caret, steal focus, or change editor input ownership.
>
> **AC-WRITING-006.7:** The desktop status bar shall provide one accessible, apparently continuous whole-percent page zoom slider from 75% through 300% and an adjacent menu containing exactly 75%, 90%, 100%, 125%, 150%, 175%, 200%, 250%, and 300%. Both controls shall share one transient per-window value and show every intermediate integer accurately. 100% shall retain the existing responsive window-fit page baseline, with the selected percentage retained across resizes; zoom shall scale only page presentation and allow horizontal as well as vertical navigation without changing editor source mapping or focus/IME ownership. Zoom shall not persist or alter native project data, session revision, saved/dirty or undo state, fixed pagination/source ranges, or fixed-layout PDF output, and shall not globally scale the toolbar/status controls.
>
> **AC-WRITING-006.8:** With status content and viewport size unchanged, the bottom status panel shall remain height-stable across 60 consecutive egui frames at normal (1200 × 820 logical points) and compact (480 × 820 logical points) widths. After frame 1, the panel-height range across frames 2–60 shall be no greater than 1 logical point, with no monotonic growth; status controls and content shall remain available and the panel shall leave both toolbar and editor visible.
>
> **AC-WRITING-006.9:** The rendered status content and expanded Diagnostics summary shall remain single-line and clipped to their allocated regions at wide, breakpoint-adjacent, compact, and narrow widths. Changes in long status text or diagnostic counters shall not add rows or increase stable footer height; opening Diagnostics may add only its fixed disclosure row.
>
> **AC-WRITING-006.10:** A supported native inward/outward pinch event shall adjust the same transient per-window whole-percent page zoom as the status slider and presets, preserving the inclusive 75–300% limits and all document, session, pagination, export, and editor-input invariants in AC-WRITING-006.7. Inward pinch is the negative direction of the backend's supported zoom event; delivery is platform/backend dependent and no distinct squeeze event is promised. Effective egui UI pixels-per-point shall use a valid OS-native value once when reported, or exactly 2.0 when unavailable/invalid; this UI scale is independent of page zoom and shall not multiply native scale twice.
