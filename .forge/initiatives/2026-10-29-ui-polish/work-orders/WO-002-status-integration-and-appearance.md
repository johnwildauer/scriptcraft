## Implementation plan and acceptance contract

### Shared status seam and deterministic overflow

1. Introduce one desktop-local typed item identity/order and rendering/activation seam, with stable IDs and explicit accessible names. It must accept optional real future consumers without editing two independent layout paths. Define the full logical right-hand order **Sprint Timer → Focus Mode → Appearance → zoom**, left to right on the bar and in overflow. Zoom means its existing slider plus adjacent nine-preset menu, sharing the existing value and pinch synchronization. In WO-002 only Appearance and zoom are present; missing timer/focus slots do not produce a visible button or a claimed action. Test-only fixture items may exercise insertion/dispatch and ordering, but must not be shipped as functionality.
2. Allocate from the actual clipped panel content width using measured current style/font, control widths, spacing and an explicit reserved overflow trigger; use the same plan for wide and compact paths. Do not overlap hit targets or rely on clipping interactive controls. Agent-default deterministic rule: retain the longest fitting prefix of present right-hand items; move the remaining suffix, in original order, into one named keyboard-accessible overflow disclosure. Measure and reserve the trigger before choosing the prefix; recompute when width, style or present items change. Keep each item atomic, including the zoom pair; if zoom is in overflow, both the slider and exact preset menu remain operable there. Avoid duplicate enabled representations and duplicate IDs.
3. Preserve page and clean/unsaved projections and operation/error state; show clipped single-line text while space permits. At widths insufficient for their useful inline allocation, expose the full current values in the same disclosure as read-only, accessible status details without creating spurious actions. An active error must remain visibly identifiable even in the extreme compact fallback, e.g. an error-marked overflow trigger with accessible error name and complete details in the disclosure; do not rely on color alone. Diagnostics remains reachable, privacy-safe and its inline expanded summary remains clipped to one fixed disclosure row. Any popup or overflow content is an overlay, not a new footer row; use a bounded scrollable popup when contents exceed available screen height.
4. Define and document the smallest usable logical viewport based on a real trigger hit target plus panel insets; cover widths down to that minimum. Below it, clamp geometry safely and expose a bounded unavailable/fallback state without panic or overlapping interactions; do not claim that physically zero-width viewports can offer a clickable control. Do not use that exceptional boundary to evade ordinary compact access. Preserve controls through resize and theme changes, manage focus if an item moves into/out of overflow, allow Tab/Shift-Tab and Enter/Space activation and Escape dismissal, and avoid double activation. The open menu must remain reachable and not steal editor input except through normal intentional focus transfer.
5. The footer must remain single-line and bounded with no growing feedback loop. At 1200 × 820 and 480 × 820 points, for fixed content and size, frames 2–60 vary by at most one logical point with no monotonic growth; cover threshold-adjacent and minimum usable widths too. Diagnostics may add only its existing fixed disclosure row. Menus do not increase footer height; toolbar and editor remain visible. Status/page projections must not scroll, reveal or focus the editor, and zoom invalidation must still publish unavailable until fresh actual geometry arrives.

### Appearance and page painting

6. Add a named, accessible Appearance item, using a moon/crescent icon or an explicit text placeholder if the font cannot render it reliably. Its menu exposes exactly **System**, **Day Mode**, **Night Mode**, **Midnight Mode** in that order, with selected state announced. One transient per-window choice starts at System; no project or preference persistence is introduced. Pointer and keyboard selection work both inline and in overflow.
7. System follows the framework's *resolved* theme, including changes while System is selected; unknown OS preference uses egui's configured resolved fallback, not an invented light/dark OS observation. Day uses a freshly derived egui default light visuals palette; Night uses a freshly derived default dark palette. Midnight derives a consistently darker dark palette, not just a renamed Night setting. Reset/replace the relevant visuals on every mode transition so Midnight cannot contaminate Night or System, while preserving unrelated style, font, spacing and zoom policy. Explicit modes ignore subsequent OS changes until System is chosen again. Apply selection at a coherent frame boundary and repaint as needed; no stale one-frame mismatched chrome/page should persist after settling.
8. Use a centralized page palette selected from the resolved mode, not the literal System menu label. Resolved light uses light paper/dark text; every resolved dark mode uses dark paper/light text, with Midnight's page and major chrome surfaces measurably darker in relative luminance than Night. Theme page border, selection fill, text over selection, caret, IME preedit and other relevant page marks, including title pages. Agent-default measurable minimums: text and IME text ≥ 4.5:1 against their actual composited background; selected text ≥ 4.5:1 against composited selection; caret and visible selection boundary ≥ 3:1 against adjacent page; compute standard sRGB relative luminance after alpha compositing. Record actual palette values and ratios. Do not change page geometry, hit testing, blink timing, focus, or native IME routing to achieve contrast.
9. Applying or changing appearance is presentation only. Preserve serialization/project bytes, core fixed layout and source mappings, session revision/dirty/undo/redo and selection, native path, PDF and plain-text export outputs, zoom and editor input ownership; controls must not themselves edit. Legitimate user edits while testing are separated from passive-invariance comparisons.
