## Alignment assessment

The amendment is generally aimed at the initiative outcome and is appropriately separated from the completed WO-005/005a provenance history. It does not reopen WO-006, layout geometry, caret blink, pointer placement, or export behavior. Reusing the existing transactional [`EditingSession`](../../../../crates/scriptcraft-core/src/editing.rs:61), transient stable-ID provenance, and version-1 profile serialization is the correct ordinary dependency direction. The two new settings are plausibly below the existing persisted profile seam and do not require a schema bump if absent fields are deliberately defaulted.

However, the command oracle contains an internal contradiction and several boundary states that cannot be compared reliably by a fresh implementer and validator. The amendment therefore is not ready for approval or dispatch.

## Blockers

### EGC-WO007-DESIGN-B-001 — `auto_parenthetical` off behavior contradicts the empty-pair command rule

- **Severity:** blocker
- **Evidence:** The amendment says that an empty Parenthetical Tab/Enter converts to Dialogue and removes both delimiters regardless of caret position at [`editor-geometry-corrections-v2.md`](../editor-geometry-corrections-v2.md:145-149), and the WO repeats that unconditional empty-pair rule at [`WO-007-parenthetical-transition-and-boundary-policy.md`](../work-orders/WO-007-parenthetical-transition-and-boundary-policy.md:20-23). The same handoff then says that when `auto_parenthetical` is off, “no automatic delimiters or special cleanup occur” at [`WO-007-parenthetical-transition-and-boundary-policy.md`](../work-orders/WO-007-parenthetical-transition-and-boundary-policy.md:55).
- **Assessment:** These statements produce different results for an empty `()` entered or retained while automation is off: convert and remove, or preserve and follow the ordinary matrix. The intended behavior cannot be identified without inventing a precedence rule. This is a design-comparison blocker under [`03-design-review.md`](../../../process/03-design-review.md:30-43), not an implementation detail.
- **Required correction:** State separately what the setting gates: generated-delimiter insertion only, generated-pair cleanup only, both insertion and cleanup, or all special Parenthetical handling. Define the exact result for an existing empty user-authored pair, an existing generated pair, and a pair loaded from disk when the setting is off. Reconcile the plan amendment, the command table, and the prose in the work order before human approval.
- **Required next state:** Keep the amendment in `draft`; revise the authoritative plan and WO-007 handoff, then obtain a new fresh design review. Do not dispatch implementation.

## Warnings

### EGC-WO007-DESIGN-W-001 — Empty Parenthetical Delete lacks a complete caret and document-edge oracle

- **Severity:** warning
- **Evidence:** The rule at [`WO-007-parenthetical-transition-and-boundary-policy.md`](../work-orders/WO-007-parenthetical-transition-and-boundary-policy.md:21-23) distinguishes deletion of the whole empty element from deletion of only `)` when the caret is after the closing delimiter. The implementation guidance mentions a safe previous-element fallback at [`WO-007-parenthetical-transition-and-boundary-policy.md`](../work-orders/WO-007-parenthetical-transition-and-boundary-policy.md:63), but the command table does not state the exact caret result when the empty element is first, when it is the only element, or when the selection is non-collapsed.
- **Risk:** A validator cannot distinguish the required previous-element end position from a same-element start fallback or an error/no-op, and cannot determine whether Delete after `)` leaves the caret before or after the retained `(`.
- **Required action:** Add an explicit matrix for before `(`, between delimiters, after `)`, first element, only element, and non-collapsed selection. State the resulting element index, byte offset, role/text, history entry, and dirty/revision behavior for each branch.
- **Required next state:** Warning disposition in the WO-007 handoff before dispatch; no scope expansion is required.

### EGC-WO007-DESIGN-W-002 — Text-bearing delimiter repair is only fully specified for a missing closing delimiter

- **Severity:** warning
- **Evidence:** The plan says missing-delimiter repair is part of the amendment at [`editor-geometry-corrections-v2.md`](../editor-geometry-corrections-v2.md:148), while the WO command table specifies only “missing closing delimiter” at [`WO-007-parenthetical-transition-and-boundary-policy.md`](../work-orders/WO-007-parenthetical-transition-and-boundary-policy.md:49-50). The implementation guidance requests centralized shape analysis but does not define repair placement for a missing opening delimiter at [`WO-007-parenthetical-transition-and-boundary-policy.md`](../work-orders/WO-007-parenthetical-transition-and-boundary-policy.md:59-62).
- **Required action:** Define the accepted shapes (`()`, `(text`, `text)`, and `text`), the valid transition boundary for each, the exact inserted delimiter and byte offset, whether existing text is otherwise preserved, and the resulting caret before the new Dialogue. State that malformed shapes outside those cases remain ordinary text and do not trigger arbitrary bracket completion.
- **Required next state:** Warning; add the shape/repair table and regression rows before implementation.

### EGC-WO007-DESIGN-W-003 — “Before opening delimiter” Enter does not define the resulting caret and setting interaction

- **Severity:** warning
- **Evidence:** The plan and handoff require Enter before `(` to insert an empty Parenthetical above the current element at [`editor-geometry-corrections-v2.md`](../editor-geometry-corrections-v2.md:148) and [`WO-007-parenthetical-transition-and-boundary-policy.md`](../work-orders/WO-007-parenthetical-transition-and-boundary-policy.md:23-24). The handoff does not state whether the new element is generated/provenance-marked, whether its caret is between `()` or at another offset, whether the current element's text/role remains byte-for-byte unchanged, or whether `auto_parenthetical = false` suppresses delimiters while still inserting the element.
- **Required action:** Specify the new element role, exact text, provenance state, caret position, selection behavior, undo/redo snapshot, and `auto_parenthetical`-off result. Include the case where the opening delimiter is absent, since the phrase “before `(`” otherwise has no direct position meaning.
- **Required next state:** Warning; complete the command oracle and validation matrix before dispatch.

### EGC-WO007-DESIGN-W-004 — Strict transition boundary semantics need an explicit valid-end definition

- **Severity:** warning
- **Evidence:** The strict rule is stated for Scene Heading, Character, and Transition at [`editor-geometry-corrections-v2.md`](../editor-geometry-corrections-v2.md:149) and [`WO-007-parenthetical-transition-and-boundary-policy.md`](../work-orders/WO-007-parenthetical-transition-and-boundary-policy.md:25,51-53), but “valid text end” is not defined as the element's UTF-8 byte length, and the handoff does not define behavior for a non-collapsed selection, an empty element, or a failed/no-op operation's history and error surface.
- **Required action:** State that the strict boundary is a collapsed caret at `text.len()` on a checked UTF-8 boundary, or explicitly choose another rule. Add empty Scene Heading/Character/Transition and non-collapsed-selection rows. Preserve the existing approved Enter/Tab matrix only at that boundary; all rejected commands must be consumed no-ops with no mutation or undo entry, consistent with [`AC-WRITING-001.4a`](../../../requirements/features/screenplay-writing-loop.md:48).
- **Required next state:** Warning; add the definition and rows before implementation.

### EGC-WO007-DESIGN-W-005 — Persisted settings are backward-compatible in direction but not fully handed off as a profile contract

- **Severity:** warning
- **Evidence:** The amendment requires two default-on persisted booleans and typed malformed-value errors at [`editor-geometry-corrections-v2.md`](../editor-geometry-corrections-v2.md:145), and the work order classifies the profile/settings seam as an update at [`WO-007-parenthetical-transition-and-boundary-policy.md`](../work-orders/WO-007-parenthetical-transition-and-boundary-policy.md:18-19,77-82). Current serialization has a version-1 `PageProfile` with an existing optional-bool compatibility helper at [`PageProfile`](../../../../crates/scriptcraft-core/src/lib.rs:154) and [`optional_bool_field()`](../../../../crates/scriptcraft-core/src/lib.rs:574), but no exact durable JSON ownership/path or explicit statement that no schema bump is authorized for these fields.
- **Assessment:** Defaulting absent fields to `true` and rejecting wrong JSON types is compatible with the existing legacy-field pattern, but “project-level” and “profile/settings seam” are used interchangeably. The handoff also does not state whether changing either setting is part of the editing-session revision/dirty contract, whether the settings are included in layout-cache equality despite being non-geometric, or how settings survive `save/reopen` and `replace_with_saved()`.
- **Required action:** Name the exact owning persisted object and JSON keys, state the current schema/version decision, define new-project/legacy-missing/malformed/round-trip behavior, and record whether setting changes are core mutations or load-time profile changes. Update the core blueprint and requirements with the final user-facing contract, not only implementation evidence.
- **Required next state:** Warning; reconcile the compatibility and durable-contract handoff before approval.
