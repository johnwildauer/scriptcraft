Locked egui-winit stores the native scale from `window.scale_factor()` in viewport input, updates it on `ScaleFactorChanged`, and derives effective scale using egui zoom multiplied by native scale. eframe's native integration updates viewport info and passes that input into egui. - **Code rationale:** The existing native-mode document page-fit scale is recalculated directly from each frame's available logical width by `presentation_geometry`; native mode uses that live metric with no transition smoothing. Locked egui `0.29.1` exposes public `Context::animate_value_with_time`, which linearly interpolates a changing `f32` target and requests repaint while active. Use that public egui animation only on the native-mode document-page scale, with a stable widget-derived ID and a short fixed 120 ms duration. Recompute page width/font size by the same scale ratio so text, page geometry, caret and pointer mapping continue to use one coherent scale. Do not use egui global zoom setters or observe/own maximized state.
- **Expected behavior:** During viewport-width changes caused by native maximize/restore, page content scale should ease toward the live fit target instead of changing immediately each frame; when geometry stops changing, it converges to the exact existing fit scale. This is a mitigation attempt, not a diagnosis or guarantee that the reported native-window popping is caused by page-fit scale.
- **Risks:** The page may temporarily lag available width, leaving extra horizontal space or briefly clipping/overflowing while the window changes size; the fixed animation may also be visually imperceptible or fail to address window-frame popping. It changes document presentation timing on any native-mode width resize, not only maximize/restore. It must not modify the OS transition, window frame, toolbar, or native controls.
