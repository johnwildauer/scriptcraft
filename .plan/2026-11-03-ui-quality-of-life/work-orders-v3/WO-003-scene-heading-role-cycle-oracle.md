## Objective

Identify the first operation that makes a Scene Heading's semantic text/runs disagree with its retained managed source projection during repeated Tab/Enter role cycling.

## Scope

1. Add one focused regression in [`v3_wo003_scene_heading_role_cycle.rs`](../../../crates/scriptcraft-core/tests/v3_wo003_scene_heading_role_cycle.rs), reusing the plain insertion probes in [`v2_wo0026_scene_heading_sync.rs`](../../../crates/scriptcraft-core/tests/v2_wo0026_scene_heading_sync.rs) only as setup guidance.
2. Use the user's saved empty-heading shape as a fixture: a managed Scene Heading with generated SceneProperties, an empty SceneArcBeats container, and no direct Text element. Include one supported nonempty-arc branch only if needed to reach the reported cycle.
3. Drive the shortest repeated Enter/split and Tab/role-transition sequence that includes a completed derived refresh and subsequent text insertion into the Scene Heading. Record the exact starting role, caret, operation order, and first rejected operation.
4. After every accepted operation, assert that semantic text equals the concatenated retained Text-run projection and that semantic runs remain compatible with source runs. After every rejected operation, assert exact session rollback.
5. Stop the diagnostic at the first divergence, before the later [`replace_managed_text()`](../../../crates/scriptcraft-core/src/preservation.rs:1606) call can mask the originating transition with TextReplacement. Retain the bounded [`ManagedTextMismatchSite`](../../../crates/scriptcraft-core/src/preservation.rs:479) category for the final operation.
6. Record the established semantic/source before-state and owning operation in this order. If no divergence is established, identify the missing user operation/fixture and keep V3-WO-004 blocked.

## Boundaries

- Do not change text replacement, role changes, split/join, deletion, derived reconciliation, or save behavior.
- Do not treat a childless managed Paragraph with empty semantic text as malformed.
- Do not add document text, run content, identities, or source XML to desktop diagnostics.

## Structural acceptance

- The regression checks synchronization after each operation rather than only at final serialization.
- The legal empty-source/empty-semantic insertion branch remains covered.
- A repair order receives one concrete originating operation and before-state, not merely the final mismatch category.

## Handoff

V3-WO-004 fixes only the divergence established here. V3-WO-005 separately addresses the deterministic deletion guard and must not be used as a substitute for text synchronization evidence.

- **Exact operation/caret:** The failed operation is the very first text insertion into the cycled second Scene Heading. Its caret had been explicitly restored to that paragraph at element 1, UTF-8 byte offset 0 immediately before the call. Enter, all three Tab transitions, derived refresh, the generated-attachment role-change safe-stop/rollback probe, and all synchronization assertions through the restored-caret step had completed first.
- **Before-state:** The regression's immediately preceding oracle establishes that the selected semantic paragraph has empty canonical text and no semantic runs, and that the retained direct Text-run projection for the managed paragraph found by that paragraph's stable identity is also empty. The mismatch therefore is not evidence of an earlier semantic/source text divergence in the tested sequence. `replace_text_element_children()` can report this mismatch only when the source paragraph actually passed to it has source Text segments whose concatenation differs from the empty semantic old text.
- **Root-cause localization:** The insertion path resolves the source paragraph through `managed_element_mut()`. That indexed mutable lookup previously trusted the cached node path without checking that the resolved node's `SourceOwnership::Managed` identity was the requested stable identity. The user-run result, combined with the preceding identity-based empty-source assertion and the unchanged mismatch guard, localizes the failure to a source-target lookup inconsistency: insertion was validated against a different indexed source target than the selected empty heading. The result does not identify which prior reconciliation first made a cached path stale; no claim is made about a preceding role/Enter operation diverging semantic text from its correctly identified source paragraph.
- **Repair handoff:** WO-004 now verifies the indexed target identity, rebuilds the managed-paragraph index from the authoritative preservation tree if the cached path does not resolve to the requested identity, and retries that identity lookup before mutation. The TextReplacement mismatch guard remains intact. This targets the failed source lookup rather than changing semantic text, run projection, role transitions, or generated attachments.
- **Extended coverage:** WO-004 extended this regression after the original insertion through subsequent typing, undo/redo, clearing and retyping, undo/redo of the retype, and in-memory FDX serialization/reopen. ## Second user-run result and diagnosis supersession — 2026-11-04

- **Second user-supplied command/result:** The user reran `cargo test -p scriptcraft-core --test v3_wo003_scene_heading_role_cycle -- --nocapture` after the first WO-004 patch and extended test. It still failed at the same original insertion into the cycled Scene Heading, now at line 236: left `Err(Preservation(ManagedTextMismatchAt(TextReplacement)))`, right `Ok(())`. The user explicitly reports this is not a later typing or undo failure. The agent did not run the command.
- **Corrected complete before-state:** Immediately before insertion the selected element is the cycled empty Scene Heading, with empty semantic text/runs and an empty `<Text>`-element run projection. Its retained paragraph also contains direct whitespace-only Text/CData children formatted around generated `SceneProperties`/`SceneArcBeats`.
- **Corrected root cause:** The regression's [`source_runs()`](../../../crates/scriptcraft-core/tests/v3_wo003_scene_heading_role_cycle.rs:36) projects only child `<Text>` elements, so its per-operation equality checks correctly passed while omitting paragraph-level whitespace formatting. By contrast, [`direct_text_child_indexes()`](../../../crates/scriptcraft-core/src/preservation.rs:3127), used by [`replace_managed_text()`](../../../crates/scriptcraft-core/src/preservation.rs:1621), previously selected every direct Text/CData child including whitespace-only formatting. The replacement therefore concatenated formatting indentation as old semantic text and rejected insertion at offset zero. This is a source-projection mismatch at the text-child classification boundary, not a stale managed-element lookup.
- **Superseded prior diagnosis:** The first follow-up's cached-path/source-target inference and its added identity verification did not fix the reported failure; the second user result falsifies it as the cause of this reproduction. Retain the identity check only as a defensive invariant, not as the repair or established root cause.
- **Current narrow repair and regression:** [`direct_text_child_indexes()`](../../../crates/scriptcraft-core/src/preservation.rs:3127) now excludes whitespace-only direct Text/CData leaves from semantic source segments while leaving those nodes in the ordered source tree. The existing strict mismatch comparison and identity check remain. The same regression now explicitly asserts that generated element-only formatting whitespace exists before the failing insertion and remains after insertion, then retains its subsequent typing, clearing/retyping, undo/redo, and FDX serialization/reopen sequence.
