## Objective

Establish which stage of the real zoom input-to-settled-scroll lifecycle fails to preserve the viewport-center anchor, without changing compensation behavior.

## Scope

1. Add a desktop test helper that invokes [`raw_input_hook()`](../../../apps/scriptcraft/src/main.rs:2651) before the complete application update, rather than manually assigning zoom state or rendering only [`live_document_surface()`](../../../apps/scriptcraft/src/main.rs:1366).
2. Drive one native pinch sequence and one status-control zoom change through complete frames at a non-edge document position. Include repeated pinch coalescing and a simultaneous raw-scroll branch to determine whether [`handle_surface_input()`](../../../apps/scriptcraft/src/main.rs:1782) cancels the pending request before paint.
3. Add bounded value-free lifecycle counters for anchor capture success/miss, manual-scroll cancellation, compensation queued, and geometry published/consumed. Keep them in the existing desktop diagnostics; do not expose page content, coordinates tied to document text, paths, or IDs.
4. Strengthen the existing compensation assertions in [`wo0012_desktop_zoom_keeps_the_viewport_anchor_once_or_clamps_at_an_edge()`](../../../apps/scriptcraft/src/main.rs:6417) to compare page index, page-local document point, and outside-page displacement after settling, except at demonstrated scroll-extent clamping.
5. Record the first failing lifecycle stage and exact synthetic input sequence in this order. Distinguish no captured anchor, canceled anchor, no queued scroll request, incorrect target, and correction not retained by the following frame.
6. If the complete synthetic paths preserve the anchor under user-owned execution, record the remaining need for the user's exact gesture/control, platform input shape, and before/after observations; do not infer acceptance.

## Boundaries

- Do not change zoom percentages, anchor policy, cancellation policy, scroll targets, page geometry, or caret reveal behavior.
- Do not add timing thresholds or claim user-perceived behavior from structural counters.
- Do not alter core layout, session state, native TextState, or exports.

## Structural acceptance

- The oracle covers capture, possible cancellation, target queueing, publication, one-shot consumption, and settled scroll in the same scenario.
- Page/gap identity is asserted rather than inferred from similar page-local coordinates.
- The next order receives one concrete failing stage or an explicit unresolved input-evidence requirement.

## V3-WO-007 repair execution and authorized lifecycle reruns — 2026-11-04

- **First diagnostic-enhanced rerun — exit `101`:** The strict native pinch assertion still failed and exposed all lifecycle counters: capture success `1`, capture miss `0`, manual-scroll cancellation `0`, compensation queued `1`, geometry published `1`, anchor consumed `1`. The computed target was `[862.4, 2379.6]` on the original page 1; scaled page rectangles began at `[[24.0 52.0] - [1700.9 2222.1]]`, `[[24.0 2237.1] - [1700.9 4407.2]]`, and `[[24.0 4422.2] - [1700.9 6592.2]]`. The output nevertheless settled at page 0 with offset `[3.6,13.2]` and maximum `[444.9,63855.4]`. - **Root cause:** `live_document_surface()` called `ui.scroll_to_rect()` with the correctly calculated centered point, but egui's resulting `ScrollArea` output did not contain that requested offset. The code treated allocation/publication of scaled page rectangles as proof that the one-shot correction had been applied, consumed the anchor immediately, and published uncorrected scroll geometry. The defect was therefore in applying/committing the queued target after `ScrollArea` resolved its current content and viewport extents, not in capture, cancellation, target math, or normal edge clamping.
- **Production repair:** [`main.rs`](../../../apps/scriptcraft/src/main.rs) now retains the correct target through the `ScrollArea` pass, calculates the viewport-centered offset from the resolved inner-viewport center and the laid-out target, clamps each axis against the resolved content extents, commits the offset to the `ScrollArea` state once, and publishes page rectangles translated to the committed view. The existing first-anchor coalescing, raw-scroll cancellation/manual-scroll precedence, page-local scaling, unscaled gaps/outside displacement, padding, caret-reveal independence, and one-shot consumption remain in place. No `status_bar.rs`, core layout, session, save, export, or public API behavior changed.
- **Bounded status-slider fixture corrections:** The first repaired run advanced beyond native pinch but found that the 1,280 px fixture overflowed the inline zoom control; a 1,920 px status-only viewport was added so the test still interacts with the actual inline slider. The next run found the original slider far-right click did not change its value, so the click was moved to the actual slider rectangle center. Neither correction removes or relaxes the status-slider lifecycle assertions.
- **Intermediate exact-command outcomes:** After the production change, the command exited `101` at the missing inline-slider fixture rect. After widening only the status fixture, it exited `101` at `the status slider must change zoom` with the far-right click.
