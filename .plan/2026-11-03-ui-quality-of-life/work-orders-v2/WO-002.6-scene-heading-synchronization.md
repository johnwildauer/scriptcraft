## Investigation outcome — 2026-11-04

### Diagnosis and exact changes

- Traced the structural path: [`EditingSession::enter()`](../../crates/scriptcraft-core/src/editing.rs:767) and [`EditingSession::split()`](../../crates/scriptcraft-core/src/editing.rs:757) create a candidate split; [`EditingSession::mutate()`](../../crates/scriptcraft-core/src/editing.rs:1058) sends identity/order changes through [`PreservationState::reconcile_body_structure()`](../../crates/scriptcraft-core/src/preservation.rs:1518). The retained paragraph text is projected from the semantic candidate and the inserted paragraph receives source provenance in the same detached candidate. [`EditingSession::change_role()`](../../crates/scriptcraft-core/src/editing.rs:957) updates a mapped paragraph's source Type and provenance role through [`change_managed_role()`](../../crates/scriptcraft-core/src/preservation.rs:1481).
- The reported category is not available with a specific value or fixture. Static tracing does not establish a Scene Heading defect in the supported plain imported-Action split/role-change path: structural reconciliation's text projection path does not emit `ManagedTextMismatch`; its possible categorized mismatch sites are source-text replacement, managed paragraph removal/provenance, and scoped projection validation. No exact branch can responsibly be assigned without the user's failing imported FDX and operation sequence or user-run results from the focused reproductions.
- No production code, mismatch checks, Cast List correction, relevance classification, scheduling, or indexes were changed. This is an intentional blocker, not a proposed semantic/source rewrite.
- Added [`v2_wo0026_scene_heading_sync.rs`](../../../crates/scriptcraft-core/tests/v2_wo0026_scene_heading_sync.rs) with imported-FDX Enter and split cases at paragraph start/interior/end; each performs the initial derived refresh, transitions the new paragraph to Scene Heading, checks original/new semantic identities and exact text, exercises undo/redo and subsequent edits, then serializes and reopens. It also covers exact session rollback for a structural edit rejected due to an opaque attachment.

### Coverage, limitations, and status

- **Authored, not run:** six supported insertion scenarios (three cursor positions for each of Enter and split), with role transition, identity/text retention, history, later edits, and in-memory FDX serialization/reopen; plus one unsupported-attachment rollback case.

There is no captured failing FDX, actual `ManagedTextMismatchSite` category, or confirmed user command sequence in the available record. User-owned execution of the focused tests, along with the failing source/operation details if they do not reproduce, is required before assigning a narrow production fix.
- Per repository policy, no tests, builds, lint, formatting, implementation checks, reviews, or validation were run. Therefore no claim is made that the authored tests compile or pass.
- **Disposition: BLOCKED; implementation not submitted.** Keep mismatch validation and rollback behavior unchanged. Resume only with an established failing branch; then fix that ownership boundary while retaining exact semantic/source text and identity state.
