# V2-WO-001.1 — Zoom anchor state and capture

- **Status:** Implementation submitted 2026-11-03; user validation pending
- **Initiative:** [`ui-quality-of-life-v2-zoom-and-typing.md`](../ui-quality-of-life-v2-zoom-and-typing.md)
- **Depends on:** None
- **Validation owner:** User; no agent-run checks or independent validators

## Objective

Add the geometry representation and application state needed to capture the document point at the viewport center before any zoom change. This order establishes the anchor contract and capture paths; V2-WO-001.2 applies the compensated scroll offset.

## Scope

1. Extend [`GeometrySnapshot`](../../apps/scriptcraft/src/status_bar.rs:582) and [`ViewportPageTracker::publish()`](../../apps/scriptcraft/src/status_bar.rs:630) with the actual scroll offset required to reconstruct the current viewport-center anchor. Update the caller in [`live_document_surface()`](../../apps/scriptcraft/src/main.rs:1348).
2. Add a bounded anchor representation that identifies a page-local document coordinate and handles viewport centers in vertical gaps or outside page bounds without inventing screenplay positions.
3. Capture one pending anchor when native pinch changes zoom in [`raw_input_hook()`](../../apps/scriptcraft/src/main.rs:2569), before geometry invalidation.
4. Capture the same anchor for slider, preset, and keyboard changes in [`show_application_panels()`](../../apps/scriptcraft/src/main.rs:2427).
5. Coalesce repeated zoom changes deterministically and clear stale pending state on document replacement. Do not use caret or pointer position.
6. Add focused geometry tests for anchor capture, page/gap selection, both axes, repeated changes, and missing/stale geometry. Tests are authored, not agent-run.

## Boundaries

- Do not change scroll offsets or page layout in this order.
- Do not change session revision, selection, dirty state, fixed layout, exports, or zoom percentages.
- Do not implement derived-refresh work or later v2 orders.

## Structural acceptance

- Every zoom input path records the same viewport-centered anchor policy when valid old geometry exists.
- The snapshot uses actual published scroll geometry rather than an assumed top origin.
- Missing or stale geometry produces a safe no-anchor outcome.
- No visible behavior change is required until V2-WO-001.2.

## Durable documentation

Record the capture-state handoff in this order. V2-WO-001.2 owns the complete user-facing zoom contract in [`technical-context.md`](../../.forge/blueprints/technical-context.md).

## Handoff

V2-WO-001.2 consumes the pending anchor after scaled page allocation, applies exact scroll compensation, and adds end-to-end desktop coverage.

## Implementation handoff — 2026-11-03

- **Status:** Implementation submitted; user validation pending. No agent-run validation was performed, in accordance with repository policy.
- **Files/interfaces changed:**
  - [`status_bar.rs`](../../../apps/scriptcraft/src/status_bar.rs) — `GeometrySnapshot` now stores the published `scroll_offset`; `ViewportPageTracker::publish()` accepts and compares that actual offset; added `ViewportCenterAnchor` with a bounded page-local document coordinate, separate outside-page/gap displacement, page index, and viewport-center position; added fresh-geometry capture with deterministic nearest-page selection and safe rejection of missing, stale, mismatched, or invalid geometry.
  - [`main.rs`](../../../apps/scriptcraft/src/main.rs) — `live_document_surface()` publishes `ScrollArea`'s actual state offset; app state stores a coalesced pending anchor, captures before status-control and native-pinch invalidation, and clears it when a document is replaced. Existing geometry publication fixtures were updated for the new offset parameter.
- **Authored, unrun coverage:** Geometry tests cover actual-scroll-offset reconstruction and scale conversion, deterministic vertical-gap selection with simultaneous horizontal/vertical edge displacement, and missing/stale/mismatched/invalidated geometry. An app test covers retention of the first pending anchor across later zoom requests. Tests were not run.
- **Limitations / next order:** Scroll compensation, scroll mutation, and pending-anchor consumption are intentionally not implemented; V2-WO-001.2 owns those behaviors. No user validation or acceptance is claimed.
