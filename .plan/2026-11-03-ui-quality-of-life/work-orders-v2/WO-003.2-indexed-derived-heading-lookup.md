## Implementation submission — 2026-11-04

### Exact changes

- [`PreservationState`](../../crates/scriptcraft-core/src/preservation.rs) now owns bounded indexed accessors for managed-element lookup, source depth/effective `xml:space` context, and mutable path access. Indexed lookups retain strict duplicate-owner ambiguity errors, verify that the current indexed path still owns the requested identity, and use the existing counted complete-search fallback only when an externally constructed state has no index. Mutable access retains path-only COW detachment, invalidates source-use data, and the derived publication rebuilds both transient indexes together.
- [`scene_metadata.rs`](../../crates/scriptcraft-core/src/scene_metadata.rs) now uses those accessors for reconciliation and arc-name reads; recursive whole-tree heading, context, and mutable searches were removed. Depth remains zero for a direct child of a preservation section and increases once per element ancestor. Effective XML-space inheritance retains the XML namespace/qualified-name matching and `default`/`preserve` behavior. Source order, supported/unsupported scene handling, and candidate publication behavior were not intentionally changed.
- Existing value-free managed-index diagnostics expose lookup/entry probes and fallback-tree visits; the authored integration case asserts indexed probes, zero fallback visits, and one derived-publication rebuild for a scoped refresh. No document values were added to diagnostics.

### Authored coverage

- [`scene_metadata.rs`](../../crates/scriptcraft-core/src/scene_metadata.rs) adds unrun cases for nested heading context with inherited XML-space, duplicate managed ownership ambiguity, and scoped-refresh lookup/rebuild counters. Existing scene-metadata coverage continues to cover unsupported-scene deferral and source-preserving publication.
- Earlier [`V2-WO-003.1`](WO-003.1-source-identity-use-index.md) coverage remains authored/unrun for source-index mutation invalidation and rebuild boundaries. Existing [`V2-WO-002.6`](WO-002.6-scene-heading-synchronization.md) imported Scene Heading probes remain diagnostic only; the reported synchronization failure is still blocked and unestablished.

### Caveats and user-validation steps

- No public API or serialized/semantic representation changed in this suborder. Existing public value-free index diagnostics are reused.
- Indexes are rebuilt together after a changed derived publication; direct out-of-band mutations to publicly exposed preservation collections still require [`rebuild_indexes()`](../../crates/scriptcraft-core/src/preservation.rs) before indexed use. If an indexed path no longer resolves to the requested owner, access rejects rather than mutating another element.
- Coverage is authored but unrun. Repository policy prohibited agent-run tests, builds, lint, formatting, implementation checks, reviews, and validation. Compilation/runtime behavior and performance measurements remain unknown; no timing improvement or user acceptance is claimed.
- User validation: compile and run the authored core coverage; verify the scoped/complete derived and native FDX round trips; exercise nested XML-space, duplicate ownership, unsupported-scene deferral, managed-source mutation/index rebuild boundaries, and user-reported Scene Heading operations; then inspect value-free index counters and perform the authorized large-document responsiveness observations. Record results before deciding whether to resume the blocked Scene Heading investigation.
