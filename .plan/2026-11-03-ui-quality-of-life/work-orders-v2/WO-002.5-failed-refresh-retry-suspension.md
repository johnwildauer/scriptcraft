# V2-WO-002.5 — Suspend failed derived refresh until relevant invalidation

- **Status:** Implementation submitted 2026-11-04; authored tests intentionally unrun per repository policy
- **Initiative:** [`ui-quality-of-life-v2-zoom-and-typing.md`](../ui-quality-of-life-v2-zoom-and-typing.md)
- **Depends on:** [`V2-WO-002.4`](WO-002.4-privacy-safe-failure-diagnostics.md)
- **Validation owner:** User; no agent-run tests, builds, lint, formatting, implementation checks, reviews, or validation

## Objective

Prevent a failed derived correction from running every second forever while preserving its pending state, error visibility, transactional rollback, and explicit save behavior.

## Scope

1. Add session-owned failed-refresh disposition separate from safe-stop deferral in [`EditingSession`](../../crates/scriptcraft-core/src/editing.rs:187).
2. When [`refresh_cast_lists_with_outcome()`](../../crates/scriptcraft-core/src/editing.rs:436) returns an error, retain the failed scope as pending but make it nonretryable until a later relevant invalidation. Do not publish the detached candidate or change project/history/dirty state.
3. Ensure unrelated text edits and timer ticks do not reactivate failed work. A new edit relevant to the failed scene, or a relevant structural/complete invalidation, may permit one retry.
4. Preserve the distinction between safe-stop deferral and fatal correction failure in [`DerivedWorkSummary`](../../crates/scriptcraft-core/src/editing.rs:45) and desktop counters/messages.
5. Keep explicit Save/Save As complete candidate preparation independent of the suspended timer state.
6. Add core and desktop tests for complete/scoped failure, repeated due ticks, unrelated edits, relevant retry, safe deferral, failure atomicity, and save independence. Tests are authored, not run.

## Boundaries

- Do not hide the V2-WO-002.4 diagnostic or convert fatal errors into successful deferral outcomes.
- Do not change the actual Cast List correction algorithm or structural relevance classification.
- Do not change the one-second cadence or introduce backoff threads.

## Structural acceptance

- One failed attempt causes zero further attempts on unrelated ticks/edits until relevant invalidation.
- Failed work remains visibly pending and its error remains available; it is not marked complete.
- A relevant later edit permits one new attempt, and explicit saving remains complete.

## Handoff

V2-WO-002.6 reproduces and fixes the Scene Heading synchronization failure without scheduler changes.

## Implementation submitted — 2026-11-04

### Exact changes

- Added session-owned failed-complete and failed-scene disposition in [`EditingSession`](../../crates/scriptcraft-core/src/editing.rs:225), separate from safe-stop deferral. Failed refreshes retain their pending invalidation, do not publish the detached candidate, and are not retried by direct refresh calls or timer ticks until relevant invalidation clears the failed disposition.
- Relevant scoped invalidation clears only failed scene scopes it intersects and can reactivate previously failed complete work; complete invalidation, undo, and redo clear the failed state. Successful save rebasing clears the disposition after complete save-candidate preparation.
- Extended public [`DerivedWorkSummary`](../../crates/scriptcraft-core/src/editing.rs:45) with `failed_complete` and `failed_scene_count`; `retryable` excludes both failed and safely deferred work. Pending and failed state remain separately observable.
- Added a desktop `derived_refresh_failed` counter and changed the scheduled error status to retain the privacy-safe failure category while identifying fatal failure/suspension rather than safe deferral. Safe-stop deferral counters and messages remain separate.
- No Cast List correction algorithm, Scene Heading algorithm, relevance classification, or indexes were changed. Timer cadence remains one second.

### API impacts

- `DerivedWorkSummary` gains the public fields `failed_complete` and `failed_scene_count`. Downstream struct literals must initialize the new fields; default construction remains available.
- Desktop diagnostics gain `derived_refresh_failed`; fatal errors no longer increment the safe-stop `derived_refresh_deferred` counter. The visible fatal status now says the failed refresh is suspended until relevant document changes and includes the existing bounded category.

### Authored coverage (not run)

- Core: [`fatal_later_scoped_scene_keeps_prior_candidate_and_pending_scope_unpublished()`](../../crates/scriptcraft-core/src/editing.rs), covering scoped failure atomicity, per-scene suspension, and reactivation of only the newly relevant scene.
- Core: [`failed_complete_refresh_suspends_until_relevant_invalidation_and_save_still_prepares()`](../../crates/scriptcraft-core/src/editing.rs), covering complete failure, pending/error state, no publication/revision/dirty/history changes, direct retry suppression, unrelated and relevant edits, and save-preparation independence.
- Core: [`suspended_complete_timer_state_does_not_block_complete_save_candidate()`](../../crates/scriptcraft-core/src/editing.rs), covering complete detached save preparation while timer work is suspended.
- Desktop: [`failed_complete_refresh_stays_pending_without_retrying_until_relevant_edit()`](../../apps/scriptcraft/src/main.rs), covering multiple due ticks, unrelated/relevant edits, one retry, status diagnostics, and failure-versus-deferral counters.
- Existing safe-stop deferral coverage remains in [`deferred_scene_waits_for_its_own_relevant_revision_and_remains_pending()`](../../crates/scriptcraft-core/src/editing.rs) and [`scheduled_refresh_does_not_report_deferred_unsupported_scene_as_an_error()`](../../apps/scriptcraft/src/main.rs).

### Limitations and validation status

- Per repository policy, all authored tests remain unrun. No build, lint, formatting, implementation check, review, or validation was performed; user-owned validation remains outstanding.
- Failure disposition stores only bounded scope state, not document content or identities in diagnostics. The underlying correction failure remains exposed through the existing safe category; this order does not diagnose or fix the underlying Cast List/Scene Heading correction errors.
