# V2-WO-002.7 — Character/Cast List correction remediation

- **Status:** Implementation submitted 2026-11-04; user validation pending
- **Initiative:** [`ui-quality-of-life-v2-zoom-and-typing.md`](../ui-quality-of-life-v2-zoom-and-typing.md)

- **Validation owner:** User; no agent-run checks or independent validators

## Objective

Reproduce and fix the source-data failure encountered when a Character edit causes an imported scene's Cast List to be rebuilt.

## Scope

1. Use the V2-WO-002.4 scheduled-refresh category to distinguish scene-arc reconciliation, Cast List source replacement, and complete candidate validation failures.
2. Author imported-FDX reproductions containing a supported Scene Heading, Character cue, and plain Cast List; exercise Character insertion/rename/removal through the scoped refresh path in [`correct_cast_lists_candidate()`](../../crates/scriptcraft-core/src/cast_list.rs:105).
3. Inspect semantic runs versus retained Text runs in [`replace_cast_list_text()`](../../crates/scriptcraft-core/src/cast_list.rs:254) and [`replace_managed_text_elements()`](../../crates/scriptcraft-core/src/preservation.rs:1304), plus generated arc consistency in [`scene_arc_names()`](../../crates/scriptcraft-core/src/scene_metadata.rs:169).
4. Fix the established defect without changing canonical cue text, normalized name projection, ordering, nested arc ownership, or supported source formatting.
5. Preserve per-scene deferral for genuinely unsupported/formatted structures and atomic rollback for fatal failures. Do not convert all errors into deferral.
6. Add coverage for plain single/multiple runs, empty/stale lists, multiple affected scenes, unsupported structures, undo/redo, complete save preparation, and serialization/reopen. Tests are authored, not run.
7. If the user's failure category is not reproducible, record the unresolved fixture requirement rather than suppressing the error.

## Boundaries

- Do not change retry suspension, structural relevance, or source-identity indexing in this order.
- Do not bypass managed-source synchronization or complete changed-candidate validation.
- Do not rewrite unrelated preserved source.

## Structural acceptance

- Supported Character changes regenerate the affected scene's derived arc and Cast List without a fatal source-mapping error.
- Semantic and managed source text remain identical after publication and reopen.
- Unsupported scenes retain their complete original subtrees and independent scenes still update.

## Handoff

V2-WO-002.8 removes overbroad complete invalidation for provably irrelevant structural edits.

## Investigation and implementation submission — 2026-11-04

### Diagnosis

- Static tracing localized a reproducible Cast List source-mapping failure class in [`correct_cast_lists_candidate()`](../../crates/scriptcraft-core/src/cast_list.rs) → [`replace_cast_list_text()`](../../crates/scriptcraft-core/src/cast_list.rs) → [`replace_managed_text_elements()`](../../crates/scriptcraft-core/src/preservation.rs). Imported paragraphs with opaque/non-text sibling content are rejected as unsupported by the preservation mapper, but the correction path previously propagated that safe structural limitation as a fatal Cast List source-mapping error. Formatted semantic runs already had an explicit per-scene deferral; equivalent unsupported preserved source structure did not.
- The existing pass reconciled scene arcs before discovering an unreplaceable Cast List. Thus a scene deferred at the Cast List stage could still have its arc subtree changed, violating complete per-scene safe deferral. No production error was suppressed broadly: source-projection mismatches, missing/ambiguous anchors, model errors, and other fatal categories remain errors.
- This establishes the failure mechanism statically and supplies focused imported-FDX reproduction fixtures. The user's original document and exact operation sequence were not provided, and repository policy prevented running the authored reproductions, so the original report is not claimed as runtime-confirmed.

### Exact changes

- [`cast_list.rs`](../../crates/scriptcraft-core/src/cast_list.rs) now preflights only stale Cast Lists in the requested scene scope before arc reconciliation. Unsupported formatting or source mapping defers the whole scene, so neither its arc subtree nor its Cast List is partially published; independently supported scenes continue. The existing detached candidate and complete validation boundary remain unchanged.
- [`preservation.rs`](../../crates/scriptcraft-core/src/preservation.rs) shares the exact non-mutating source/run mapping validation with replacement. This lets correction distinguish unsupported structure from a managed-text mismatch before changing scene arcs, while preserving all original Text elements/runs on the eventual replacement and retaining fatal mismatch behavior.
- Normalized Character projection and ordering are unchanged. Supported plain single-/multi-Text-run Cast Lists update the semantic projection and source runs together; replacement text remains in the first run and remaining plain runs are emptied as before. Arc reconciliation remains tied to the same candidate and publication boundary.

### Authored coverage and limitations

- Added imported-FDX cases in [`cast_list.rs`](../../crates/scriptcraft-core/src/cast_list.rs) for a stale two-run Cast List through Character edit, scoped refresh, complete save preparation, serialization/reopen, and arc consistency; an imported empty list through rebuild and round trip; and an opaque Cast List subtree that is deferred whole while an independent scene updates. These also cover source-run preservation and multiple scenes.
- Existing Cast List tests continue to author plain/single-run updates, multiple scene correction, unsupported formatting deferral, undo/redo, candidate atomic publication, save preparation, and FDX reopen behavior. All coverage is authored only; no tests were run.
- No changes were made to relevance classification, scheduling/retry behavior, indexes, or save gates. No tests, builds, lint, formatting, implementation checks, reviews, or validation were run, per repository policy. Compilation and runtime results remain unknown; user-owned validation is pending.

**Disposition: IMPLEMENTATION SUBMITTED.** The identified structural source-mapping failure is handled as scene-local safe deferral rather than a fatal refresh error; truly inconsistent semantic/source projections still fail atomically.
