## Objective

Stop revision-only derived refresh attempts and integrate pending-derived scheduling, diagnostics, and desktop regression coverage.

## Scope

1. Update [`refresh_cast_lists_on_schedule()`](../../apps/scriptcraft/src/main.rs:550) so a due tick with no pending derived work skips before candidate cloning or reconciliation, even when the session revision changed.
2. Replace or narrow the existing revision-only [`DerivedRefreshWatermark`](../../apps/scriptcraft/src/main.rs) logic so it cannot make a non-cast edit eligible and cannot suppress a newly relevant edit.
3. Preserve one-second scheduling, same-frame input ordering, initial complete refresh, repaint behavior, failure status, and document-activation invalidation.
4. Project the new value-free pending/requested/attempted/deferred scene counts through existing desktop diagnostics without IDs or content.
5. Extend the desktop render oracle to prove:
   - Action and Dialogue insertions produce no derived attempt on later due ticks;
   - Character-cue edits request only their owning scene;
   - unrelated edits do not retry deferred scenes;
   - activation still performs one complete pass;
   - Save/Save As preparation remains independent of the scheduler.
6. Reconcile earlier tests that assume every changed revision triggers a refresh. Tests are authored, not agent-run.

## Boundaries

- Do not change the refresh interval or move work to another thread.
- Do not implement V2-WO-003 through V2-WO-006.
- Do not claim latency improvement without user measurement.

## Structural acceptance

- Irrelevant content revisions cause zero derived attempts and zero derived project candidates.
- Relevant revisions invoke only the scoped core path and preserve repaint/revision/dirty behavior.
- Due unchanged ticks remain cheap and existing migration-modal input exclusion remains intact.
- Diagnostics remain value-free and save correctness does not depend on timer state.

## Implementation handoff — 2026-11-04

- **Implemented:** Removed desktop revision/disposition watermark scheduling. Due ticks now consult the session-owned derived-work summary before invoking correction; complete activation work remains eligible, irrelevant Action/Dialogue revisions skip before project-candidate cloning, and only retryable affected-scene work proceeds. Safe-stop-deferred scenes remain pending but do not retry on unrelated edits/ticks. Save/Save As continues its unconditional complete candidate preparation; the successfully prepared saved-session rebase clears pending work so the timer cannot repeat that complete pass. Existing one-second cadence, input-before-refresh ordering, repaint behavior on changed results, failure status, activation invalidation, and migration-modal exclusion are retained.
- **Value-free diagnostics:** The public summary now carries retryable and deferred-scene counts in addition to pending/complete/affected counts. Desktop totals expose irrelevant due skips and cumulative requested/attempted/deferred scene counts; the status summary exposes live pending scope counts. No scene identities or screenplay/source values are projected.
- **Public API caveat:** Adding public fields to `DerivedWorkSummary` preserves `Default`-based construction and existing field reads but requires external exhaustive struct literals to initialize `retryable` and `deferred_scene_count`. External struct-literal source compatibility is not guaranteed.
- **Authored coverage (not run):** Updated revision-gate expectations and deferred-scene scheduling coverage; added desktop oracle coverage for Action/Dialogue no-attempt/no-candidate behavior, one-scene Character-cue scope, initial complete activation pass, value-free scene counters, and deferred work staying asleep across an unrelated role edit. Existing Save/Save As timer-independence coverage remains applicable.
- **Limitations:** No latency or user-experience improvement is claimed. The tests are authored only. No tests, build, lint, formatting, desktop automation, implementation checks, review, or independent validation were run. User validation remains pending; V2-WO-003 and later orders were not started.
