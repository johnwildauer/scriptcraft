# V2-WO-002.8 — Precise structural derived relevance

- **Status:** Implementation submitted 2026-11-04; user validation pending
- **Initiative:** [`ui-quality-of-life-v2-zoom-and-typing.md`](../ui-quality-of-life-v2-zoom-and-typing.md)
- **Depends on:** [`V2-WO-002.7`](WO-002.7-cast-list-correction.md)
- **Validation owner:** User; no agent-run checks or independent validators

## Objective

Avoid complete derived refresh after provably irrelevant element insertion/deletion while retaining correct invalidation when scene ownership or Character membership changes.

## Scope

1. Replace the length/identity shortcut in [`classify_derived_invalidation()`](../../crates/scriptcraft-core/src/editing.rs:1095) with a before/after structural diff that considers stable element identities, roles, text where relevant, and old/new owning scenes.
2. An inserted or deleted non-Character, non-Scene-Heading element with no ownership ambiguity shall produce no derived invalidation.
3. Mark only the owning scene for inserted/deleted Character cues. Handle Scene Heading insertion/removal, splits, joins, and cross-scene movement by marking provably affected old/new scenes or using complete fallback when the mapping is ambiguous.
4. Preserve existing single-element relevance behavior, failed/deferred retry rules, and complete fallback for undo/redo or uncertain topology.
5. Add a structural relevance matrix for Action insertion, Character insertion, Scene Heading insertion, same/cross-scene split/join, deletion, role transitions, and ambiguous identities. Include desktop proof that creating an Action element does not schedule a complete refresh. Tests are authored, not run.

## Boundaries

- Do not alter the actual editing operation, scene ownership, derived output, or save preparation.
- Do not implement source-identity indexes or layout optimizations.
- Prefer complete fallback over an incomplete affected-scene set.

## Structural acceptance

- New Action elements schedule no derived pass; continued typing remains unaffected.
- Character and scene-boundary changes mark every and only provably affected scene, with conservative fallback where necessary.
- No failed/deferred work is accidentally cleared or reactivated by an irrelevant structural edit.

## Handoff

V2-WO-003.1 removes the repeated per-Paragraph complete-source scans that still make necessary complete and relevant refreshes expensive.

## Implementation submission — 2026-11-04

### Exact changes

- [`classify_derived_invalidation()`](../../crates/scriptcraft-core/src/editing.rs) now matches before/after elements by unique stable identity and compares each scene's ordered Character identity/text projection. Structural Action-only insertions, deletions, same-scene splits, and joins therefore produce no invalidation; Character insertion/deletion, Character role transitions, cue reordering, and scene-ownership changes mark the live affected scene set.
- New Scene Heading identities are marked directly. Heading text edits preserve the existing owning-scene behavior. Heading insertions/removals are resolved from the before/after cue owners, while reordered common heading identities, duplicate identities, or Character cues without a provable owner use complete fallback. Removed scene identities are not included in the post-edit scope.
- Existing failed/deferred suspension transitions were left unchanged. An irrelevant structural edit classifies to `None` and does not clear failed or deferred state; relevant scoped invalidations retain their prior retry behavior. Undo/redo and replacement continue using complete invalidation.
- No editing operation, derived correction algorithm, save preparation, or index was changed.

### Authored coverage

- [`editing.rs`](../../crates/scriptcraft-core/src/editing.rs) includes a structural relevance matrix for Action insertion/deletion, Character insertion/deletion, Scene Heading insertion/removal, ownership-changing split/join shapes, Character↔Action role transitions, duplicate identities, missing scene ownership, and complete undo/redo fallback. Additional coverage asserts irrelevant Action splits do not reactivate failed-complete or deferred-scene work.
- [`main.rs`](../../apps/scriptcraft/src/main.rs) extends the desktop scheduler oracle: splitting an Action creates a new Action element, but the due timer records an irrelevant skip, performs no derived attempt, and creates no derived candidate clone. Existing subsequent Character-edit coverage still exercises scoped refresh.
- Coverage is authored only. No tests, builds, lint, formatting, implementation checks, reviews, or validation were run, per repository policy. Compilation and runtime results remain unknown; user-owned validation is pending.

**Disposition: IMPLEMENTATION SUBMITTED.** Structural invalidation is scoped by before/after role and scene ownership where provable, with complete fallback for ambiguity.
