# V2-WO-002.1 — Session-owned derived relevance tracking

- **Status:** Implementation submitted 2026-11-04; user validation pending
- **Initiative:** [`ui-quality-of-life-v2-zoom-and-typing.md`](../ui-quality-of-life-v2-zoom-and-typing.md)
- **Depends on:** [`V2-WO-001.2`](WO-001.2-zoom-scroll-compensation.md) for sequence only; no shared implementation mechanism
- **Validation owner:** User; no agent-run checks or independent validators

## Objective

Track whether an edit can affect derived scene/cast data and identify the affected scenes without changing the desktop scheduler or reconciliation algorithm yet.

## Scope

1. Add session-owned pending derived invalidation state to [`EditingSession`](../../crates/scriptcraft-core/src/editing.rs:127): none, affected-scene identities, or complete refresh.
2. Initialize a newly opened/created session to require one complete refresh, preserving current initial synchronization behavior.
3. In the mutation path, compare only the before/after roles and ownership information needed to classify relevance:
   - ordinary text changes outside Character cues do not mark derived work;
   - Character-cue text changes mark the owning scene;
   - role transitions into/out of Character mark the affected owning scene;
   - scene-heading changes, split/join/delete, undo/redo, and structural or ambiguous ownership use conservative affected old/new scenes or complete fallback.
4. Expose only a value-free pending summary needed by the desktop scheduler: whether work is pending, whether it is complete, and the affected scene count. Do not expose document identities in diagnostics.
5. Keep explicit Save/Save As candidate preparation complete and independent of pending state.
6. Define the internal handoff consumed by V2-WO-002.2 for scoped refresh and pending-state completion. Do not make the desktop use the new state in this order.
7. Add core relevance-matrix tests for text edits, role changes, structural operations, undo/redo, replacement/rebase, no-op edits, and failed edit rollback. Tests are authored, not agent-run.

## Boundaries

- Do not change derived names, SceneProperties, SceneArcBeats, Cast List contents, or refresh timing yet.
- Do not remove the existing scheduler watermark until V2-WO-002.3.
- Do not implement source-identity indexing from V2-WO-003 or ordinary-edit storage changes from V2-WO-004.

## Structural acceptance

- Non-cast text edits leave pending derived work unchanged.
- Relevant edits identify only provably affected scenes; conservative fallback covers ownership movement.
- Failed edits do not change pending state; no-op behavior remains exact.
- Initial activation and explicit save preparation retain complete semantics.

## Durable documentation

Record the session invalidation model and public/value-free API impact in this order. V2-WO-002.3 owns the integrated blueprint update.

## Handoff

V2-WO-002.2 consumes the pending scope in core correction, reconciles only affected scenes, and defines success/deferral completion rules.

## Implementation record — submitted 2026-11-04

- **Files changed:** [`editing.rs`](../../crates/scriptcraft-core/src/editing.rs) and this work-order record only. No desktop scheduler, correction algorithm, or initiative blueprint was changed.
- **Session state:** [`EditingSession`](../../crates/scriptcraft-core/src/editing.rs) owns `PendingDerivedInvalidation::{None, Scenes, Complete}`. New, replaced, and saved-rebased sessions begin with complete invalidation. Successful edits merge their classified scope only after candidate validation/publication; failed and exact no-op edits preserve it. Undo and redo mark complete.
- **Classification:** Stable element identity/order is required for local classification. Character text edits and transitions into/out of Character mark the owning scene; scene-heading text changes mark that heading's scene. Scene-heading role changes, absent/ambiguous owners, and any element insertion/removal/reordering use complete fallback. Other text/role changes are irrelevant. Scope accumulation unions scene identities; complete dominates.
- **Value-free public API:** `DerivedWorkSummary` and `EditingSession::pending_derived_work_summary()` expose only pending, complete, and affected-scene count; complete scope reports zero individually affected scenes. Scene identities are not exposed. Additive public API impact is limited to this summary type and accessor in the existing public `editing` module.
- **V2-WO-002.2 internal handoff:** Crate-visible `PendingDerivedInvalidation`, `EditingSession::pending_derived_invalidation()`, and `EditingSession::complete_derived_invalidation()` provide scope consumption and completion. Scoped completion removes only completed scene IDs and cannot consume complete work; successful complete refresh clears all pending state. Explicit save-candidate preparation remains complete and does not consume session pending state.
- **Authored but unrun core coverage:** Initial complete summary/value-free fields; irrelevant Action text; Character text and role transitions; heading text; multi-scene union; split/join/delete and heading-role structural fallback; undo/redo; replacement and saved rebase; no-op and failed-edit rollback; save-candidate independence; and scoped/complete pending completion.
- **Limitations:** Structural ownership changes deliberately fall back to a complete refresh; no attempt is made here to compute narrower scopes for split/join/delete. The existing desktop scheduler still does not consult pending state, and existing correction remains whole-document. No tests, builds, lint, formatting, implementation checks, reviews, or independent validation were run; authored coverage is not evidence of passing behavior.
- **User validation:** Pending. No acceptance or runtime behavior is claimed.

### Handoff to V2-WO-002.2

Consume the crate-visible pending scope in core correction, preserving the complete-refresh path for activation/save preparation. Scoped correction should use the scene-heading IDs held in `PendingDerivedInvalidation::Scenes`; invoke `complete_derived_invalidation` only for successfully reconciled scope, leaving deferred scenes pending. This order intentionally leaves scheduler integration for V2-WO-002.3.
