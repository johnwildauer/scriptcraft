# V2-WO-003.1 — Reusable source identity-use index

- **Status:** Implementation submitted 2026-11-04; user review and validation pending
- **Initiative:** [`ui-quality-of-life-v2-zoom-and-typing.md`](../ui-quality-of-life-v2-zoom-and-typing.md)
- **Depends on:** [`V2-WO-002.8`](WO-002.8-structural-derived-relevance.md)
- **Validation owner:** User; no agent-run checks or independent validators

## Objective

Replace per-Paragraph complete-source scans in derived removal safety and ID reservation with a reusable transient index having equivalent safety semantics.

## Scope

1. Add a private transient source-identity-use index to [`PreservationState`](../../crates/scriptcraft-core/src/preservation.rs:661), excluded from semantic equality and serialization.
2. Build it during existing complete index reconstruction/validation with one bounded tree walk. Track Paragraph identity multiplicity, reference/anchor use, reserved source ID attributes, and external attribute/text/CDATA/comment/PI occurrences using the current substring rules.
3. Replace repeated [`safe_paragraph_removals()`](../../crates/scriptcraft-core/src/scene_metadata.rs:853) identity/reference/tree scans and [`source_id_values()`](../../crates/scriptcraft-core/src/scene_metadata.rs:931) full-tree collection with indexed queries.
4. Update or invalidate the index transactionally after every managed/source mutation. Rebuild at import, structural/global, undo/redo, derived publication, replacement, and saved-rebase boundaries unless local maintenance is provably complete.
5. Preserve collision allocation, duplicate-ID handling, external-use safe-stops, unsupported-scene deferral, and opaque data exactly.
6. Add value-free build/node/query counters and differential tests against the existing scan semantics for IDs in every supported node/attribute position. Tests are authored, not run.

## Boundaries

- Do not change derived names, scene scope, correction behavior, or save validation.
- Do not expose document IDs or text through diagnostics.
- Do not implement layout or semantic-element storage changes.

## Structural acceptance

- One index build examines each source node a bounded constant number of times; a refresh does not rescan the full tree per Paragraph identity.
- Indexed removal/reservation decisions equal the prior scan decisions on duplicate, referenced, anchored, external-use, and opaque fixtures.
- Stale indexes cannot be used after source mutation.

## Handoff

V2-WO-003.2 removes remaining recursive managed-heading lookups and integrates the new counters and durable documentation.

## Implementation submission — 2026-11-04

### Exact changes

- [`preservation.rs`](../../crates/scriptcraft-core/src/preservation.rs) now builds the managed-paragraph location map and a private, transient source identity-use index in one source-tree walk. The index stores Paragraph identity multiplicity, Paragraph-domain reference and foreign-anchor uses, all plain `id` attribute values for reservation, and external substring-use hits across attributes, text, CDATA, comments, and processing-instruction targets/data. A multi-pattern byte matcher preserves the prior case-sensitive substring behavior and the special exemption for the matching unqualified `id` on a uniquely identified Paragraph.
- [`scene_metadata.rs`](../../crates/scriptcraft-core/src/scene_metadata.rs) now obtains derived arc removal-safety and reserved source IDs through index queries; the per-identity reference/anchor/source-tree scans and source-ID tree collector were removed. [`preservation.rs`](../../crates/scriptcraft-core/src/preservation.rs) also uses the indexed source-ID values for managed Paragraph ID allocation.
- Managed mutation access invalidates the source-use index; edit candidates rebuild before validation/publication when needed. Structural insert/remove, derived publication, import/session construction, undo/redo, replacement, and saved rebase reconstruct both indexes together. Index fields remain outside semantic equality and serialization. Direct edits through the existing publicly mutable preservation collections must call the new index-rebuild maintenance API in [`preservation.rs`](../../crates/scriptcraft-core/src/preservation.rs) before later indexed use.
- Added aggregate value-free rebuild/node/query counters. No heading lookup, derived semantics, relevance classification, retry policy, or save behavior was changed.

### API impact

- Added public value-free diagnostics type/functions for source identity-use index counters and a public index-rebuild maintenance method for callers that mutate the publicly exposed preservation collections directly. The transient index itself is private to the crate. No existing semantic data representation or serialization format changed.

### Authored coverage

- [`preservation.rs`](../../crates/scriptcraft-core/src/preservation.rs) adds differential checks against the previous scan rules for duplicate, referenced, anchored, safe self-ID, attribute, nested attribute, text, CDATA, comment, processing-instruction target/data, namespaced-ID, and reserved-ID cases; it also covers managed text mutation invalidation/rebuild, transient equality exclusion, and derived publication rebuilding.
- [`editing.rs`](../../crates/scriptcraft-core/src/editing.rs) extends structural edit/history coverage to assert index availability after split/join, undo/redo, saved rebase, and replacement.
- Coverage is authored but unrun, as required by repository policy.

### Limitations and validation

- Since preservation collections remain publicly mutable for compatibility, callers performing direct out-of-band mutation must explicitly rebuild indexes before indexed use. Managed application mutation paths do this transactionally.
- The separate potential-reference scan used by structural paragraph deletion was not changed; this order replaces the derived removal-safety and source-ID reservation scans only. Heading lookup remains for V2-WO-003.2.
- No tests, builds, lint, formatting, implementation checks, reviews, or validation were run. Compilation/runtime behavior and performance measurements remain unknown; user validation is pending.

**Disposition: IMPLEMENTATION SUBMITTED.** The derived removal-safety and ID-reservation queries now use the reusable transient source index, with no change to derived or save semantics.
