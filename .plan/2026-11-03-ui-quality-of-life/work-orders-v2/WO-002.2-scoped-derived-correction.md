## Objective

Make session refresh consume pending derived scope and reconcile only affected scenes while retaining complete refresh and save preparation paths.

## Scope

1. Route [`EditingSession::refresh_cast_lists_with_outcome()`](../../crates/scriptcraft-core/src/editing.rs:313) through a scoped internal correction path using V2-WO-002.1 pending state.
2. Extend [`correct_cast_lists_candidate()`](../../crates/scriptcraft-core/src/cast_list.rs:79) and [`reconcile_project_candidate_with_outcome()`](../../crates/scriptcraft-core/src/scene_metadata.rs:55) with an internal scope that limits scene projection, managed-heading attempts, and Cast List visits to requested scenes.
3. Preserve the existing complete path for initial activation and [`prepare_save_candidate()`](../../crates/scriptcraft-core/src/cast_list.rs:150).
4. On successful refresh, clear completed pending scenes. Retain deferred scenes so they retry only after a later revision relevant to those scenes; unrelated edits must not reactivate them.
5. Preserve detached candidate rollback, complete validation of changed candidates, non-undoable refresh history behavior, revision/dirty updates, formatted-list deferral, and independent-scene progress.
6. Keep diagnostics value-free. Add requested, attempted, changed, unchanged, and deferred scene counts without identities or document text.
7. Add core tests for one/multiple affected scenes, unrelated-scene retention, Character add/remove/rename, role transitions, deferred scenes, fatal later-scene failure, undo/redo, initial complete refresh, and explicit save before/after scoped refresh. Tests are authored, not agent-run.

## Boundaries

- Do not optimize the per-paragraph removal-safety scan; that is deferred V2-WO-003.
- Do not change derived-name normalization, ordering, nested arc association, or canonical Character text.
- Do not change desktop scheduling until V2-WO-002.3.

## Structural acceptance

- Scoped correction does not attempt unrelated managed headings or Cast Lists.
- Unrelated scene source subtrees and semantic elements remain unchanged.
- Deferred and fatal outcomes retain their current safety behavior without unrelated retries.
- Save/Save As always performs complete derived preparation.

## Implementation record — submitted 2026-11-04

- **Files changed:** [`editing.rs`](../../../crates/scriptcraft-core/src/editing.rs), [`cast_list.rs`](../../../crates/scriptcraft-core/src/cast_list.rs), [`scene_metadata.rs`](../../../crates/scriptcraft-core/src/scene_metadata.rs), and this work-order record. No desktop scheduler, initiative blueprint, or later-order work was changed.
- **Scoped correction:** Session refresh now dispatches `None` as zero work, `Scenes` through the requested scene-heading IDs, and `Complete` through the existing full correction path. Scoped projection, managed-heading reconciliation, and Cast List updates are restricted to requested scenes. Initial session activation remains complete; `prepare_cast_list_save_candidate()` continues to use full correction independently of pending state.
- **Completion and deferral:** Successful scoped correction clears only attempted, non-deferred scenes. Unsupported scene metadata and formatted Cast Lists remain pending; a complete pass with deferred scenes narrows pending state to those scene IDs. Deferred scenes are suppressed from repeat correction until a relevant edit to that scene, a structural/complete invalidation, or another relevant scene edit reactivates its own scope. Fatal candidate errors publish neither project changes nor pending completion. Changed candidates retain full validation and existing non-undoable refresh/revision/dirty behavior.
- **Value-free counters:** `CastListCorrection` now reports requested, attempted, changed, unchanged, and deferred scene counts, alongside the prior aggregate correction counters. No IDs or document content are reported. Changed and deferred counts can overlap when metadata changed but a formatted Cast List in that same scene remained deferred; unchanged excludes deferred scenes.
- **Public compatibility impact:** The public `CastListCorrection` struct has five new public fields; downstream code constructing it with a struct literal must supply them. Scoped APIs and scene identities remain crate-internal.
- **Authored, unrun core coverage:** Six new `editing.rs` tests cover initial complete plus one-scene refresh, multiple-scene isolation, Character role transitions/removal and undo/redo, deferred-scene suppression/reactivation, scoped refresh with complete explicit save preparation, and fatal later-scene rollback with pending-scope retention. Existing save, metadata-deferral, and complete-correction coverage remains authored in the core suite. No tests were run.
- **Limitations:** Removal-safety and reserved-ID scans remain unchanged and may still traverse the full preserved source; reusable safety indexing is deferred to V2-WO-003. Desktop scheduling still uses its existing revision gate and does not yet consult pending state; V2-WO-002.3 owns that integration. No builds, tests, lint, formatting checks, implementation checks, reviews, or independent validation were run. No runtime behavior or user acceptance is claimed.
- **User validation:** Pending.
