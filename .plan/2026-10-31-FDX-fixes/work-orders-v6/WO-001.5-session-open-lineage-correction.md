# V6-WO-001.5 — Session-open lineage correction

- **Status:** Implemented 2026-11-03; regressions authored but not executed; user validation pending
- **Depends on:** V6-WO-001.1 implementation; supersedes its initial DocumentRef-derived timestamp source and Save-only XRef behavior
- **Validation:** User-owned; no agent-run checks or independent validators

## Objective and current contract

Capture one ephemeral session-open wall-clock timestamp whenever an editing session begins, for imported and new projects. This timestamp is not the imported DocumentRef DateTime, is not canonical Project state, and stays unchanged across Save, Save As, and successful save rebases. Reopening/new session captures a new value.

Every successful Save and Save As independently updates DocumentRef DateTime to the current saving/serialization time and preserves its existing UUID. XRef behavior:

| Operation | Direct-child XRefs before save | Result |
|---|---:|---|
| Save | 0 | Append one XRef using session-open timestamp |
| Save | 1 or more | Preserve all XRefs; append none |
| Save As | Any count | Append exactly one XRef using session-open timestamp |
| Direct source-backed serialization | Any count | No lineage changes |

Every appended XRef receives a fresh collision-checked UUID. FDX's one-second resolution means session-open and saving timestamps may coincide; do not force a difference or fabricate monotonic time.

## Implementation

1. Replaced `EditingSession.opened_document_ref_datetime` with a required session-open timestamp captured at session construction. It remains outside project, undo/redo, dirty tracking, and document serialization; both saved-rebase paths retain it. Added a test-only constructor seam to inject a fixed session-open value.
2. Renamed the parsed `FdxDocument` field to `document_ref_datetime` so it remains explicit source metadata and is not mistaken for session state. Removed the old helper that derived session lineage from preserved DocumentRef.
3. Renamed the save-context field and builder to carry session-open time separately from the save timestamp. Transactional storage supplies the session value; direct serialization has no lineage authority.
4. Implemented conditional empty-history initialization for Save and unconditional XRef append for Save As. Both source-backed reconciliation and new-document generation use session-open time for XRef and save-context time for DocumentRef; transactional writers reject missing or invalid session-open timestamps instead of falling back to DocumentRef or save time.
5. Retained detached-candidate identity/tree checks, source preservation, conflict detection, atomic publication, and failure rollback. Existing XRefs remain untouched.
6. Updated screenplay-writing requirements, product overview, technical context, v6 planning, and the historical 001.1 record.

## Regression coverage authored, not executed

- Fixed session-open/save times are injected independently; repeated successful Save As reuses session-open while updating DocumentRef time and allocating distinct XRef IDs, and a reopened fixed session uses a new injected value.
- Ordinary Save with empty history creates one XRef; the following Save creates none and preserves the first XRef.
- Ordinary Save with existing XRefs preserves them; Save As appends despite existing history.
- New-document Save As uses distinct injected session-open and saving timestamps.
- Missing/malformed DocumentRef behavior does not use its old DateTime as the session-open value; direct serialization remains lineage-neutral.
- Existing transactional failure tests continue to assert no session/target/destination publication on failure.
- Session-open time survives successful project rebase and saved-project replacement.
