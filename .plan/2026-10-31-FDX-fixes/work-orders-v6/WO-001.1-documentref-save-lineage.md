# V6-WO-001.1 — DocumentRef and Save As lineage

- **Status:** Implemented 2026-11-03; regression coverage authored but not executed; user validation pending
- **Depends on:** The corrected lifecycle in [`fdx-fixes-v6.md`](../fdx-fixes-v6.md); no other v6 work order
- **Validation:** User-owned; no agent-run checks or independent validators

> **Superseded lineage details:** The initial implementation in this order incorrectly used the imported DocumentRef DateTime as its session anchor and did not initialize an empty XRef history on ordinary Save. The approved correction in [V6-WO-001.5](WO-001.5-session-open-lineage-correction.md) is the current contract. The remainder of this file records the historical 001.1 implementation and its safeguards; do not treat its old timestamp source or Save-only behavior as current requirements.

## Objective

Make DocumentRef the durable current-save record and XRef the append-only Save As history:

- preserve DocumentRef ID across Save and Save As;
- update DocumentRef DateTime to the current time on every Save/Save As;
- on Save As, append one new XRef with a fresh UUID and the DocumentRef DateTime captured when the file was opened;
- preserve all prior XRefs unchanged;
- retain strict source identity, source-tree, conflict, and atomic-publication safeguards.

## Lifecycle example

Assume a file is opened with DocumentRef timestamp T0:

1. Ordinary Save at T1 writes DocumentRef T1 and adds no XRef.
2. Another ordinary Save at T2 writes DocumentRef T2 and adds no XRef.
3. Save As at T3 appends an XRef with timestamp T0—not T1 or T2—and a fresh UUID, then writes DocumentRef T3.
4. A second Save As in that same session at T4 appends another XRef with timestamp T0 and a different fresh UUID, then writes DocumentRef T4.
5. After reopening, the session anchor becomes the DocumentRef timestamp read from that file, so later Save As uses the new anchor.

For a never-saved document, no deserialized timestamp exists. The first Save As uses the current save timestamp for both DocumentRef and the initial XRef.

## Current constraint

[`save_session_with_codec()`](../../../crates/scriptcraft-core/src/fdx_storage.rs:382) knows the operation mode, but [`write_v6()`](../../../crates/scriptcraft-core/src/fdx.rs:500) does not. The desktop also calls the direct writer from [`session_health()`](../../../apps/scriptcraft/src/main.rs:563), so writer invocation alone cannot authorize timestamp or lineage changes.

[`identity_domain()`](../../../crates/scriptcraft-core/src/fdx.rs:3260) already registers DocumentRef and XRef identities. Adding an XRef before the original graph comparison would incorrectly fail code 4; omitting its registered identity would instead fail code 29. The implementation must reconcile the authorized addition at the correct point in the detached candidate lifecycle.

## Scope

1. Capture DocumentRef DateTime once during deserialization and retain it as per-session lineage state.
2. Introduce save-scoped writer input carrying operation kind and one current save timestamp.
3. Generate DocumentRef for new documents and supply it when an actual save lacks one.
4. Update DocumentRef DateTime on every transactional Save/Save As.
5. Append exactly one XRef on Save As using the session anchor and a fresh collision-checked UUID v4.
6. Preserve direct source-backed serialization and all unrelated source content.
7. Keep code 4, code 29, code 30, conflict detection, and atomic publication strict.
8. Update durable requirements/architecture and the v6 execution record.

## Non-goals

- No WindowState/TextState runtime restore or overwrite; those are 001.2 and 001.3.
- No page presentation or scaling changes.
- No regeneration of DocumentRef or existing XRef IDs.
- No latest-XRef timestamp refresh algorithm; ordinary Save never updates an XRef.
- No arbitrary identity-graph exceptions or relaxation of code 30.
- No blanket Final Draft compatibility claim.
- No agent-run tests, desktop automation, Final Draft automation, review, or validation.

## Implementation requirements

### 1. Capture the opened timestamp

Extend the reader result associated with [`FdxDocument`](../../../crates/scriptcraft-core/src/fdx.rs:244) to expose the valid root DocumentRef DateTime observed during deserialization.

Add private optional opened-timestamp state to [`EditingSession`](../../../crates/scriptcraft-core/src/editing.rs:86):

- set it once when an imported session is constructed;
- let existing headless constructors derive it from imported preservation so they do not silently lose the anchor;
- keep it outside undo/redo snapshots and canonical screenplay content;
- carry the original value through [`prepare_saved_rebase()`](../../../crates/scriptcraft-core/src/editing.rs:212), rather than adopting the newly saved DocumentRef timestamp from the re-read output;
- leave it absent for a new preservation-free project.

Accept only the exact 15-character YYYYMMDDTHHMMSS shape with valid calendar/time fields as a usable anchor. Preserve malformed source attributes in the tree, but treat their typed anchor as absent.

### 2. Add save-scoped writer input

Introduce a bounded writer/save context that distinguishes ordinary Save from Save As and carries one timestamp captured at the start of save preparation.

Direct [`write_v6()`](../../../crates/scriptcraft-core/src/fdx.rs:500) behavior remains non-mutating for source-backed documents: no DateTime refresh and no XRef addition. New preservation-free direct output may generate a DocumentRef with fresh identity and serialization time, but it does not append an XRef without an explicit Save As operation.

[`save_session_with_codec()`](../../../crates/scriptcraft-core/src/fdx_storage.rs:382) supplies the actual operation and timestamp. Tests must be able to inject fixed timestamps and lineage IDs without sleeping or reading the real clock.

**Clock default:** use local wall-clock time because FDX has no zone suffix. If local offset discovery fails, use UTC rather than failing an otherwise valid save. Keep the dependency minimal and the clock behind the injectable save boundary.

### 3. Reconcile DocumentRef before output checks

For preservation-free generation in [`make_new_document_nodes()`](../../../crates/scriptcraft-core/src/fdx.rs:1734), insert DocumentRef before Content with DateTime then id attributes in reference order.

For imported documents during actual save:

- if DocumentRef is absent, create it before Content with a fresh UUID and the current save timestamp;
- if present, preserve its ID, attribute order, namespace, unrelated attributes, children, and source position;
- update only its recognized DateTime attribute value in place;
- if DateTime is absent, add it using the reference-compatible attribute order without normalizing unrelated attributes;
- ambiguous DocumentRef structure must not result in guessing which durable identity to edit. Return a bounded privacy-safe error rather than selecting one arbitrarily.

New IDs follow the existing lowercase hyphenated UUID v4 shape. Reuse the bounded allocation pattern in [`ParagraphIdAllocator`](../../../crates/scriptcraft-core/src/paragraph_id.rs:14), with lineage-appropriate errors and collision checks against all registered identities and source ID attributes.

### 4. Append XRef only for Save As

For Save As, select the appended timestamp in this order:

1. the session's opened DocumentRef DateTime;
2. if no opened anchor exists, the current valid pre-save DocumentRef DateTime;
3. otherwise, the current save timestamp.

Append one direct child XRef after the existing XRef children with DateTime then id attributes. Use a fresh collision-checked UUID v4 and preserve every existing XRef exactly.

Then set DocumentRef DateTime to the current save timestamp. Do not run a separate ordinary-Save timestamp algorithm that could alter the new XRef.

Apply best-effort reference-like LF/two-space formatting only to the newly created XRef's unambiguous element-only container context. Include the same formatting in the detached expected tree. Do not globally format DocumentRef or imported source.

### 5. Preserve identity and transaction gates

Use this order inside the save writer:

1. Validate the original live candidate and compare its original non-paragraph graph under code 4.
2. Clone preservation into a detached effective save candidate.
3. Apply the authorized DocumentRef and optional XRef reconciliation to that clone.
4. Perform existing managed screenplay reconciliation and inserted-structure formatting.
5. Compare the effective expected identity set and source tree against immediate re-read under code 29/code 30.
6. Complete storage conflict checks and atomic publication before installing the re-read session.

Do not compare code 29 against the pre-addition identity list. Do not weaken code 4 for any unrelated identity change. Append any new diagnostic integers to the durable table in [`technical-context.md`](../../../.forge/blueprints/technical-context.md:49) without reusing existing values.

A failed operation must leave the destination, live DocumentRef/XRef tree, opened-timestamp anchor, path, baseline, selection, and dirty state unchanged.

## Regression coverage

Author [`v6_wo0011_documentref_save_lineage.rs`](../../../crates/scriptcraft-core/tests/v6_wo0011_documentref_save_lineage.rs) with fixed clocks and, where useful, deterministic ID seams:

1. Ordinary Save updates only DocumentRef DateTime and preserves its ID and all XRefs.
2. Open at T0, Save at T1/T2, then Save As at T3 appends XRef T0 and writes DocumentRef T3.
3. Repeated Save As in one session appends fresh XRef IDs with the same opened timestamp.
4. Reopen establishes the new DocumentRef timestamp as the next Save As anchor.
5. First Save As of a new project creates DocumentRef and one XRef using the current save time when no anchor exists.
6. A missing imported DocumentRef is created before Content; an imported non-UUID DocumentRef ID remains verbatim.
7. Missing/malformed DateTime follows the typed fallback without exposing source values in errors.
8. Existing XRef IDs, timestamps, attributes, order, and unrelated DocumentRef children remain unchanged.
9. New UUIDs are lowercase hyphenated v4 and collision-check all current identities/source ID attributes; entropy/collision failures remain transactional.
10. Direct source-backed serialization and desktop health-check serialization do not update DocumentRef or append XRefs.
11. Unrelated identity mutation still fails code 4; authorized XRef output passes code 29/code 30; independently injected tree corruption still fails code 30.
12. Codec, conflict, and injected storage failures preserve destination bytes, live lineage, anchor, path, baseline, and dirty state.
13. Reference copies retain screenplay, scene-arc, TitlePage, board, image, and unrelated opaque content through Save/Save As/reopen.
