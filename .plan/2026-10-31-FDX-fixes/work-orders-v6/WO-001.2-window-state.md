# V6-WO-001.2 — Root WindowState restore and overwrite

- **Status:** Implemented 2026-11-03; regression coverage authored but not executed; user desktop validation pending
- **Depends on:** V6-WO-001.1 save-scoped candidate input and transaction path
- **Validation:** User-owned; no agent-run checks or independent validators

## Objective

Read the direct root WindowState once on Open, restore its supported native geometry with safe fallback, and overwrite that root block from current desktop geometry on every Save/Save As. Treat it as disposable view state rather than semantic screenplay content.

## Reference contract

The checked-in examples place WindowState between PageLayout and ElementSettings:

- [`reference2.fdx`](../../../.reference/reference2.fdx:169): Height 854, Left 0, Mode Normal, Top 95, Width 870.
- [`real_script_example.fdx`](../../../.reference/real_script_example.fdx:108): Height 854, Left 2, Mode Normal, Top 95, Width 1510.
- [`arc copy.fdx`](../../../.reference/arc%20copy.fdx:103): Height 824, Left 29, Mode Normal, Top 125, Width 870.

Only Normal mode is evidenced. V6 does not invent maximized, minimized, or fullscreen FDX mappings.

## Scope

1. Project only a direct root WindowState during deserialization.
2. Restore supported Left, Top, Width, Height, and Normal mode once after successful document activation.
3. Retain latest reported native geometry for Save without changing Project or dirty state.
4. Generate a default WindowState for new native output and replace imported root WindowState during actual Save/Save As.
5. Leave nested source structures and all unrelated sections untouched.
6. Preserve direct non-save source serialization and transactional failure behavior.

## Non-goals

- No TextState Scaling or Selection behavior; that is 001.3.
- No continuous synchronization of window geometry into Project or preservation state.
- No promise that a native window manager accepts a requested position/size.
- No monitor calibration, physical-pixel serialization, maximized/minimized mapping, or multi-window model.
- No DocumentRef/XRef lifecycle changes beyond consuming 001.1's save input.
- No agent-run tests, desktop automation, review, or validation.

## Implementation requirements

### 1. Add a bounded root-only projection

Extend the reader's typed view-state result with an optional/root-defaulted WindowState projection. Match only a direct child of FinalDraft with the supported expanded name; do not select nested elements that happen to share the local name.

Parse Left, Top, Width, and Height as bounded integers:

- Left and Top may be negative for legitimate multi-monitor arrangements;
- Width and Height must be positive and representable in the desktop's bounded coordinate type;
- malformed, overflowing, zero, or negative dimensions are unusable;
- unknown or missing Mode falls back to Normal;
- duplicate or ambiguous root WindowState blocks produce the safe runtime default rather than an arbitrary source choice.

Opening must not fail merely because this disposable view state is unusable.

### 2. Restore once after Open

During successful activation in [`activate_opened_project()`](../../../apps/scriptcraft/src/main.rs:475):

- retain valid imported geometry as a pending one-shot native restore;
- if geometry is absent or unusable, leave the current native window unchanged;
- dispatch position/size once from the desktop update path and then clear the pending request regardless of whether the OS later reports the exact requested values;
- do not reapply the imported geometry on subsequent frames, resizes, focus changes, or Save;
- do not alter session revision, dirty state, undo history, fixed layout, or PDF state.

Use a consistent coordinate contract: Width/Height represent the native inner-window logical dimensions, while Left/Top represent the outer-window logical position. If the backend cannot supply one of those rectangles, use the documented safe fallback rather than mixing physical pixels with logical points.

Native viewport commands are best-effort. Tests may prove one-shot command generation, but must not claim OS acceptance without user desktop validation.

### 3. Capture current geometry for Save

The current Save path in [`save_fdx_mode_at()`](../../../apps/scriptcraft/src/main.rs:321) has no egui context argument. Add a small latest-reported geometry snapshot updated from the desktop frame/viewport information and pass it through 001.1's save-scoped input.

At Save:

- use the latest valid current inner dimensions and outer position;
- do not read screenplay layout, page scale, TextState Scaling, or native pixels-per-point as window geometry;
- if no valid native snapshot exists, use the new-document default Height 854, Left 0, Mode Normal, Top 95, Width 870 as **agent-default**;
- keep geometry in OS logical coordinates; do not multiply by native display scale before storing it.

Window movement/resizing alone does not mutate Project, preservation, session revision, dirty state, or history.

### 4. Generate and overwrite only the root block

For preservation-free output, generate WindowState after Content and before ElementSettings. V6-WO-001.3 will insert TextState immediately after it.

For imported actual Save/Save As:

- replace the direct root WindowState with one canonical element using attribute order Height, Left, Mode, Top, Width;
- if missing, insert after PageLayout when available, otherwise before the first ElementSettings;
- if duplicates exist, replace them with one canonical root block because the user explicitly designated this data disposable;
- do not touch any nested WindowState-like structure, TitlePage, Content, ElementSettings, DocumentRef/XRef, or unrelated opaque source;
- apply only bounded structural whitespace around inserted/replaced generated elements and include it in the expected source tree.

Direct source-backed serialization outside transactional Save retains the imported root block unchanged. Actual Save always uses the current runtime snapshot rather than preserving imported values.

### 5. Retain transaction safeguards

Prepare the replacement only in the detached candidate. Codec, identity, source-tree, conflict, or storage failure must not publish geometry into the live preservation state or destination.

Successful Save rebases from actual saved bytes through 001.1 while leaving the live native window where the user currently has it. Saving must not reapply imported or newly saved geometry to the desktop.

## User-owned desktop validation

On disposable documents:

1. Open each reference and record the requested window restore without assuming the OS must honor it exactly.
2. Move/resize the window, verify no dirty indicator or content change results, Save, reopen, and confirm the latest geometry is used.
3. Test negative/multi-monitor coordinates where available and confirm off-screen recovery remains possible through native OS controls.
4. Test missing and malformed WindowState and verify the screenplay opens with current/default geometry.
5. Confirm Save does not move/resize the current window and TitlePage or other source structures remain unchanged.

## Completion criteria

The order closes after user validation confirms one-shot Open restoration, current-geometry Save/Save As overwrite, no continuous Project/dirty synchronization, no native-scale multiplication, no TitlePage or opaque-data changes, and transactional failure safety.

## Implementation record — 2026-11-03

Implemented V6-WO-001.2 only, on the existing initiative branch and on top of the completed 001.1 save-scoped transaction path. `FdxDocument` now carries an optional bounded `WindowState` projection for exactly one direct child in the FinalDraft root's expanded namespace. Signed Left/Top values are accepted; positive Width/Height are bounded by `i32`; missing, malformed, overflowing, invalid-dimension, or duplicate root blocks project as unavailable without failing document Open. Mode is treated as Normal, including unknown/missing source values. Nested lookalikes are not consulted.

The desktop receives the projection during successful FDX activation and consumes it once in the next update, dispatching best-effort outer position and inner logical size commands. It captures latest complete logical geometry from viewport outer position and inner size for Save/Save As; incomplete snapshots retain the last complete sample, and no sample uses the documented 870 × 854 at (0,95) agent-default. Geometry remains outside Project, session revision, dirty/history state, layout, and PDF. The save-scoped context passes the snapshot to detached candidate reconciliation. Actual Save/Save As replaces duplicate direct-root WindowState elements with one canonical Height/Left/Mode/Top/Width element, inserts missing blocks at the bounded PageLayout/ElementSettings anchor, and generates the block after Content for new output. Direct source-backed serialization remains unchanged; nested structures and unrelated source sections are retained, and existing code 4/code 29/code 30 and atomic publication gates are not relaxed. Save does not dispatch a restore.
