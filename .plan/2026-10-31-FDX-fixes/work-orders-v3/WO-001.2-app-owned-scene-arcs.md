# V3-WO-001.2 — App-owned scene-arc membership after import

- **Status:** Draft; implementation not started
- **Depends on:** [V3-WO-001.1](WO-001.1-derived-character-projection.md)
- **Validation:** User-owned; no agent-run checks

## Outcome

Make supported imported CharacterArcBeat membership app-owned and derived from the current scene. Removing or renaming a Character after a separate reopen must update derived arcs and permit Save/Save As instead of failing for lack of ScriptCraft creation proof.

## Current defect

[`reconcile_heading()`](../../../crates/scriptcraft-core/src/scene_metadata.rs:220) removes an unmatched arc only when its nested Paragraph ID appears in runtime generated ownership and passes reference checks. Import resets that ownership in [`read_v6()`](../../../crates/scriptcraft-core/src/fdx.rs:362), so ordinary post-reopen edits can make every later save fail through [`prepare_cast_list_save_candidate()`](../../../crates/scriptcraft-core/src/editing.rs:205).

The user-observed Final Draft behavior establishes that nested derived Paragraph IDs are regenerated and are not durable ownership evidence. Supported derived scene data becomes app-owned on deserialization.

## Scope

1. Switch imported-scene reconciliation in [`scene_metadata.rs`](../../../crates/scriptcraft-core/src/scene_metadata.rs) to the normalized key/uppercase-name projection introduced in V3-WO-001.1.
2. For the currently recognized empty nested-Paragraph arc shape:
   - Retain an entry whose normalized Character key remains in the scene.
   - Update its CharacterArcBeat Name to the stored uppercase derived name.
   - Remove an entry whose normalized Character key is no longer present, without requiring ScriptCraft creation history.
   - Add missing entries using the existing reference shape and bounded UUID v4 allocator.
   - Retain first-occurrence scene order from the derived projection.
3. Treat a rename to a different normalized key as removal plus addition. Do not transfer an arc by position or nested UUID.
4. Remove obsolete runtime creation-ownership state and propagation rather than retaining a misleading parallel authority:
   - [`generated_scene_arc_paragraph_ids`](../../../crates/scriptcraft-core/src/preservation.rs:284) and its import/new-document initializers.
   - [`carry_generated_ownership()`](../../../crates/scriptcraft-core/src/scene_metadata.rs:182) and its call in [`save_session_with_codec()`](../../../crates/scriptcraft-core/src/fdx_storage.rs:410).
   - Ownership-only helpers and old expectations that conflict with app-owned derived arcs.
5. Keep ordinary body/title Paragraph identity behavior unchanged. Matched nested arc IDs may remain stable, but must not control deletion or association.
6. Keep the existing strict save candidate, serialization/re-read, conflict, and atomic replacement behavior unchanged.
7. Continue safe-stopping unsupported arc shapes in this order. Text-bearing arc support belongs to V3-WO-001.3; document-wide nonblocking deferral belongs to V3-WO-001.4.

## Regression coverage to author

Add focused core cases in [`v3_wo0012_app_owned_scene_arcs.rs`](../../../crates/scriptcraft-core/tests/v3_wo0012_app_owned_scene_arcs.rs) and replace contradictory v2 expectations:

- Import supported derived arcs, reopen separately, delete a Character, and verify reconciliation removes its arc and Save/Save As succeed.
- Rename a Character to a different normalized key and verify old arc removal plus new UUID-backed arc creation.
- Add/remove other Characters while retaining one Character and verify that retained entry and nested ID remain associated by normalized name, not position.
- Verify mixed-case cues produce uppercase arc Names without modifying canonical text.
- Verify extension-bearing cues reconcile against extension-free imported arc Names.
- Verify undo/redo restores the exact derived membership and source state.
- Retain fatal managed-source mismatch and destination/storage failure behavior.

The prior [`separately_reopened_stale_imported_scene_arc_safe_stops_without_mutation()`](../../../crates/scriptcraft-core/tests/wo0032_uuid_lifecycle.rs:293) must be replaced by the new app-owned lifecycle expectation. Authored cases are not validation results.
