# V3-WO-001.4 — Nonblocking derived refresh, Cast Lists, and native save

- **Status:** Draft; implementation not started
- **Depends on:** [V3-WO-001.3](WO-001.3-scene-arc-content-retention.md)
- **Validation:** User-owned; no agent-run checks

## Outcome

Ensure unsupported derived metadata or an uncorrectable formatted Cast List cannot prevent an otherwise valid canonical FDX Save or Save As. Generate Cast List text from the same uppercase derived scene names used by scene arcs.

## Current defect

[`correct_cast_lists()`](../../../crates/scriptcraft-core/src/cast_list.rs:37) reconciles all scenes before updating any list. Any unsupported scene returns an error for the whole operation. Every native save calls this path through [`save_session_with_codec()`](../../../crates/scriptcraft-core/src/fdx_storage.rs:398).

[`replace_cast_list_text()`](../../../crates/scriptcraft-core/src/cast_list.rs:129) also rejects formatted runs. If a stale list needs correction, that local derived-text limitation can block the entire native save.

## Scope

1. Change scene reconciliation to produce a per-scene outcome that identifies fully reconciled scenes and deferred scenes. Preserve detached candidate behavior; do not mutate the live session during Save preparation.
2. Apply [`SceneMetadataError::UnsupportedSceneMetadata`](../../../crates/scriptcraft-core/src/scene_metadata.rs:12) as a per-scene deferral when the source shape is preservable but unsupported:
   - Leave that scene's complete SceneProperties/SceneArcBeats subtree unchanged.
   - Do not partially add, remove, rename, or reorder entries in that scene.
   - Continue reconciling other independent scenes.
3. Keep model validation failure, missing managed-source mappings, required UUID allocation failure, and actual preservation integrity errors fatal. Do not convert genuine candidate corruption into a silent deferral.
4. Update Cast List generation in [`cast_list.rs`](../../../crates/scriptcraft-core/src/cast_list.rs):
   - Consume only fully reconciled scene-arc projections for source-backed scenes.
   - Leave every Cast List in a deferred scene unchanged.
   - Use the V3-WO-001.1 uppercase derived names for preservation-free projects as well, so stored Cast List text follows the same casing contract.
   - Retain existing alphabetical case-insensitive sorting and parenthesized formatting.
5. If a formatted Cast List cannot be corrected without unsupported run rewriting, leave that list's text and runs unchanged and continue the operation. Do not drop formatting merely to force generation.
6. Use the same deferral policy for scheduled refresh, undo/redo correction, Save, and Save As. Expected deferral must not produce the recurring desktop refresh error currently set in [`refresh_cast_lists_on_schedule()`](../../../apps/scriptcraft/src/main.rs:242).
7. Preserve strict managed-source reconciliation, semantic/re-read comparison, conflict detection, and atomic filesystem publication. No new popup, status redesign, private metadata marker, or recovery behavior is in scope.

## Regression coverage to author

Add focused core cases in [`v3_wo0014_nonblocking_derived_save.rs`](../../../crates/scriptcraft-core/tests/v3_wo0014_nonblocking_derived_save.rs) and focused desktop cases only where the existing refresh status is affected:

- Mix one supported scene and one unsupported scene; update only the supported scene and Save/Save As all canonical edits while retaining the unsupported subtree exactly.
- Verify a deferred scene's Cast Lists remain unchanged while supported scenes' lists update.
- Save unrelated edits with a stale formatted Cast List and verify its text and run attributes remain unchanged.
- Verify stored Cast List text is uppercase for mixed-case canonical cues in both source-backed and preservation-free projects.
- Verify scheduled refresh treats expected unsupported-scene deferral as nonfatal and does not repeatedly show a save-style error.
- Verify undo/redo with deferred scenes does not publish partial derived corrections.
- Retain fatal invalid-candidate, managed-source mismatch, required-ID entropy, re-read difference, conflict, and storage failure cases.

These are authored cases, not validation results. The user performs all checks.

## Explicitly deferred

- Editing unknown arc payloads or arbitrary run formatting.
- Broad diagnostics/notification UX for deferred derived updates.
- Repeated title-page identities and insertion formatting, owned by V3-WO-002 and V3-WO-003.
