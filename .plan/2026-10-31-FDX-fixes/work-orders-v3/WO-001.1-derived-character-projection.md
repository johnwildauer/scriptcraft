# V3-WO-001.1 — Derived Character name projection

- **Status:** Draft; implementation not started
- **Depends on:** Existing v2 checkout; no other v3 work order
- **Validation:** User-owned; no agent-run checks

## Outcome

Introduce one bounded Character-to-derived-name projection for native scene metadata, with normalized association keys and uppercase stored derived names. Use it for newly generated documents first so imported reconciliation can migrate in the following focused order.

## Evidence and current limitation

[`character_names()`](../../../crates/scriptcraft-core/src/scene_metadata.rs:121) currently trims full Character cue text, deduplicates case-insensitively, and retains the first typed spelling. This conflates canonical cue text with derived Character identity.

The references require two different representations:

- [`reference2.fdx`](../../../.reference/reference2.fdx:25) stores canonical cue John while [`reference2.fdx`](../../../.reference/reference2.fdx:15) stores derived arc Name JOHN.
- [`real_script_example.fdx`](../../../.reference/real_script_example.fdx:23) stores canonical cue HELEN MIRREN (V.O.) while [`real_script_example.fdx`](../../../.reference/real_script_example.fdx:13) stores derived arc Name HELEN MIRREN.

## Scope

1. Add an internal derived-Character projection in [`scene_metadata.rs`](../../../crates/scriptcraft-core/src/scene_metadata.rs) that returns, in first-occurrence order, both a normalized association key and the stored derived name for each unique Character.
2. Build the projection from each scene's Character elements only. Trim outer Unicode whitespace and ignore empty results.
3. Remove one recognized trailing delivery extension before forming the name. Support the native extension vocabulary evidenced in [`real_script_example.fdx`](../../../.reference/real_script_example.fdx:365): (V.O.), (O.S.), (O.C.), (CONT'D), (SUBTITLE), (TEXT), and (V.O). Match these suffixes case-insensitively and trim whitespace left before the suffix.
4. Do not strip arbitrary parenthetical text, split multi-Character cues, or otherwise reinterpret canonical screenplay meaning.
5. Form the association key with Unicode case-insensitive normalization and the stored derived name with Unicode uppercase. Deduplicate by normalized key while retaining first occurrence order.
6. Keep [`ScreenplayElement.text`](../../../crates/scriptcraft-core/src/lib.rs:292) and every source Text node unchanged. This order affects derived generation only; it does not reactivate edit-time uppercasing.
7. Switch new-document scene metadata generation in [`make_new_document_nodes()`](../../../crates/scriptcraft-core/src/fdx.rs:1095) to the new projection.
8. Leave imported-scene reconciliation and Cast List consumption on their existing path until V3-WO-001.2 and V3-WO-001.4. Do not change deletion ownership, arc recognizers, save error behavior, or UUID allocation here.

## Regression coverage to author

Add focused core cases in [`v3_wo0011_derived_character_projection.rs`](../../../crates/scriptcraft-core/tests/v3_wo0011_derived_character_projection.rs):

- Mixed-case John produces derived JOHN while canonical John remains unchanged.
- HELEN MIRREN (V.O.) produces association/name HELEN MIRREN and matches an existing extension-free derived name.
- Cover every supported extension, case-insensitive suffix matching, outer Unicode whitespace, empty cues, and case-variant duplicates.
- Verify an arbitrary parenthetical suffix not in the recognized vocabulary remains part of the derived name.
- Verify Unicode uppercase behavior, including an expanding uppercase mapping, without changing canonical source text.
- Verify new-document SceneArcBeats use uppercase extension-free names in first-occurrence order.

These are authored cases, not validation results. The user runs all checks.
