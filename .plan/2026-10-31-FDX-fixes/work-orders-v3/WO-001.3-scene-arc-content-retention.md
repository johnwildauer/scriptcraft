# V3-WO-001.3 — Scene-arc content retention by Character association

- **Status:** Draft; implementation not started
- **Depends on:** [V3-WO-001.2](WO-001.2-app-owned-scene-arcs.md)
- **Validation:** User-owned; no agent-run checks

## Outcome

Deserialize supported text-bearing CharacterArcBeat content and associate it with the normalized Character key. Adding or deleting other Characters must not lose a retained Character's arc content; removing that Character intentionally removes its derived arc and arc text.

## Current limitation

[`recognized_beat()`](../../../crates/scriptcraft-core/src/scene_metadata.rs:482) requires the nested Paragraph to have no children. Real arc content can live below that Paragraph, so the current recognizer cannot retain and reconcile the user's arc text. Nested IDs are unstable in Final Draft and cannot provide the association.

## Scope

1. Broaden the bounded recognizer in [`scene_metadata.rs`](../../../crates/scriptcraft-core/src/scene_metadata.rs) to accept a supported CharacterArcBeat containing one nested Paragraph with ordered text/run content and preserved source attributes.
2. Keep the nested arc Paragraph opaque to the screenplay body: do not create a semantic body element, managed body anchor, or editable screenplay role for it.
3. For a retained normalized Character key, retain the existing nested Paragraph node, including its text, ordered runs, supported formatting, and current ID. Update only the derived CharacterArcBeat Name and arc ordering required by reconciliation.
4. Preserve retained arc content when unrelated Characters are added, deleted, reordered, or case-normalized. Association uses the V3-WO-001.1 normalized Character key, never nested UUID or sibling position.
5. When a Character's normalized key is removed, remove its entire derived CharacterArcBeat, including arc text. This is intentional derived-data lifecycle, not preservation of a removed Character's stale metadata.
6. When a Character is renamed to a different normalized key, do not transfer old arc text to the new key. Treat it as removal plus a new blank derived arc.
7. Continue allocating UUID v4 only for newly created nested arc Paragraphs and registering/removing affected identity records consistently with the existing preservation graph.
8. Reject or defer arc structures with ambiguous duplicate beats, multiple nested Paragraphs, or unknown non-text child structures rather than guessing which payload is derived. V3-WO-001.4 will make such deferral nonblocking for native save.

## Regression coverage to author

Add focused core cases in [`v3_wo0013_scene_arc_content_retention.rs`](../../../crates/scriptcraft-core/tests/v3_wo0013_scene_arc_content_retention.rs):

- Import a nonempty arc Paragraph and save/reopen with its exact text and ordered run attributes retained.
- Add and remove other Characters while verifying the retained Character's arc content and nested ID remain unchanged.
- Match an extension-bearing canonical cue to an extension-free arc Name without losing arc text.
- Change only canonical cue casing and verify the uppercase derived Name and retained arc content.
- Remove the associated Character and verify its arc text is removed with the derived entry.
- Rename to a different normalized identity and verify old arc text is not transferred by position or ID.
- Cover multiple scenes so identical Character names retain independent arc content per scene.
- Verify undo/redo and Save/Save As retain the same association and content lifecycle.

These are authored cases, not validation results. The user performs all checks.

## Explicitly deferred

- Nonblocking handling of unsupported scenes and formatted Cast Lists: V3-WO-001.4.
- General arc-editing UI, beat-board editing, SceneProperties Page/Length recalculation, and Scene Heading structural split/join changes.
