# V2-WO-003.2 — UUID lifecycle verification

- **Status:** Implementation authored; user review and validation pending
- **Depends on:** [V2-WO-003.1](WO-003.1-uuid-v4-allocation.md)
- **Validation:** User-owned; no agent-run checks

## Outcome

Prove paragraph UUIDs follow editing, history, and save operations without unintended reuse or regeneration.

## Scope

- Verify ordinary edits, role changes, scene-cast refresh, Save, Save As, and reopen retain existing UUIDs.
- Verify split retains the original/left UUID and allocates only the right UUID; join/delete removes only the removed paragraph identity.
- Verify matched scene-arc names retain nested paragraph UUIDs, renamed/new names receive fresh UUIDs, and removed derived entries disappear.
- Verify undo/redo restores exact prior UUID state; newly reintroduced content receives a fresh UUID without a historical registry.
- Replace legacy ID assertions in [`fdx.rs`](../../../crates/scriptcraft-core/src/fdx.rs:3245) and [`wo012f_source_structural_edits.rs`](../../../crates/scriptcraft-core/tests/wo012f_source_structural_edits.rs:36).
- Fix only lifecycle defects exposed by these cases; do not redesign unrelated foreign identities.

## Implementation handoff — 2026-11-01

WO-003.2 lifecycle regressions are authored on the existing checkout. The tests cover established identity retention during ordinary edits, role changes, scene-cast refresh and codec save/reopen; transactional Save and Save As followed by reopen; split identity continuity and single-right-side allocation; join/delete removal of only the removed identity; exact undo/redo snapshot restoration; and new content after deletion. Scene-arc coverage checks matched and case-only-renamed name retention, newly added and renamed name allocation, safely owned stale-entry removal, and the separate-reopen ambiguous imported-arc safe-stop. The legacy FDX UUID assertion in [`fdx.rs`](../../../crates/scriptcraft-core/src/fdx.rs:3317) now checks canonical lowercase UUID v4 shape/version/variant, and [`wo012f_source_structural_edits.rs`](../../../crates/scriptcraft-core/tests/wo012f_source_structural_edits.rs:36) checks all generated identities from its split/insert sequence rather than selecting one at random.

No product or allocator fix was identified as necessary from the source inspection; the predecessor's shared bounded UUID v4 allocator, fallible entropy, identity preservation, writer re-read/identity comparisons, and atomic save path are unchanged. Tests are authored coverage only. No tests, builds, lint, formatting, manual verification, implementation checks, reviews, validator dispatches, or other validation were run, as prohibited by [the authoritative project policy](../../../.forge/project-manifest.md:73). User review and validation remain pending.

Implemented behavior retains existing IDs across the covered session, save, and reopen lifecycle, allocates for newly created body/arc paragraphs, and removes only IDs for authorized removed entries. There is deliberately no historical tombstone registry: newly reintroduced content receives a new random allocation, but absolute non-reuse against every previously deleted ID cannot be guaranteed. Separately, after a reopened file contains a stale arc with no in-session creation proof, the implementation cannot safely infer ScriptCraft ownership even if its shape looks derived; reconciliation and cast refresh stop atomically and leave the ambiguous entry intact. Neither limitation was weakened or claimed solved.
