# V2-WO-001.2 — SceneProperties and scene arc reconciliation

- **Status:** Implemented; user-owned review and validation pending
- **Depends on:** [V2-WO-001.1](WO-001.1-imported-role-source-synchronization.md)
- **Validation:** User-owned; no agent-run checks

## Outcome

Ensure every managed Scene Heading has SceneProperties and SceneArcBeats containing the supported derived scene-cast projection.

## Scope

- Add a focused scene-metadata reconciliation module and use it at the existing cast-list refresh/save-candidate boundary and in new-document FDX generation.
- Create missing structure before the first Text child. Default new SceneProperties to Length 1/8, Page 1, and empty Title; preserve existing values and do not recalculate Page or Length.
- For each scene, collect nonblank Character names after its heading and before the next heading. Trim outer Unicode whitespace, deduplicate case-insensitively, and retain first spelling and occurrence order.
- Create one CharacterArcBeat per name with the reference nested Paragraph shape from [`reference2.fdx`](../../../.reference/reference2.fdx:15). Preserve canonical name case.
- Register new nested paragraph identities in the preservation graph while leaving those nodes opaque rather than managed screenplay elements; do not create semantic body elements or managed anchors for them.
- Retain matched nested paragraph IDs; allocate fresh IDs only for new entries. V2-WO-003.1 will convert all new allocations to UUID v4.
- Remove stale entries only when they match the supported derived shape. Preserve ambiguous or unknown authored payloads and safe-stop updates for that scene rather than deleting data.
- Keep existing Scene Heading split/join attachment rules unchanged.

## Regression coverage

Cover new and imported headings with missing/existing metadata, multiple scenes, rename/add/remove/reorder, duplicate casing, Unicode whitespace, matched-ID retention, save/reopen, undo/redo, and unsupported-payload atomicity.
