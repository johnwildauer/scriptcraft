# V2-WO-003.1 — Shared UUID v4 allocation

- **Status:** Implemented; user review and validation pending
- **Depends on:** [V2-WO-002.2](WO-002.2-all-caps-text-export.md)
- **Validation:** User-owned; no agent-run checks

## Outcome

Use lowercase hyphenated UUID v4 values for every newly created FDX paragraph identity.

## Scope

- Add a focused direct UUID dependency with v4 generation in [`crates/scriptcraft-core/Cargo.toml`](../../../crates/scriptcraft-core/Cargo.toml:8).
- Introduce one bounded collision-checking paragraph-ID allocator and replace [`new_paragraph()`](../../../crates/scriptcraft-core/src/fdx.rs:928), [`fresh_foreign_paragraph_id()`](../../../crates/scriptcraft-core/src/preservation.rs:1086), and scene-arc nested-paragraph allocation.
- Include body, title-page, imported-inserted, split-created, and scene-arc paragraphs. Do not change semantic IDs, anchors, DocumentRef, or board/image identities.
- Preserve all existing IDs verbatim, including legacy non-UUID values. Retry collisions within a fixed bound, then return a typed error; keep no tombstone registry.

## Regression coverage

Assert UUID version/variant/shape and uniqueness without hard-coded random values. Cover all creation paths and preservation of existing UUID and non-UUID IDs.

## Implementation handoff — 2026-11-02

The shared paragraph identity allocator now generates canonical lowercase, hyphenated UUID v4 values through a bounded 16-attempt collision check. It reserves IDs as it allocates, checks existing preservation identity values and all source `id` attributes in source-backed paths, and includes board identities/references in the reserved set. Random bytes come from fallible `getrandom`; entropy failure and exhausted collision retries return distinct typed errors so candidate edits, scene reconciliation, and new-document serialization fail without publishing partial state. No tombstone registry was added. Existing imported paragraph IDs—including non-UUID values such as `scriptcraft-paragraph-1`—remain verbatim. Semantic element IDs, source anchors, DocumentRef IDs, and board/image identity domains were not regenerated. Writer structural re-read and identity checks and atomic save publication paths were left intact; scene-arc creation tracking still flows through the existing writer re-read ownership mechanism.

First-time IDs for a never-saved, preservation-free project are random and repeated independent serializations may therefore differ. After a successful save/re-read establishes the source tree and IDs, later saves retain those identities; this is an identity-stability guarantee, not a claim of byte-for-byte determinism for a first-time output.

Focused tests were authored in [`paragraph_id.rs`](../../../crates/scriptcraft-core/src/paragraph_id.rs), [`wo0031_uuid_allocation.rs`](../../../crates/scriptcraft-core/tests/wo0031_uuid_allocation.rs), the FDX/scene-metadata unit coverage, and the updated legacy assertion in [`wo012f_source_structural_edits.rs`](../../../crates/scriptcraft-core/tests/wo012f_source_structural_edits.rs). Coverage includes UUID v4 lowercase shape/version/variant, uniqueness across new body/title/scene-arc paragraphs, imported Enter/split allocation, retention of legacy source IDs, bounded forced collisions, and typed entropy failure. These are authored cases only: no tests, builds, lint, formatting, manual verification, implementation checks, reviews, validator dispatch, or other validation were run. User review and validation remain pending; no Final Draft interoperability claim is made.
