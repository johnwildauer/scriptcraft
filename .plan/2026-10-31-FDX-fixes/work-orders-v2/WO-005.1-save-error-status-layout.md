## Implementation handoff — 2026-11-02

`TransactionalSaveError::fmt()` now preserves privacy-safe category detail for session candidate preparation, codec serialization/re-read, storage operation, and missing-baseline failures. Session errors are projected through fixed category labels rather than debug output; codec detail uses the bounded `FdxError` display category; storage display remains path- and content-free. The desktop save error keeps “FDX save failed; document unchanged” in the operation message and shows the projected detail separately. No screenplay text or filesystem path is added to this save-error path.

The center Clean/Dirty label was removed from the status row and its existing overflow summary. The existing operation/error text is now left-aligned in the full center region. The visible-page item, right-side controls, noninteractive message text, status panel structure, and existing overflow control behavior remain; no popup or new overflow behavior was added. The session still owns dirty state, and save failure does not publish a candidate or alter the live session, path, baseline, destination, or dirty state. The predecessor's `FdxError::UnsupportedConstruct` refusal for ambiguous mixed-content or effective `xml:space="preserve"` inserted/split formatting remains intact and is not masked.

Focused cases were authored in `fdx_storage.rs` for privacy-safe error categories, in the desktop app tests for visible error projection and preservation of initially dirty/clean session state, and in `status_bar.rs` for removal of Clean/Dirty text, left-aligned wide/compact message geometry, page/right-control retention, and existing status-message access. These are authored cases, not results. No tests, builds, lint, formatting, manual verification, implementation checks, reviews, or validator dispatches were run under the [project policy](../../../.forge/project-manifest.md:73); user review and validation remain pending.
